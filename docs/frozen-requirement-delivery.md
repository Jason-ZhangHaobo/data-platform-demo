# 需求理解随交付包冻结与审阅

## 背景

SQL Agent已保存可审阅理解，但只在任务上展示还不足以说明“工程师批准了哪一份需求”。交付、恢复和发布必须绑定原需求、口径、模型解释及确切代码，不能在文件已生成后悄悄采用任务上的新内容。

## 价值

工程师在独立Agent的交付区直接查看该包冻结的指标、字段、客户日粒度、参数和约束。需求内容、代码或来源变化后，新交付使用新摘要并重新审阅；旧包、旧批准和运行历史保留，不能成为新版本的批准。

## 问题

只在包里附加一段说明会留下绕过入口：准备API漏传、恢复时丢失依据、重算包内哈希、存储读取后来源变化，以及使用旧交付或审阅。仅保留可变任务文本也无法复核已发布内容。人工手写、人工辅助和旧任务须保持原归因，不能借新字段升级成原生Agent成功。

## 需求

- 保留原八文件及`shuduo-delivery/v1`身份。完整`requirements`进入`validation.json`，`manifest.source.requirement`保存协议、原taskId、basisDigest与reportDigest；报告和文件字节都进入包摘要。不新增第九份文件，不重写旧包。
- 新生成SQL版本保存`requirementBinding`，绑定结构化理解报告。准备者必须提供同项目、原作者、原Agent、同次成功尝试、同运行和代码的完整记录；登记口径与依据也须匹配。缺失或矛盾直接拒绝，不能静默回落为无依据的旧包。
- 冻结对象只接受已定义字段，不能归档任意模型debug／业务行／凭证字段。包读取、解包和文件演练检查依据与解释、源代码、口径、摘要及完整字节。现有basisDigest编码规则保留，新增reportDigest使用规范化JSON。
- 普通API、Agent准备及持久／人工辅助交付均接入同一生产与校验；存储等待之后、恢复与新增提交之前重核。停止或读取已提交结果不因此触发额外计算。幂等与复用带上需求绑定，同一原包／原任务恢复不重建文件或模型任务。
- 已有成功任务可用新准备编号生成包含依据的新包，无需重跑模型；已有包和批准不迁移。需求变更的新包须重新审阅，不能借用旧reviewId或批准。旧任务确无结构化理解时继续按原范围保留，不补造理解。
- 人工辅助模型版本可以携带同源提案，仍是ENGINEER_ASSISTED；手写／独立手工代码不继承另一个Agent的解释，仍按ENGINEER_AUTHORED等原来源核验。
- 审阅、批准、版本激活及新批次提交沿用原权限、预算和窗口，重核当前来源与冻结包。原包摘要继续绑定原审阅／批准，无自动审批或新的运行授权。
- 交付区以只读卡展示“此交付包冻结的需求理解”和依据摘要，宽屏展示多列指标；刷新不变。新理解存在但绑定失败时，需求旅程和独立核验都显示需要处理，不能保留绿色需求结论。GUI／API／CLI／MCP沿用原任务和八文件接口，文件包可独立复核。
- 当前v3记录在存在结构化理解时继续核对同一冻结绑定；历史目录和契约不迁移。结构确认、模型解释或合成回执均不等于完整自主完成或公网验收。

## Demo与验收

1. 同一原生Agent结果生成八文件并往返解包，依据与原报告一致；人工辅助保留归因，历史无依据包仍可读取。
2. 删除、替换或添加未定义需求字段后重算全部内部哈希，仍不能通过；去掉任务报告或错用其他来源也被拒绝。
3. 存储写入／校验、持久化或恢复期间修改理解，不能创建批准或新提交。SQLite与控制器重开保持原交付编号、包、摘要和一次演练提交。
4. 真实本机HTTP生成包、审阅和批准；原需求变化时拒绝批准，新包不能使用旧reviewId。该测试使用合成引擎回执，不代表实际业务批准。
5. 一次真实本机Spark3.5.9文件演练执行主SQL、测试SQL和五组登记场景，通过独立客户金额／数量及八文件哈希检查。模型与上游成功来源合成，仅是本机文件检查，不导入云端回执或当前v3真实分数。
6. 完整页面展开冻结指标／字段／粒度／约束，刷新保持摘要；模拟任务内容变化后，原包不变、需求旅程及核验转为需处理，页面不提供可用的新发布操作。页面回执合成、计算禁用，临时进程关闭。

回归入口：`requirement-delivery.test.mjs`、`agent-workflow-read.test.mjs`、`agent-journey-ui.test.mjs`及现有交付／发布／手工来源测试。当前执行和实际证据分别见[续接清单](goal-mode-next.md)与本机受保护状态。本增量未部署，不开模型、云资源或IAM权限窗口。
