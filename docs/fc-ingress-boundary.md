# FC 公开与私有调用边界

本文件描述代码合同和验收门槛，不是公网已上线或真实云验证通过的证明。实际环境记录只保留在受保护位置。

## 入口合同

- `cloud-server.mjs` 固定安装 FC 入口校验，先校验再刷新持久状态、读取载荷或执行操作。
- 私有调用只接受平台标记 `x-fc-control-path: /invoke` 与精确 `POST /invoke`。继续使用原 IAM 调用授权、事件签名、任务范围和次数限制；标记不是应用用户身份。
- 公开 HTTP 默认关闭。只有显式 `V2_FC_PUBLIC_HTTP_ENABLED=true` 才允许页面 GET、`/api/v2/` GET/POST；支持 `/http-invoke` 或无控制标记的公开请求，其他标记仍拒绝。内部调度路由仍拒绝，应用登录、项目权限、CSRF、预算及版本审阅保持原样。只读模式依据守卫返回的 HTTP 通道判断，不因缺少请求头而失效。打开此开关不等于通过其他上线门槛。
- 请求进入 URL 规范化之前拒绝双斜线、点段、反斜线、编码路径、绝对 URL 和重复控制头；查询参数允许正常 URL 编码。浏览器不能通过改路径或 `Host`、`X-Forwarded-For`、`X-Original-URL` 升级为私有调用。
- 进程内转发使用随机、实例独有、不落盘的内部凭证，仅接受回环地址和非内部的应用 API；不凭回环地址本身授权。外部私有转发载荷不能注入该凭证。此凭证不代替用户 Cookie/CSRF，也不能访问 `/invoke` 或内部调度。实例重建即失效。

## 平台信任前提

阿里云官方[Web 函数公共请求头](https://help.aliyun.com/zh/functioncompute/context-and-log-format-1)说明控制标记由平台生成，区分事件和 HTTP 请求；[调用机制](https://help.aliyun.com/zh/functioncompute/web-functions)说明 InvokeFunction 转换为 POST /invoke，HTTP 则透传应用路径。

此实现只能部署在 **FC 托管入口后方、没有其他可直达监听端口的环境**。任何能直接访问 Node 监听端口的客户端都能自行填写平台标记；本机模拟标记的测试不证明平台抗伪造。不能将本服务端口直接暴露公网，也不能将通用反向代理复制头视为可信平台。

## 发布顺序与强制门槛

1. 完成本机入口拒绝、私有查询转发、正常登录、CSRF、原事件处理回归和完整 CI。
2. 按现有私有部署权限仅更新代码，公开开关保持关闭；精确私有状态调用、应用查询及原 OSS 后台调用须实际复核，配置/角色/容量不变。私有事件缺失或不同控制标记必须拒绝，不能仅靠路径进入私有处理；无标记的公开路由仅在显式启用后放行，不赋予私有身份。
3. 取得具体 HTTP 入口验证范围，保持公开开关关闭。仅使用无副作用的状态载荷，通过真实 FC HTTP 入口分别发送正常请求、伪造/重复/混合大小写的控制头、编码/点段路径及伪造内部凭证。全部拒绝，且不能返回私有状态或产生数据/任务。默认 URL 和自定义域名要分别测；任何异常立即关闭入口并调查，不放宽校验。
4. 核对 HTTPS 证书、备案、DNS、预算、邀请身份和项目权限。通过以上检查后才申请/实施精确公网开放变更；保留默认函数 URL 的访问控制。不要直接套用旧部署流程覆盖当前事件驱动环境。
5. 公网启用后正常登录、未登录/越权拒绝、历史结果展示、原任务恢复和退出验证；不因页面可打开就计作完整 Agent E2E。

云上测试前不能宣称标记不可伪造、OSS 触发兼容性已经验收或公网已安全开放。回滚顺序：关闭 HTTP 入口/公开开关，再按原代码包和配置恢复；保持原持久任务和结果。

本机覆盖：`test/v2/fc-ingress.test.mjs`，以及既有 private-application、private-invoke-smoke 和 Agent 事件驱动测试。没有新建资源、签发证书、变更 DNS 或调用模型/Spark的隐式授权。
