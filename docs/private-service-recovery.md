# 私有数据服务：恢复对照与实际行完整性

范围：通用实现与合成测试。本文不报告私有云部署状态；当前环境的验收原件留在受保护执行状态和证据目录。

## 恢复合同

读取`GET /api/v2/data-services/{dapis|xapis}/:id/recovery`，只允许原平台会话中的Owner或项目管理员；应用Bearer令牌不能管理或读取该报告。私有通道仍须显式开启，无新计算、物化、授权或批次。

报告包括本次后端随机`bootId`、当前/已发布版本和配置摘要、固定的XAPI子版本、源批次与包摘要、实际业务行重新计算的快照摘要、持久调用和应用撤销状态。报告不返回业务行、模型上下文、Cookie、令牌或令牌哈希。

同一服务停止写入的验收窗口内：

1. 原实例读回报告并保留原件。
2. 使用已经允许的操作重建后端，保留实例终止和新启动证据；不终止未知任务、不改权限/网络/容量。
3. 新实例读取同一服务报告；启动标识应不同，状态摘要应一致，所有来源及实际行检查应通过。
4. 检查原身份/版本、数据结果、日志、幂等、撤销和限流状态；前后报告变化须能解释，不盲目重提计算。

只有单份报告，或只刷新页面/重启临时代理，都不能声明已恢复。

## 工具与界面

- GUI“恢复对照”只说明当前实例快照/来源是否完整；可下载报告，再与新实例报告比较。
- CLI：`shuduo services recovery --type xapi --id SERVICE_ID`。
- MCP：`data_service_recovery`，输入`type`与`serviceId`。认证仍由服务端执行；管理端会话接入不可用时应返回401，不降级为应用令牌或虚构身份。
- 离线对照：`node scripts/compare-v2-service-recovery.mjs before.json after.json`。输出明确是`REPORT_COMPARISON_ONLY`；即使通过也不单独证明FC冷启动。

## 数据完整性

物化契约最多1000个客户。查询和恢复报告都重新读取该快照的实际行、排序并计算正文摘要，且检查行数与版本绑定的摘要。缺快照、缺行、额外行或内容漂移返回409`SOURCE_SNAPSHOT_UNAVAILABLE`，不能因为元数据中的旧哈希仍一致就返回被改动结果，也不自动用参考数据补回。

## 测试分层

`test/v2/private-service-process-recovery.test.mjs`使用两个真正独立的Node进程和真实SQLite查询；文件CAS只替代MySQL/OSS传输。验证原会话、固定服务/子版本、日志、撤销、限流、幂等恢复，并拒绝丢失/损坏业务状态。输入的证券运行证据为合成记录，结果仅标记`LOCAL_PROCESS_RESTART_FILE_CAS`，不计云Spark或FC/MySQL/OSS验收。

真实云验收另需：当前部署代码与报告协议匹配、受保护存储回读、真实不同实例证据、身份边界、预算和清理。未取得这些证据，云验收保持待验证。
