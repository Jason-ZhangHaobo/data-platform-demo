# 私有服务 Agent：受控事件推进

本协议复用既有 OSS 唤醒前缀、签名对象、持久 outbox 与消费机制。当前交付为源码与本机合成验收，没有由此安装云触发器、启用付费窗口或开放公网写入；真实模型、真实云实例及完整 E2E 另行验收。

## 用户流程

1. 保存需求、原请求 UUID、确切任务／包／发布／成功批次，只保存待执行任务，不调用模型或写 OSS。
2. 明确登记模型事件，`advance` 返回202与原任务。先保存签名 outbox，再尝试投递，此请求不执行模型。
3. 独立事件到达后复核原任务、窗口、来源、成员、签名、版本及预算，执行一个模型边界。重复或陈旧事件不能启动第二次模型。
4. 从原链接读取同一结果，审阅完整方案摘要后才确认原草稿。事件不自动应用、测试、发布或创建凭证。

GUI、CLI、MCP共用原有创建／推进／查询／摘要应用／取消API，没有客户端可设置的驱动模式或执行者字段。CLI仍为 `services advance-plan --id … --expected-version …`，MCP仍为 `service_agent_plan_advance`；旧版本拒绝。GET不投递、不调用模型、不续期。

## 恢复与停止

| 情况 | 处理 |
|---|---|
| 投递回执未知 | 保留相同 outbox、对象键与字节；本人明确恢复原投递，GET不重发 |
| 投递停滞或来源恢复 | 明确重新核对并投递原任务，先保存新检查点和版本；原次数、Token与事件计数不清零，旧事件不能执行新版本 |
| 模型结果未知 | 保留次数和保守预留，事件等待本人 `confirmModelRetry:true`；读取或重放不代表确认 |
| 发送前失败 | 显示未确认发送，仍保留原尝试与预留；处理原因后本人继续，不后台循环 |
| 事件窗口到期 | 只能在原执行窗口及剩余额度内明确续接；不能自动续期或重置计数 |
| 取消或权限变化 | 停止本人任务及事件授权，晚到不覆盖取消；成员、来源、模型或事件边界变化使旧事件失效 |

事件次数与模型调用次数分开展示。事件可能在发送模型前因预算或资源忙而停止，事件上限可能先于模型额度耗尽；不能据事件回执推断已收费或业务完成。

## 默认关闭与隔离

可信配置 `V2_PRIVATE_SERVICE_AGENT_PROFILE.driver` 可选 `EXPLICIT_ADVANCE` 或 `OSS_EVENTS`，省略时保持原模式和指纹。事件模式进入窗口指纹，绑定当前事件 bucket、账号、项目、结果前缀及签名密钥摘要。账单刷新不续期、不重置历史；换事件密钥或路由不能借旧窗口继续。

复用现有配置与 OSS transport，不启用原SQL Agent，不自动购买资源、增加权限或安装触发器。原窗口仍限一个账号、确切来源、最长两小时、共享次数／Token／费用及完整月账单与未结算预留。每次事件登记最多十五分钟且不超过原执行窗口，剩余不足一分钟时不登记。

服务任务族为 `service_agent_plan`，唤醒记录明确类型，签名域为 `shuduo-service-agent-wake/v1`。旧SQL字节及签名域保持不变；服务消费器不执行SQL族唤醒或Spark结果。仅受保护FC事件入口接收实际OSS原始事件，普通应用API和公网只读入口不能代替它。

模型等待让出元数据通道，处理结果前重获通道；刷新、授权及写入仍串行，另一规划不能并行启动模型。没有新增轮询后台；页面只有有界状态查询。关闭页面不负责推进，但实际执行仍取决于已核验的配置与触发器。

## 验收范围

本机使用真实HTTP、认证／CSRF、SQLite、预算与服务管理器，上游模型、OSS和Spark发布回执全部合成。实际界面验证登记后关闭任务页、独立事件推进、原链接恢复和人审草稿；也验证未知确认、同任务新检查点、明确重新投递、取消及旧事件失效。1280双栏与900单栏无横向溢出。

逻辑控制器接续不等于新进程或真实云实例恢复，本机延迟不证明公网三秒目标。`backgroundDispatcherVerified`、`cloudDriverVerified` 继续为 `false`，不能由开关自我证明。后续先做跨进程恢复，再按有效具体范围核验真实云事件、模型与费用；所有公开材料只使用虚构证券数据。
