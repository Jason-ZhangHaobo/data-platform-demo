# 受邀云端工作台接线与版本冻结

本合同服务于公网 Data Agent 标杆交付，不代表云部署或浏览器验收完成。

## 环境与权限

- 临时预览的HTML标记只约束预览通道范围，不决定服务端运行在本机还是云端，也不授予权限。
- 普通HTTPS页面从状态API的运行模式、数据服务开关及范围选择后端。受邀云端不能因为缺少预览标记而调用本机发布批次接口。
- Agent内的云数据服务接管和经典服务模块使用同一个后端判断；前者保留原任务编号，只选择该任务的实际发布来源。
- 服务写操作单独检查SERVICES权限，不继承父级AGENT模块的写权限。后端原有会话、项目、CSRF、所有权与版本审批检查不变。
- 未读取状态、能力关闭或模式不明时不猜测后端、不自动创建资源，也不回退本机接口。
- 本机人工交付只能在服务端明确的本机模式使用；云端人工版本未接入交付时如实提示，不能借用原Agent的审批。
- 私有预览仍受原模块白名单限制；邀请云端入口不因此获得“生产已验收”标记。现有虚构数据测试范围标签保留。

## 创建请求恢复

私有代理允许已启用的持久Agent读取原创建请求编号。只允许精确GET路径，拒绝额外查询、路径穿越、任意请求头和POST执行；内层API继续验证原会话与资源所有权。恢复查询不能调用模型或创建第二个任务。

## 验证与发布门

### 先只读验收，再开放计算

- 云启动将`V2_FC_PUBLIC_READ_ONLY`默认视为开启（仅显式`false`可关闭），但它不代替默认关闭的`V2_FC_PUBLIC_HTTP_ENABLED`。设置开关、创建长期入口和更改域名认证都需独立阶段批准。
- 只读模式只允许公网GET及现有账号的登录/退出POST。任务创建、运行、审阅发布、API发布/授权、邀请创建/兑换、改密等POST均在访问持久层前返回`403 PUBLIC_READ_ONLY`，管理员也不能绕过。
- 公网登录和会话查询返回`readOnly:true`及仅`SESSION`展示权限，保留数据库中的原角色。工作台显示只读横幅，禁用写操作、隐藏邀请/改密入口；退出后仍保留只读标记。私有签名事件及进程内受控转发继续执行原权限，不受此公网模式影响。
- 定向验收见`test/v2/fc-ingress.test.mjs`、`test/v2/auth-readonly-ui.test.mjs`，结合持久认证回归。实际组件静态输出不是浏览器视觉验收；仍需正式HTTPS真实登录、退出和拒绝操作证据。
- 正式接入计划复用原域名/证书/DNS，新增一个HTTP触发器，拟设`disableURLInternet:true`关闭默认公网URL；域名认证改为应用层受邀会话，保留原HTTPS/TLS/路由及私有隔离。必须真实验证默认URL拒绝和域名路由，不能只以配置回读成功判定。
- 不调用模型/Spark、不新增业务账号或重置原密码；已有管理员在正式页面自行登录。私有证据、阶段请求上限、预算预留、元数据/变更次数及回滚记录只保存在受保护位置；旧一次性授权不适用。

官方依据：[HTTP触发器字段](https://help.aliyun.com/zh/functioncompute/api-fc-2023-03-30-struct-httptriggerconfig)、[更新域名及权限](https://help.aliyun.com/zh/functioncompute/api-fc-2023-03-30-updatecustomdomain)。`UpdateCustomDomain`与`CreateTrigger`的官方授权表均为`Resource:*`，必须向用户说明平台粒度限制，不能宣称IAM已限制到单域名；执行器目标限制、短时凭证和结束撤权只能作为额外控制，不等价于资源级IAM限制。

### 新阶段代码刷新与入口配置差异

复用原私有代码更新工作流，增加独立的`INVITED_READ_ONLY_CODE_REFRESH`子范围。旧`P0A_PRIVATE_CODE_ONLY`的11次历史/8次上限保持原样，不把旧批准改名复用。新子范围保留55次历史、最多6次固定只读调用（正常完成后累计61）、一次候选代码写入和一次必要回滚；不包含HTTP创建、环境修改或模型/Spark。工作流输入与加密清单范围必须一致，旧检查点不得套入新范围。枚举值只是执行校验，不是人类授权。

新子范围逐次持久预留FC配置GET计数（含`GetFunctionCode`），最多30；存储回执需在同步CLI派发前落盘。前置读取多于正常9次时，不再开始候选代码更新，为恢复留出余量；函数状态读取最多3次，不盲目重试写入。此上限不是每个子步骤都可重新获得的配额：后续入口步骤必须合并原`transport.configurationReads`及所有其他配置读取，与批准的整阶段预算对账；不能仅凭本子步骤未超限宣称全阶段未超限。开工前若完整预演含清理超限，先停止，不擅自扩额。

`scripts/invited-readonly-config.mjs`仅生成和核对精确差异，不加载凭证、不联网、不改IAM或资源：

- 必须先验证已解密原代码刷新证据，绑定源码/包摘要/字节/实际CRC和5项私有检查；旧代码、旧阶段或未完成回执一律拒绝。
- 配置请求只有四项环境键、域名认证字段和一个默认地址关闭的HTTP入口。环境全量回传时保留所有原键，原后台触发器/容量/角色/代码/证书/TLS/路由必须一致。
- 已完整应用且归属未变时，生成“先关闭应用入口→恢复域名签名认证→删除本次入口”的回滚请求。未知/部分应用、证书或外来配置漂移不自动覆盖；这些情况仍需实际协调器按检查点查询原请求后处理。此函数不负责业务代码包的回滚。
- 返回的环境请求体含现有秘密，只能留在内存或受保护加密检查点；CLI传输须使用0600临时文件及`--body-file`，不能放进命令参数、日志或公开摘要，公开日志仅输出`summary`。内容摘要用于检测意外变化，不等同于不可伪造的审批或审计。

测试入口为`test/v2/control-code-update.test.mjs`、`test/v2/control-code-transport.test.mjs`和`test/v2/invited-readonly-config.test.mjs`。下面的执行器补齐了适配器级部分写入恢复；真实CLI/HTTPS传输、外层总计数及临时权限回收仍须接通并验收，不能据本机通过宣称可以立即开放。

### 有界入口执行与中断恢复

`scripts/invited-readonly-entry.mjs`只执行固定的“核对基线→创建一个HTTP触发器→更新域名认证→最后打开只读应用开关→固定探测→最终回读”序列。每个适配器方法只能发出一个请求，不能藏重试；先持久保存计数与写前标记，再派发请求。原证书、DNS和原两条OSS触发器不在写集合内。

- 新的执行范围标识为`INVITED_READ_ONLY_OPENING_V2`，**是待人类另行批准的修订方案，不是旧授权的自动延伸**。建议配置/权限/账单读取合计上限80、清理预留20，主动探测新60/历史55/累计115，写操作各一次、最长1小时、增量2元/月度200元。旧30次读取卡不能启用这一范围。
- 必须携带代码更新实际回执中的配置读计数，入口起始计数还要加上已发生的其他前置读取，不能从零开始。合成夹具从25次续接，正常入口再用14次，达到39，尚不包含外层清理；这说明旧30次预算不能覆盖这套顺序，不代表已经发生39次云调用。代码子步骤原有30次局部上限也不产生另一份可重置的额度。
- 丢失写回执时先回读：已生效则继续，不再创建/更新；未确认或未生效就清理，不自动重发同一写入。断点恢复保留计数和已完成探测；中断GET只允许额外读取一次，结果未知的POST探测不重发。
- 失败清理独立核对函数、域名和触发器：能安全关闭的先关闭，外来修改不能覆盖；一个资源发生冲突不能阻止其他资源的安全收口。未知清理写入仍只回读，不发第二次。已成功保留的入口，后来只读核验失败不会自动拆除。
- 检查点损坏、期限过期、来源/包不匹配均拒绝继续。普通内容摘要不是审批凭证；即使重算摘要，四项环境差异、只读开关、域名认证与默认地址关闭的语义约束也不能被放宽。
- 9项探测覆盖默认地址拒绝、冻结HTML摘要、匿名只读会话、Agent/发布写入拒绝、内部路径隔离、未映射私有路径、跨Origin拒绝及错误登录。可信TLS/正确端点、域名证书匹配、无意外Cookie与真实应用错误字段同时判断；不以HTTP 200代替验收。业务POST意外成功时标记可能发生未预期写入，不宣称实际模型/计算用量为零。
- `invitedUserAccepted`始终为false：这些自动探测没有使用真实用户密码，不能替代本人登录、已登录项目隔离、Safari/Chrome与多网络验收。`externalCleanupRequired`始终为true：业务包回退、IAM/Secret清理及其剩余读取必须由外层协调器接入同一额度，在它们完成前不能称全阶段成功。

本轮46项定向及完整CI729项（728通过、0失败、1既有跳过）通过，类型/构建/入口预算通过；故障演练使用合成云状态，业务包没有变化。额外覆盖了额度耗尽不得越界清理，以及TLS/HTML/身份/应用错误不匹配时拒绝伪成功。当前不提供默认可执行的云命令，也未开放新的入口。

### CLI/HTTPS实际传输适配

`scripts/invited-entry-cloud-adapter.mjs`已经将固定方法接到CLI与HTTPS客户端，但尚未接通整批工作流与外层权限清理，不得直接声称云部署完成。

- 只接受受保护main、确切操作源码、新V2范围及同一部署角色的STS环境；固定函数/域名/触发器，不接受任意命令、路径或URL。CLI不隐藏重试，查询参数独立传旗标。
- 环境变量体仅通过0700临时目录中的0600文件传给CLI，结束删除；不放入命令参数。真实CLI 3.5.1的本机dry-run已确认PUT/body-file格式，未发送云请求。
- 域名复用已有官方签名传输，V2只允许GET与认证字段PUT；旧范围不能执行匿名认证更新，新范围不能创建/删除域名或改证书/TLS/路由。
- 公共探测不携带云密钥、Cookie或Authorization，不跟随跳转，不允许IP替换；验证可信TLS、端点与证书摘要，设总超时和64KiB响应上限，只向执行器提供必要字段。默认URL只从本函数已核验触发器回读中取得。
- 已用实际本机TLS服务器和真实应用路由验证7项合同，CA/主机映射仅测试注入；默认FC地址和真实公共DNS仍需云验收。测试HTML独立生成，不依赖本机已有构建目录或私有审计文件。

上线前检查同时发现并修复访问隔离缺口，见[公网读取边界](public-auth.md#公网读取边界修复2026-10-26)。完整CI737项（736通过、0失败、1既有跳过）、类型/构建/入口预算通过，管理员登录/退出的本机界面验证通过。此次有必要业务源码改动，旧候选包须被新冻结包替代；未做任何云资源变更。

`test/v2/workbench-environment.test.mjs`验证模式、服务权限、两处实际接线及真实组件静态渲染；`test/v2/private-application.test.mjs`覆盖实际本机HTTP代理的原请求读取和未登录拒绝。这些测试不替代浏览器点击、视觉布局或云端业务验收。

冻结流程：比较本机/main/已部署业务文件 → 集中修复必要接线 → 定向与完整CI → 固定main SHA构包 → 记录包摘要/字节及回滚依据 → 获得阶段授权 → 私有部署与验收。无源码变化不重复构包；没有可验证的回滚产物不更新云函数。

### 整段计数与代码回退

`invited-opening-stage.mjs`复用两个实际传输适配器执行固定顺序，不创建域名、证书、DNS或新的执行引擎。它没有默认可运行入口；必须由受保护工作流与本机协调过程提供既有角色、精确包身份、原始检查点、共同用量账本和有效的新授权。

- `invited-opening-usage.mjs`统一记录STS身份、每页账单、FC/域名/OSS元数据以及RAM读取；主动请求保留55历史，新增不超过60。普通步骤最多消耗60次配置读取，剩余20次仅用于清理，跨步骤/进程恢复不清零。未知结果仍计数；同步持久化失败后停止发请求。
- 对象下载/上传独立计数，仍须经过原传输层的精确对象、字节、摘要、私有ACL及禁止覆盖校验；不是额外费用豁免。各子步骤原有上限同时生效。
- 入口验收失败时，先确认本次函数开关、域名认证和HTTP触发器全部恢复，再回退代码。`rollbackOnly`沿用原VERIFIED检查点与原一次回退额度，不修改阶段冒充未验证状态，也不重新调用模型/Spark或私有业务探测。
- 外来配置变化不覆盖，入口未完全恢复时不把旧代码部署到可能开放的入口。已经成功保留的入口也不会因后来核验失败而被自动拆除。
- 证书有效期必须覆盖本次窗口；已提供备案信息必须与当前展示配置一致，缺失时在创建入口前停止，不静默扩大四项环境变量修改范围。
- 正常合成集成路径包含12次虚构前置读取，整段为48次读取、15次新探测、累计70；这些数字不是实际云调用。最终仍标记`externalCleanupRequired=true`及`invitedUserAccepted=false`，IAM/Secret回收和真实用户验收不能被该结果替代。

60项定向及完整CI747项（746通过、0失败、1既有skip）通过。整段测试使用真实适配器构造命令、虚构CLI/HTTPS响应；已有回环TLS测试继续覆盖实际网络协议。受保护工作流、加密交接和本机外层清理尚待接线，未进行云部署。

## 仅代码更新保护

`scripts/control-code-update.mjs`是适配器驱动的更新策略，不持有凭证、不直接联网，不管理IAM。它本身不是已接通云端的部署命令。实际传输必须复用受保护通道，取得当前授权后才可执行。

- 应用源码与操作脚本源码分别记录。配置、目标、包摘要/字节/对象键、授权窗口及请求上限均绑定原检查点；恢复时不能换包、延长窗口或提高上限。
- 更新前须取得并独立验证原代码字节，确认两个不可变私有对象、预算及当前配置；更新请求只有`code`字段，不修改环境、Worker、网络、容量和触发器。
- 保存写前检查点；响应丢失后只读回查，不盲目重发。仅在仍为本次候选代码且受保护配置未漂移时，允许一次原包回滚。损坏回执、外来代码或配置变化均不能触发覆盖。
- 固定探测仅覆盖私有状态、应用状态、匿名会话及匿名拒绝读取；必须验证应用协议封装，网关HTTP状态不能替代应用结果。未配置执行能力不得因本阶段通过而标为模型/Spark可用。
- 此策略不开放公网、不创建业务任务，不执行模型或Spark，也不代替IAM清理和真实云端验收。

`test/v2/control-code-update.test.mjs`覆盖故障、恢复、范围绑定和实际回环HTTP合同。HTTP合同使用真实应用路由与权限检查，但云持久化和FC写操作仍是替身，不应称为真实云部署验证。

执行接线为`scripts/control-code-transport.mjs`与`update-v2-control-code.yml`：只允许受保护main和明确阶段批准，目标通过临时加密Secret传入并在获取OIDC前遮罩；下载原构包Artifact并核对摘要/大小，签名下载旧代码仅允许对应地域OSS且强制HTTPS。对象只允许两个精确包、create-only私有写入及字节回读/ACL验证，桶隐私须有当前受保护预检证据。CLI禁止自动重试，恢复不重新提交未知写入，最终只上传加密证据。工作流不管理IAM，临时权限及Secret由受保护本机协调过程回收。

对象创建不发送ACL修改头，默认继承已经核验的私有Bucket；写后仍必须读取对象ACL核验。`oss:GetObjectAcl`是独立只读权限，不由`oss:GetObject`隐含授权，须获两个精确对象的明确补充批准后才可执行；不申请`PutObjectAcl`或全桶权限。依据：[官方GetObjectACL权限说明](https://help.aliyun.com/zh/oss/developer-reference/get-object-acl)。

CLI的ROA路径不拼接查询字符串：列触发器用`--limit`，读代码/弹性配置用`--qualifier`独立传参。回归覆盖实际构造的参数列表，诊断区分函数读取、触发器列表、并发、弹性和旧包读取；CLI路径拒绝单独标记，不能作为网络或权限错误原样重试。本机CLI dry-run仅验证命令形状，不代表云调用成功。

官方接口依据：[取得旧代码](https://help.aliyun.com/zh/functioncompute/api-fc-2023-03-30-getfunctioncode)、[并发配置](https://help.aliyun.com/zh/functioncompute/api-fc-2023-03-30-getconcurrencyconfig)、[弹性配置](https://help.aliyun.com/zh/functioncompute/api-fc-2023-03-30-getscalingconfig)。弹性配置比较排除当前实例数等运行态字段，保留配置策略，避免正常缩扩实例被误当成配置改写。
