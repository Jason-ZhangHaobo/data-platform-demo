# 人工辅助 SQL 修正的交付与演练

更新：2026-11-09。本机实现与验收；实际云部署、真实模型和发布另按具体有效范围验证。

## 1 背景

工程师可选择历史失败运行和成功基线，委托 Agent 修正证券加工SQL。新代码仍由模型生成，但包含人工参考依据。此前交付流程只接受工程师手工保存的版本；辅助修正结果因此停在开发核验，不能进入同一套文件与演练流程。

## 2 价值

独立工作台直接承接已核验的辅助修正结果，复用现有八文件交付包、持久演练及MANUAL版本审阅。不会把模型生成代码改标为手写SQL，也不会升级为原生自主成果。来源、文件、演练与后续发布分别绑定确切版本。

## 3 问题

- 修正任务成功不代表来源完整。须核对工程师、任务末次尝试、当前代码与运行、原失败依据、可选基线及保存证据。
- 引用历史依据不继承原包、原演练或原批准。相同SQL也可能属于另一任务和输入，必须重新固定新包并核验。
- 创建回执中断时，界面不得自动重提或重置请求编号；应查询原版本的交付记录，再继续同一次演练。
- 本机真实Spark、合成远程回执与真实云端执行需要分开统计，不能按界面状态或单次SQL通过计算完整E2E。

## 4 需求与验收

### 来源与文件

`manualCloudDeliverySource`兼容两种来源：既有手工接管版本；模型生成且明确记录人工辅助的持久SQL修正版本。辅助分支要求当前账号拥有任务与版本，末次成功尝试、当前任务SQL、代码摘要、运行及验证契约一致；任务、代码和运行的人工辅助归因须与服务端生成规则一致。替身、未知模型标识及原生代码不得借此进入人工来源。

原失败依据重新核对；对照修正还须重新核对冻结基线与证据摘要。文件演练维持现有隔离Spark、五场景及预算门槛。来源变化不创建新的计算，未知结果先读取原回执。

不可变清单 `source.attribution` 保留 `ENGINEER_ASSISTED`、修正任务、工程师及 `agentIndependentE2E:false`，可选增加 `developmentReference`：

- 普通失败修正：原运行、原版本、原代码摘要、初始SQL摘要。
- 对照修正：在上述内容外固定基线运行、基线代码摘要和保存证据摘要。
- 成功版本续改：固定直接父任务／运行／代码／证据与原始参考，来源与深度按[续改协议](assisted-success-continuation.md)核对，不能继承父包或批准。

此引用进入交付包摘要；任务、包和当前来源在演练与MANUAL发布审阅时再次核对。旧手工包不回填该字段。原生Agent准备／发布入口继续拒绝辅助来源；不复用其他来源的审阅或批准。

### 工作台

当前持久修正任务及其成功运行恢复后，显示人工辅助交付面板。依据默认折叠，按需查看原失败、基线和摘要。生成、八文件预览、文件演练编号、源版本和运行仍使用既有交互；代码未保存或展示历史运行时不能把旧结果用于当前交付。

准备结果未确认时，保留原请求并显示“查询原交付”，禁止再次准备和发布。查询成功后恢复同一包；继续演练须明确操作。刷新不重新调用模型或计算；已生成文件不显示为已部署，演练通过仍显示待审阅。

### GUI／API／CLI／MCP

- API沿用 `GET /runs/:runId/workflow`、`POST /runs/:runId/prepare-delivery` 和持久交付推进接口。身份从后端会话取得，POST为空对象并使用原幂等编号；邀请、CSRF、限定任务和到期边界保持。
- CLI：`shuduo agent workflow --id TASK --source-kind MANUAL --source-run-id RUN`；准备时使用 `shuduo agent prepare-delivery --id TASK --source-kind MANUAL --source-run-id RUN --request-id UUID --confirm`。
- MCP沿用 `agent_development_workflow`、`agent_delivery_prepare`，人工来源显式提供 `sourceKind:MANUAL` 和 `sourceRunId`；准备还需原 `requestId` 与 `confirm:true`。先只读核对来源，再提交空请求体；错误或未知回执不自动重试。

验收覆盖：普通失败及对照来源、归属与CSRF、引用或文件变化、旧批准拒绝、原生入口拒绝、原请求与演练恢复、权限到期、客户端一致性、界面文件预览及刷新。仅合成定时事件测试既有两个批次的归因传递，不代表真实云定时器验收。

## 5 Demo

虚构财富管理客户资产SQL在重复持仓回归中失败。工程师选择同口径成功基线，Agent生成修正版本，经独立核验后生成八文件交付包；依据随清单固定，再进行文件演练，最后进入确切版本审阅。

本机验收分别保存三类证据：已保存实际Spark参考依据；新修正任务及云接口的合成回执；实际生成文件的一次本机Spark五场景／测试SQL执行与独立字节核对。只有最后一项属于新增真实引擎执行，均不计当前完整E2E自主完成率或真实云发布。
