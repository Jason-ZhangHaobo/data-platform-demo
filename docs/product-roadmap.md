## M0 已核对事实
- 旧后端为 Node.js，元数据写入 OSS 单 JSON；不适合直接当作多用户生产库。
- 旧 Agent 使用关键词路由；旧质量/报表/实时指标多数预设；旧发布没有实际调度执行。
- 当前开发机可运行 Node.js 24；本轮已在项目内安装 Java 17/Python 3.12/Spark 3.5.7，并通过 23 项真实引擎用例；没有安装 Docker，也没有配置模型凭证。
- 当前云资源实际账单、域名、备案和模型能力未验证。
- UI 为大标题/长横向导航；V2 改为按工作组织的侧栏与开发工作台。

## 下一批工作顺序

1. 用户本机配置专用模型凭证，复跑真实生成/修复/取消与独立结果断言；没有凭证时不自动改用假模型。
2. 取得现有 FC/OSS/RDS 的只读账单，选择符合总预算的隔离执行与独立平台元数据库。
3. 完成 M1 真实模型评测和新指标契约，再进入 M2 发布审批、调度文件、执行批次与回滚。
4. M3 完成 DAPI/XAPI 外部消费，V2 CLI/MCP 迁移到同源 API。模块布局与可访问性持续一起验收。
