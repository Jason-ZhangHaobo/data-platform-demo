# 中国证券行业业务上下文

## 1. 长期默认背景

从本文件生效起，项目后续新增的 PRD、需求澄清、用户故事、页面原型、前后端参考代码、测试数据、验收用例、Data Agent 示例和培训材料，默认围绕中国证券行业的数据中台场景展开。

这里的“中国证券行业”是产品语境，不代表接入任何真实机构、交易所、监管系统或生产数据。所有机构、账户、证券代码、基金代码、客户信息、订单、成交、持仓、估值和监管报送数据必须是虚构数据。

## 2. 默认业务主体

- 券商经纪与财富管理：投资者、客户账户、资金账户、订单、成交、持仓、客户适当性。
- 资产管理与基金：产品、组合、估值、净值、份额、申赎、持仓和业绩归因。
- 托管、清算与运营：交易流水、清算结果、资金对账、持仓对账和异常处理。
- 行情与参考数据：证券主数据、交易日历、市场行情、行业分类和估值指标。
- 风险、合规与审计：风险指标、限额、异常行为、数据留痕、权限审计和监管报送准备。

## 3. 默认业务模块映射

| 数据中台模块 | 证券行业默认场景 |
|---|---|
| 离线同步 | 交易流水、持仓快照、客户账户、行情和参考数据的批量接入 |
| 数据开发 | 交易日加工、T+0/T+1 汇总、指标计算、宽表和数据集市加工 |
| 数据脱敏 | 客户姓名、证件号、手机号、资金账号、银行卡号和联系方式脱敏 |
| 数据资产目录 | 证券、账户、客户、订单、成交、持仓、产品、净值和指标的元数据、血缘与口径 |
| 账号、权限和审计 | 按机构、部门、岗位、数据域和敏感等级控制访问并记录操作 |
| Data Agent | 跨模块澄清数据需求、生成任务草稿、解释指标、诊断失败、查询资产和输出审计摘要 |

## 4. 默认术语与数据约定

后续文档优先使用“投资者/客户、证券账户、资金账户、订单、成交、持仓、证券主数据、交易日历、估值、净值、清算、对账、适当性、风险、合规、审计”等术语。

演示数据应使用明显虚构的机构名、客户名和标识，例如 `华东示例证券`、`INV-DEMO-0001`、`SEC-DEMO-0001`、`FUND-DEMO-0001`。不要使用真实客户、真实手机号、真实证件号、真实账号、真实交易记录或可被误认为真实的生产连接信息。

## 5. 场景设计优先级

新增业务场景时，优先从以下闭环中选择：

1. 需求澄清：明确业务角色、数据范围、频率、时效、敏感等级和验收口径。
2. 数据接入：将虚构的证券业务 CSV、数据库表或接口数据接入 staging。
3. 数据开发：完成清洗、标准化、汇总、指标计算和质量校验。
4. 数据安全：对客户和账户敏感字段实施脱敏、权限控制和审计。
5. 数据资产：登记表、字段、指标、血缘、负责人和业务口径。
6. Data Agent：通过自然语言完成查询、规划、预览、确认和执行总结。

## 6. 安全边界

本项目用于产品经理学习、公开演示和流程复刻，不执行真实交易、下单、撤单、资金划拨、清算结算、投资建议或正式监管报送。涉及这些动作时，只能生成模拟计划、只读预览或虚构结果，并明确标注“学习演示，不接入真实生产”。
