# 完整持仓目标快照 → 独立 Agent 开发输入

## 价值与当前范围

证券持仓经过全量同步、增量合并或显式删除后，工程师应能直接委托独立 Agent 开发该批实际持仓。原始增量文件、删除事件不是完整持仓，不能拿它们替代最终目标状态。

本机实现 `SYNC_MATERIALIZED_HOLDINGS_V1`。仅接受成功、实际执行、留存且重新核验的 CSV 目标快照，支持 `FULL`、`INCREMENTAL_UPSERT`、`INCREMENTAL_CHANGELOG`，目标名不再限于 `raw_positions`。范围为七个登记证券持仓字段，最多 500 行，可有 `currency`。这只证明所选目标的完整留存状态，不证明上游业务系统已全部接入。云端模式继续拒绝；旧当前表及 `SYNC_RUN_ARCHIVE_V1` 的选择、摘要、批准和口径保持兼容。

## 工程师操作

1. 完成离线同步并留存原批次，进入独立 Agent 数据开发，选择“客户资产 T+1”登记口径。
2. 在“本次数据与业务口径”展开“选择完整目标快照用于开发”，读取目录，按目标、模式、行数和原运行编号选取。
3. 点击“核对并使用完整快照”。目录仅是候选回执；此步重新核对元数据、实际行、币种、落地摘要及显式变更控制摘要。失败清除上一选择，不回退当前表或旧入口。
4. 描述开发需求并提交。服务端再次核对和冻结来源。后续同步变化不修改此任务输入；刷新、重读和人工续改沿用原冻结版本。切换新输入需要另建任务。

账户和现金始终来自登记上下文，不能从持仓事件猜造。已确认空持仓仍保留登记账户和现金：本仓库虚构基线中，客户一为 300 元，客户二为 200 元，持仓市值和证券数量为零。空输入不声称“实际行币种已核验”。未知客户、其他业务日、未登记字段、非 CNY 币种和不符合精度的金额仍拒绝。

## 共享契约

API 均以 `/api/v2` 开头，只允许本机回环开发范围内的工程师读取，不接受额外查询参数，不启动模型或计算。

| 操作 | 接口 |
|---|---|
| 读取候选目录 | `GET /development/synced-positions/materialized` |
| 核对指定原批次 | `GET /development/synced-positions/materialized/:taskId/:runId` |

选择对象固定为 `kind, targetTable, taskId, runId, targetHash, landingSnapshotHash, mode`。显式变更另需 `changeEpochId, changeStateHash`。不完整、未知字段及模式/代号/摘要不一致拒绝。任务冻结增加来源元数据、源版本、行数和冻结快照摘要；交付绑定分别为 15 或 17 字段，原 12/14 字段保持。交付校验重建登记上下文和独立预期，不能只更改行数或摘要。

```sh
node bin/shuduo.mjs sql materialized-archives
node bin/shuduo.mjs sql materialized-positions --task-id <UUID> --run-id <UUID>
```

MCP 对应 `sql_materialized_archives`、`sql_materialized_positions`。GUI/API/CLI/MCP 读取同一契约；实际开发、演练、审阅和发布仍沿原步骤和权限进行。

## 验收与未完成项

- 实际 CSV/SQLite：种子两行 → 清仓一行 → 完全空持仓；完整快照与原始增量区分，保留原归档，错误元数据/内容/币种/业务日/精度/身份拒绝。
- 原生任务替身回归：冻结后生产者新增持仓，原空持仓任务仍使用原输入；同请求回读不重复生成。新全量选择覆盖实际保存、重开、八文件校验和后续来源的协议回归。合成模型和计算替身不计真实模型验收。
- 本机真实 Spark 3.5.9：空持仓两个现金结果逐项断言，五组登记回归通过。该验证使用参考 SQL；不是模型自主生成，也不是云端发布。
- 实际 Chrome：完整快照选择、空持仓意义、读取失败清除旧选择及 420 像素窄屏；选择过程中没有生成任务、落地或启动计算。
- 新来源已能通过冻结输入和交付上下文检查，但增量/显式变更来源的完整离线复刻核验器仍待适配。现有核验器要求原全量 CSV，不能用单个增量文件证明完整输入；遇到新模式须明确拒绝，不称完整生命周期已通过。
- 真实模型、该来源的调度/发布/消费、远端执行和全面 E2E 仍分别待验。正式持仓 T+1 优先续接原检查点，不由本机回归替代。
