# SQL 字段值来源：资产与独立 Agent 共用的证据

更新：2026-11-09。状态：已实现并完成本机验收，尚未云部署。复用现有SQLglot 27.14.0，解析器与Spark Worker保持相同锁定版本；算法入口参考[官方字段血缘接口](https://sqlglot.com/sqlglot/lineage.html)，实际兼容范围按本项目测试记录。

## 1 背景

证券数据开发工程师在编写客户资产SQL时，需要核对总资产是否包含现金、证券数量来自什么字段，以及聚合经过哪些中间结果。数据产品经理也需要从发布数据集追溯原代码依据。资产模块原有表级版本关系不能回答这些字段问题。

本次在独立Agent开发结果区加入“字段来源”，资产血缘页展示同一协议的发布来源。读取只使用原运行保存的分析，不因打开页面启动模型、解析器或Spark，不用最新代码补造旧批次记录。

## 2 价值

工程师可把输出字段、脱去字面量的表达式和源字段对照查看；资产视图可直接跳转源表字段。Agent修正时可获得当前代码的字段依赖摘要，辅助排查问题。这里尚未测量真实模型正确率或工时提升，不能据此宣称达到完整E2E目标。

## 3 问题

表级关系不能证明字段值的来源；历史批次也可能没有分析。另一个版本的SQL、结构或输出不能作为本版依据。解析表达式所依赖的值字段，也不能完整说明连接、筛选、分组及权限如何改变结果行集。

## 4 需求与验收

| 编号 | 行为与预期 |
|---|---|
| FR-CL01 / AC-CL01 | Worker在已验证的SELECT/WITH执行路径保存静态值来源，绑定原SQL SHA-256、上下文、输入结构摘要和实际输出字段。嵌套CTE、聚合和类型转换可追到登记源字段；总资产示例同时追到持仓金额和现金金额 |
| FR-CL02 / AC-CL02 | 表达式字面量和注释不出现在分析展示；数据类型精度保留。常量标为常量，未能解析的字段或COUNT(*)等行集依赖不冒充纯字段来源；未知列、歧义列或结构不一致不能标完整 |
| FR-CL03 / AC-CL03 | 发布数据集读取核对原批次、发布、代码版本、SQL、输入结构和输出字段。错摘要、错结构或未知源字段返回未确认；原批次无记录时明确显示未采集，不回退最新版本 |
| FR-CL04 / AC-CL04 | 独立Agent“字段来源”核对当前保存SQL、代码版本、开发运行与结构。未保存草稿只显示原版证据及待验证提示；代码、结构或运行切换后，迟到核对不能覆盖新来源。不把开发运行称作已发布批次 |
| FR-CL05 / AC-CL05 | 资产页保留版本绑定图，字段映射只取已核对分析。静态值依赖与完整行集影响分开；坏回执保留原快照，重新读取后可恢复，读取不写入或计算 |
| FR-CL06 / AC-CL06 | 修正反馈只加入同一当前SQL／结构的字段依赖。白名单仅含输出名、解析状态、源表列和摘要；不含行、预期金额、参考SQL、表达式、注释或任意附加字段。模型适配器发送前再校验；无效摘要省略，不削弱独立结果断言 |
| FR-CL07 / AC-CL07 | 保存WHERE、JOIN、GROUP BY、HAVING及DISTINCT所引用的源字段，仅遍历实际被引用的查询作用域，未使用CTE不列为影响。保留关联类型、条件编号和作用域；USING经限定解析后的关联条件可追溯。子查询／行集依赖不能解析时标未解析；没有字段引用不等于没有行数影响 |
| FR-CL08 / AC-CL08 | 条件引用独立绑定原SQL与结构摘要，坏子摘要不得进入当前视图；可信后端可保留已核对的字段值来源，将条件标未确认。旧值来源记录没有条件记录时显示尚未采集。超过100组只展示前100组并标部分解析，不称完整 |

协议为`shuduo-sql-value-lineage/v1`，分析范围固定`STATIC_VALUE_DEPENDENCIES`及`rowSetImpactAnalyzed=false`。`COMPLETE`只表示所有输出的值来源解析完成；`PARTIAL`保留未解析字段；`UNAVAILABLE`不展示猜测的映射。解析失败不把正确的Spark业务结果改成失败，也不把业务断言失败改成通过。

资产`GET /api/v2/assets/:id/lineage`及详情中新增`columnLineages`；CLI `assets lineage --id`与MCP `asset_lineage`读取相同结果。开发视图使用既有运行资源中的分析，没有新建执行通道或权限。修正摘要协议为`shuduo-sql-value-lineage-summary/v1`，只在既有模型调用中使用，不触发新调用。

条件引用另用`shuduo-sql-condition-references/v1`，固定`STATIC_CONDITION_REFERENCES`及`semanticImpactAnalyzed=false`。COMPLETE仅表示本期支持条件的字段引用解析完成，未证明条件正确、行数变化、连接倍增、空值保留或权限效果。NO_COLUMN_REFERENCE包括无显式条件的笛卡尔连接，不能解读为无影响。当前不完整覆盖子查询、排序、LIMIT/OFFSET、窗口或任意外部数据源。

Agent修正中的条件摘要用`shuduo-sql-condition-reference-summary/v1`，同样核对当前SQL／结构和登记源字段；只保留种类、状态、关联类型、编号与源字段，不转发表达式、作用域标签或诊断原文。GUI默认折叠条件明细；资产页用表格并支持源字段跳转，窄开发结果区用卡片，保留原版证据与读取恢复。

完整本机CI1623项：1622通过、0失败、1既有跳过，类型、构建及入口体积门通过。本机实际验证一个Spark 3.5.9进程，参考SQL五场景、测试SQL和五输出的独立来源预期通过。资产界面用合成发布／审阅夹具配合真实解析结果核验跳转、错批次拒绝与恢复；独立开发界面导入同一真实Worker结果并保留手工归因，验证字段页、错SQL摘要拒绝和原链接恢复。界面仅读取，元数据摘要保持不变。修正模型请求用替身检验传输内容，没有新真实模型或云调用；这些结果不计当前v3自主20例、真实调度发布、真人审阅或公网验收。

## 5 Demo 与未完成范围

本机进入独立Agent数据开发，打开有分析记录的原运行，选择“字段来源”；代码／结果／字段来源在同一工作台。资产模块选择发布数据集的“血缘”，可看输出与源字段并跳转源表。示例总资产来自`positions.market_value`与`cash.available_cash`，证券数量来自`positions.security_code`；它们是虚构证券案例。

旧运行没有分析时，页面会明确提示，查看不会自动重跑。生产或旧云Worker不因源码合并取得新证据，需单独部署和验收。Hive方言、任意外部表、复杂窗口／UDF、完整行集影响、历史重新分析和公司真实目录仍不在本次已验收范围；不通过静态结果宣称完整Spark兼容或生产血缘。
