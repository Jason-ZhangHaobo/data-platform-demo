# M4h：版本化数据契约、兼容评估与实际检查

日期：2026-09-15。当前只使用本仓库虚构证券数据和本机实际运行，不含公司材料、真实客户、生产连接或公网验收。

## 产品闭环

1. 从当前资产字段和证据摘要创建契约V1，固定责任人、BACKWARD/FULL/NONE兼容策略、最低行通过率和最大新鲜度。
2. 变更先形成独立评估，记录新增、删除、类型、可空性、Schema摘要和版本绑定下游影响；评估不自动改当前版本。
3. BACKWARD下新增可空字段允许，新增必填、删除、类型变化、非空变可空均保守判为破坏性；FULL下所有结构变化均需确认。
4. 新版本只接受基于当前版本的未过期评估；破坏性变更必须在界面或API显式确认。
5. 检查读取实际资产元数据和可用实际行，计算结构差异、非空行通过率和新鲜度SLO。缺少行或时间证据时返回PARTIAL，不冒充完整PASSED。
6. FAILED创建告警；只有同一契约后续完整PASSED检查会关联恢复。检查和告警不保存业务值。
7. 资产Agent只读取契约字段/Schema摘要、最近检查状态和下游数量，不读取业务行，不可自动改契约。

## 实际验收证据

- 契约`raw_positions_contract`从`landing:raw_positions`的7字段实际Schema和资产证据创建V1。
- V1检查实际读取5行，行通过率100%高于99%目标，新鲜度小于86400秒，结构差异0，结果PASSED。
- 增加可空`currency`被判COMPATIBLE并创建V2；实际资产仍为7字段，V2复检缺1字段，结果FAILED并打开`DATA_CONTRACT_VIOLATION`告警。
- 从V2删除`currency`被判`REMOVED:currency`破坏性变更；未勾选确认时“创建V3”禁用。确认后生成V3，复检PASSED，原告警记录恢复检查ID并转RESOLVED。
- CLI读取到同一契约的3个版本、2个已应用评估、3次检查和1条已恢复告警；API幂等重放、陈旧评估和破坏性门由自动化测试覆盖。
- GUI将契约合并在“指标、标准与契约”资产治理标签中；创建、检查、兼容评估、版本创建和恢复均通过实际页面操作，不是静态卡片。
- GUI/API/CLI/MCP新增6个同源契约操作。Node全量测试181/181通过，TypeScript与Vite生产构建通过。
