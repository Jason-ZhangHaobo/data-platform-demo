# 服务规划事件：本机跨进程恢复验收

本阶段补充进程边界证据，不改变生产代码、默认驱动或权限。两个实际Node子进程依次打开同一SQLite/WAL和合成OSS文件，使用真实HTTP、FC入口校验、认证／CSRF、来源、版本及预算逻辑；模型、对象存储和Spark发布上游均为合成。

| 场景 | 中断与恢复 | 独立断言 |
|---|---|---|
| 事件已登记，模型未开始 | A正常退出，B重新打开原文件并消费原事件 | PID与bootId变化，业务恢复摘要一致；原会话／请求／任务／来源／窗口／额度保留；唤醒字节不变，只有B执行一次合成模型；重放不增加次数，人审同一方案才创建草稿 |
| 模型请求在途 | 观察开始标记后SIGKILL A，B在原测试租约过期后消费原事件 | A退出后文件仍为MODEL_IN_FLIGHT、一次尝试及8000保守Token；B只转UNKNOWN／NEEDS_CONFIRMATION，不自动再调用；明确确认后新事件才在B执行第二次合成模型，合计8700 Token，旧事件不能消费新确认 |

两例均断言只有一个原规划记录，父Agent及人工归因不改，原创建时间和请求UUID不被改写。会话使用原令牌，不在B重新登录；正常登录会撤销同用户旧会话，因此重新登录不能证明原会话恢复。

启动证据来自既有 `GET /api/v2/data-services/dapis/:id/recovery` 的bootId及fingerprint，并与真实子进程PID、退出状态和合成模型执行PID交叉核验。单个报告或不同PID本身不足以证明业务数据恢复，必须同时检查原记录、状态摘要和计数。

测试入口：

```sh
node --test test/v2/service-agent-process-recovery.test.mjs
```

无需云或模型凭证。测试进程只接受带明确合成标记的配置，不读取 `.env.local`，不通过命令参数或输出传递密码／密钥，不执行真实计算。对象替身限制固定唤醒前缀并校验不可变字节。可通过 `SHUDUO_SYNTHETIC_PROCESS_EVIDENCE_DIR` 保存允许字段的本机报告，目录必须位于被Git忽略的 `.runtime/`；不得将私有报告上传公开仓库。

测试在途场景使用五秒租约和实际等待，便于重复验收；不修改生产九十秒租约，也不调整任务创建时间、执行窗口或预算来伪造恢复。子进程、连接和临时文件均由测试清理，强制中断与正常退出分别记录。

本机新进程验收不证明真实FC实例更换、MySQL／OSS网络与CAS故障、真实模型正确率或公网性能。后续应先核对受保护配置的当前交接状态和可复用版本，再准备与确切版本绑定的私有云验收；原缺失输入不重复催填，未有有效新范围不激活云写入或付费。
