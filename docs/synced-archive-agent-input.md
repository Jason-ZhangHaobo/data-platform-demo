# 在独立 Data Agent 中选择原持仓批次

本机范围，使用仓库虚构中国证券持仓。用于当前落地表已被后续同步覆盖时，明确指定原批次开发；不把当前表重新标记成历史数据。

## 使用流程

1. 在数据源与同步模块完成 `raw_positions` 的 LOCAL_CSV／FULL 同步，保留完整原批次快照。
2. 打开独立 Data Agent 的“本次数据与业务口径”，展开“选择原同步批次”并读取归档目录。
3. 目录最多列最近100条回执候选，尚未核对行数据。选择确切任务／运行后，点击“核对并使用原批次”。
4. 后端重算原快照与行摘要，核对原元数据、字段、客户／证券、固定业务日和币种。成功后页面明确标记使用原归档；失败不回退当前表或登记样例。
5. 写需求并明确提交。提交时再次核对同一归档摘要，冻结输入后再按原开发流程生成代码、执行和核验。只读查看及选择不会运行模型或Spark。

当前限制沿用已登记持仓开发：1—500行、七个合同字段，仅可额外携带逐行为CNY的 `currency`；账户和现金使用登记样例。当前表发生覆盖或源有新版本，不改变原任务的元数据版本。增量批次、其他目标表、MySQL源及其他业务日尚不纳入这个开发入口，不影响通用同步快照预览。

## 兼容与恢复

旧三字段选择仍表示“核对当前表”，当前提交变化后继续拒绝。归档选择显式包含 `kind=SYNC_RUN_ARCHIVE_V1`、任务／运行、目标表、落地摘要及 `landingSnapshotHash`。该归档摘要与冻结上下文的 `snapshotHash` 含义不同。

新冻结来源在已有绑定中增加kind和归档摘要，交付上下文、请求签名重建及保存链路复核同步识别。旧绑定、交付文件和幂等请求保持兼容，不自动升级旧来源或继承批准。已保存冻结输入独立于当前表及源归档；重开原任务按原请求恢复，不重新读取当前数据或新增计算。

## 共用只读接口

- `GET /development/synced-positions/archives`：候选回执目录，不返回业务行或“已核验”承诺。
- `GET /development/synced-positions/archives/:taskId/:runId`：实际重核指定归档，返回选择、原元数据编号、行数与币种结论，不返回行数据。
- CLI：`shuduo sql sync-archives`；`shuduo sql archived-positions --task-id UUID --run-id UUID`。
- MCP：`sql_sync_archives`、`sql_archived_positions`。

新增入口限本机工程师；无效会话、跨项目及非本机环境拒绝。新任务仍需原Agent身份、预算、执行环境与来源门槛；不开放云端或公网写入。

## 验证范围

真实CSV／SQLite归档、覆盖、摘要与权限校验单独验收；模型和Spark替身用于开发／交付／发布／离线复核契约回归。替身不证明真实模型、真实Spark或正式公网完整E2E。正式T+1继续沿原检查点，不因本项新建任务、重跑自检或替换线上冻结包。

## 原生 Agent 的文件交付与失败恢复

同一原生Agent任务、代码与冻结运行已核对时，直接显示原Agent的交付记录、八文件及演练状态。工程师编辑后保存的手工运行仍进入独立手工交付；编号或快照不一致时关闭交付，不静默换来源。

冻结持仓采用自身登记契约，前端同时要求输出字段/类型与原五场景核验。普通持仓、股票现金等其他契约不能替代。实际失败、取消或中断优先于旧阶段文案，避免失败后仍显示“正在演练”。已生成文件可以查看、下载和只读重读；重新准备会新增一次文件演练，不能当作只读刷新。

恢复时先回读原失败和包。对相同成功开发版本重新准备时复用已有确切包，失败回执保留，新的演练另存编号；不重跑开发、不重新生成包、不继承人审或发布批准。演练成功显示“待审阅交付”，不自动发布。
