# M4c：资产目录、血缘、指标与标准

2026-09-15新增的数据契约闭环作为不改写本页历史验收的扩展，见[M4h数据契约](m4h-data-contracts.md)。

日期：2026-09-14。当前全部资产均来自本仓库虚构证券数据和本机实际运行；未连接公司目录、真实客户、生产元数据或公网资产。

## 产品语义

1. 目录不是手工造出的静态卡片：Spark样例表、已采集源、离线落地表、实时源/状态、已验证发布数据集和DAPI/XAPI按当前资源自动投影。
2. 多次成功发布批次合并为一个逻辑业务数据集，保留版本数和最近证据，避免目录被运行批次淹没。
3. 业务名称、说明、域、负责人、分类与标签独立版本化，不覆盖底层字段、行数或内容摘要。
4. 血缘来自同步字段映射、实时任务、发布批次和数据服务版本绑定；上游与下游分别遍历，避免把共享来源的兄弟资产串入当前链路。
5. 当前只有同步映射具备字段映射证据；Spark SQL字段级表达式解析固定返回`sqlColumnLineageParsed=false`。
6. 指标与标准首版只在有实际本机行数据的落地表和实时状态表上运行。SUM用整数分精确计算；标准失败值只保留SHA-256。
7. 资产Agent只读取目录摘要和版本边，最多引用8个已登记资产；未知引用失败关闭，不读取业务行、不写资产。

## 测试与边界

5项M4c测试覆盖目录/血缘、说明版本、实际指标、实际标准、Agent引用校验、模型行数据隔离和API流程；多端回归同时验证CLI/MCP。全量`npm run ci`为121/121，源码检查和两个前端构建通过。

M4c只完成本机合成范围。外部Catalog/Glue/Hive Metastore、SQL AST字段级血缘、跨项目权限、术语审批、指标版本迁移、分布式执行和公网搜索均未实现；下一步M4d建设数据质量，不能把资产标准检查冒充完整质量中心。
