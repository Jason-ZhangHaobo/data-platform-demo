## 产品目标与边界

交付国内公网可实际使用、智能化、功能完整、易用且有审美的数据中台，为证券行业数据产品经理提供可带回公司的建设与复刻参考。经典功能可以独立操作，Data Agent 深度融合各模块，GUI/API/CLI/MCP共享资源、身份、版本和运行结果。以DataWorks为主要对标，同时参考Databricks、Snowflake、Fabric、Collibra、Informatica；比较具体任务体验与结果，不宣称已全面超越。

仅使用虚构中国证券数据，聚焦经纪财富管理与资产管理/基金。禁止把公司材料、内部地址、真实用户数据或秘密上传到公开仓库、日志、模型或报告。凭证可以由已授权的部署进程在受保护环境内使用，不向聊天回显。

## 实施顺序

1. 修复部署准备与秘密处理。检查JASONSECRETS的格式、必填项、占位符和管理员哈希，反馈只包含键名/错误码；展开后的每个秘密须在GitHub日志中屏蔽，尽量缩短可见范围。修复目录清理、配置校验与测试覆盖问题，不能只靠字符串匹配测试宣称安全。
2. 一次性诊断部署权限。核对实际OIDC身份、信任、附加策略及预算/RAM/VPC/ECS/FC/OSS各调用所需动作和资源范围。以最新失败为依据，先修正实现错误；新权限超出现有批准时，给出完整最小策略、用途、影响和回滚，一次请求确认。不要猜一个权限就运行一次完整部署，不跳过预算门，也不改用高权限身份绕过拒绝。
3. 完成独立V2云控制面。优先复用现有个人试验RDS/私有OSS，分离平台元数据与业务数据；核验实际运行角色、对象前缀权限、私网连接、冷启动、并发冲突、恢复和不可变产物。实例并发1不等于最大实例1，必须单独验证实例上限和按需缩至0。私有预置可先于域名备案，公网开放仍需单独验收。
4. 完成云端执行与持久调度。隔离Spark Worker真实运行Java/PySpark，验证鉴权、权限、限时限资源、取消、失败和证据落盘；把依赖本机定时器/后台进程的任务改造成在FC冻结、缩容和重启后仍能恢复的持久任务与调度机制。业务审批必须绑定用户实际审阅的版本，不能由开发代理伪造审阅。
   当前W1的318,914,420字节Linux包已可复现并从包内真实运行；W2计划必须使用杭州私有OSS代码位置和官方Nodejs20/Python310/Java17 v3层。精确对象Get/Put权限已获授权，但只有策略实际附加且云端四项私有性证据通过后才能上传和创建Worker；控制面Invoke属于W3，仍未授权并须单独审批。
5. 完成标杆业务闭环：财富顾问客户持仓与资产分析，从需求理解、写代码、调试、生成调度及部署文件、受控上线到监控恢复；验证客户总资产、持仓市值、证券去重数量、资产类别和行业分布。接入DAPI/XAPI与示例外部消费者，验证授权、参数、版本、限流、超时、日志和撤销。
6. 按PRD能力表补齐经典模块真实能力：外部数据源/元数据、离线全量增量与CDC、实时同步和开发、离线SQL/Python开发、资产血缘、指标标准契约、质量、安全脱敏、报表、运维。为每项写出真实实现/本机限定/未实现及证据，不能将CSV/JSONL模拟适配器、固定输出或菜单入口视为最终完成。资源不足时提出明确取舍，未经确认不删减目标。
7. 并行推进Agent与易用性。把跨模块路由推进为可持续执行、可恢复、可接管的任务编排；专业Agent按资源权限工作，发布受版本审阅约束，运维诊断引用运行证据。统一导航、布局、状态反馈、键盘操作和响应式；每模块手动流程与Agent流程都需实际可用。
8. 公网发布与成本验收。用户完成域名选择、必要实名/备案/支付后，由Codex完成DNS、证书与续期方案、HTTPS、严格Origin和受邀登录。优先查询备案资源资格和首年/续费总成本，未经批准不新购资源。月成本尽量50元以内、上限200元；包括RDS试用到期、存储、备份、FC、模型、流量和域名。账单可能延迟，告警不是硬封顶，必须结合配额、限流、停用机制和实际费用验证。
9. 公网完整评测。预先冻结至少20个不同证券业务任务，每例覆盖需求→代码→调试→调度→部署→上线→监控，至少观察实际调度批次。成功率目标≥85%，人工救援、阻塞、取消、失败保留且单列，安全拒绝用例不能抬高业务成功率。本机结果不得复用为公网结果。实测Safari/Chrome及国内两类网络；首屏可操作目标≤3秒，冷/热启动分开记录。无第二网络访问能力时明确待用户配合实测。
10. 最终交付。更新需求、决策、架构、路线图、接口、验收、成本与恢复手册；完成公司复刻手册和全流程PPT，包含总路线、用户路线、Codex路线、里程碑、产物及作用。最终提供实际可访问URL、受邀使用流程、真实验收结果、适配边界和已知限制。

## 执行效率与完成条件

每轮先确认现状，选对最终结果有价值的工作；单项受阻时推进其他独立任务。优先CLI/API，长期运行跟踪同一任务ID，观察超时不当作执行失败。依据改动风险运行必要测试，没有代码变化或新风险时不反复跑CI、不为重复状态单独制造提交。

进展汇报以可用功能、排除的真实阻塞和验收证据为主，不以提交数或测试数当作产品完成度。对仍未完成的经典能力和Agent能力保持待办，不得笼统宣称“本地全完成、只差公网”。

真正需要新授权时先完成可独立完成的准备，一次列出具体动作和理由；自动审批拒绝时如实说明拒绝原因。若所有有意义的路径确实受阻且达到目标工具的阻塞阈值，调用工具标记blocked并只给一次可执行交接，不继续循环相同回复。

仅在公网真实可用、经典模块与Agent按约定范围完成、完整评测达标、费用与恢复措施验收、复刻手册和PPT交付后标记总目标完成。不得自行把总目标缩为“部署成功”或“测试通过”。
