# 数舵 V2：当前执行与续接清单

更新日期：2026-10-12。本文件只记录通用产品计划与代码进度，不能作为实际部署或云端验收证据。实际环境和运行结果须读取本机受保护的 `docs/private-execution-state.md`，禁止将该文件及其派生运行事实发布到公开仓库。

## 下一轮目标模式：10小时验收驱动执行指导

本节是用户要求的下一轮执行计划，保存计划不等于目标模式已开启。实施开始时记录本轮开始时间、时区和10小时截止时间；下面时间分配是可调整的工作时间盒，不是工期或不间断运行承诺。目标模式仍受平台额度、中断及必要授权约束。

### 本轮目标与不做事项

首个恢复代码增量的合同与验证方法见[私有服务恢复](private-service-recovery.md)。运行启动标识与实际行完整性共同对照；独立本机进程测试和文件CAS传输替身不能升级为FC/MySQL/OSS验收。当前环境中的真实完成状态仍只读取受保护续接文件。

版本治理增量见[审阅与回滚合同](service-version-governance.md)：发布与切换携带确切审阅上下文，原请求与历史回执可恢复；实际环境的部署/验收仍与通用实现分开记录。

优先交付一个可演示、可恢复、有证据的独立Data Agent标杆工作台：复用已核验证券任务与发布结果，串起核验、文件、审阅发布、监控和DAPI/XAPI消费。先解决服务持久恢复与版本治理，再完善用户体验，最后统一验收；不能为增加功能数量跳过可靠性门槛。

本轮不追求全部经典模块、世界领先声明、完整公网20例/85%或正式PPT。未获得当前具体授权，不新建云资源、IAM权限、永久触发器、公开端点或付费批次；不重复运行已通过的模型/Spark任务，不复活前轮已撤销的令牌。备案、实名、验证码或购买不能成为十小时空等事项。

### 阶段、产物与通过条件

| 阶段 | 时间盒 | 工作与产物 | 通过条件及被阻时替代任务 |
|---|---|---|---|
| S0：冻结基线 | 0—0.5小时 | 读取AGENTS、PRD、决策与受保护最新状态；检查Git、当前包、有效凭证、环境与授权；建立本轮任务表和开始/截止时间 | 列清已验收、待验证、仅本机、私有云与公网边界；不按历史TODO重新部署。认证缺失就记录阻塞，继续离线验证，不要求用户重填已有配置 |
| S1：持久恢复P0 | 0.5—2小时 | 为服务/数据快照/日志/撤销状态建立恢复对照；实现必要的窄范围诊断和一键验收脚本；在获准的测试范围证明进程重建 | 必须有不同运行实例/启动标识，并核对原服务ID、版本/摘要、实际数据、日志和撤销状态；刷新浏览器或重启Cloud Shell代理不算FC冷启动。云端被阻时，以独立后端进程+相同持久快照做本机恢复/冲突/缺失测试，只标本机通过 |
| S2：版本治理P1 | 2—4小时 | 复用既有版本API与SQLite快照查询，测试DAPI V1→V2→V1、XAPI固定子版本、批准失效/输入变更、来源混用拒绝；补必要UI接管 | 同一消费者能辨别实际版本与正确结果；旧批准不能发布新配置，XAPI不随子服务版本偷偷变化，历史调用和失败保留。仅在独立测试服务或已获准的测试版本上变更；云端受阻则完成本机/API/CLI/MCP契约回归，不改原健康服务 |
| S3：独立Agent体验P1 | 4—6.5小时 | 在同一Agent任务界面显示需求、计划、代码/差异、核验、交付文件、发布批次、监控与接口消费证据；提供继续原任务、查看证据、经典模块接管 | 用户能看清当前阶段、失败原因、产物来源和下一动作；只有有证据的步骤才显示完成。保护未保存代码，避免重复点击、身份混用、错误提示不清；1280/768布局无页面级横向溢出。发布/授权仍需合规审阅，不在聊天中自动代批 |
| S4：集中回归P1 | 6.5—8.5小时 | 合并同一范围内修复；执行每阶段定向回归、完整CI和GUI旅程；准备/运行少量明确分层的证券用例 | 覆盖正常结果、口径/字段变化、重复请求、重启、失效批准、权限拒绝和失败恢复。最多先选3条必要的新增真实付费用例，只有现有授权覆盖次数/范围且预算通过才运行，否则仅准备。冻结20例清单，但不把合成测试、历史重放或人工救援计作新的自主E2E成功 |
| S5：验收交付 | 8.5—10小时 | 补足阻塞项，做最终CI/版本校验/清理，保存演示截图、调用示例、证据索引、遗留问题与唯一下一步 | 代码、测试、部署/实例、界面、结果、恢复和权限证据能对应；临时入口明确到期，失败与未验收项不隐藏。适合公开的代码才能沿已有有效授权提交/推送/部署，私有标识/账单/日志/截图不出受保护目录 |

时间可因前序提前完成或证据变化重新分配，但最后至少预留1小时用于回归和清理。某阶段超时不等于完成；其下游云验收保持待验证，可推进没有该依赖的实现/本机测试。不得把前序故障带入原健康发布。核心门槛提前全部满足可提前结束，不为凑满10小时扩散范围。

### 故障处理：分类、限时、换路

| 现象 | 先查与允许重试 | 到达时间盒后的去向 |
|---|---|---|
| GET超时、网络短断或暂态5xx | 先核实进程/凭证是否有效；只读请求最多2次有界退避（建议2秒、5秒）。没有新证据不第三次原样调用 | 单故障15分钟无进展，保存错误分类和恢复点，转做对应本机测试、UI或文档 |
| 创建/发布/调用付费模型结果未知 | 先按原任务/幂等键/包摘要查证；未确认前不重提、不创建新批次。模型未知结果保留预算预留 | 查询仍不可用就保存UNKNOWN，继续其他不依赖该结果的工作；不得自动付费重试 |
| 401、403、AccessDenied、STS缺失或过期 | 检查身份、Token传递、精确动作与有效期；有正常刷新路径才刷新一次。不重置用户密码、不扩IAM | 认证链诊断累计最多20分钟；必要时一次性提出具体配合及准确入口，同时继续本机任务 |
| Cloud Shell断开、端口不通、无命令回显 | 先确认终端提示符、是否有原进程、监听/日志和会话期限；排队命令结果未知时只读查证，不叠加启动。端口占用先识别原进程 | 同一故障最多恢复2次，或10分钟无进展就转离线工作；不靠保活/反复让用户登录冒充长期入口。只有通道状态变化才回来继续 |
| 上传403、构包/解压失败 | 检查短期下载URL、已有对象、SHA/字节和归档完整性。相同包不重构；过期仅刷新下载授权。改用分片时必须逐片完成、最终摘要一致并完整解压验证 | 两次同类失败后换传输假设/已授权路径。先在本机确认修复，不重复传50MB包或使用损坏归档 |
| 409/CAS、版本或输入漂移 | 重读最新状态，核对预期版本、任务归属与摘要；先判断是否已提交成功 | 不覆盖冲突、不去掉版本检查；保留冲突用例，转其他资源的独立测试 |
| 429限流 | 区分业务版本限流、平台流控、队列满；记录Retry-After和具体code | 业务限流的预期拒绝计入证据，不以重试绕过；平台流控有界退避，必要时降低请求批量但不提升容量 |
| CI/业务断言失败 | 一次最小复现，定向修复后回归；证据不符时保持未通过 | 定位25分钟无新证据就换假设/缩小用例；未通过的相关变更不部署，也不以放宽断言换绿灯 |
| 安全拦截、预算门或必要本人操作 | 停止涉及该边界的动作；说明精确风险与范围 | 不换工具绕过、不向用户泛化索权；继续不受影响任务。全部有效任务都依赖该边界时报告阻塞，不能用无关整理充当进展 |

建议时间盒是排障上限，不是计时一到就无依据切路。切路前保存最后成功点、未知写入、待清理资源和下一次最小诊断；只在新证据、正常授权或外部状态变化后重试。禁止30分钟没有证据变化仍在同一浏览器/上传/登录循环里消耗时间。

### 授权、费用与连续执行规则

- 开始时将已有授权逐项映射到本轮操作、资源、数据、次数和期限；已经用完的临时批次/触发器/测试令牌授权不当作永久许可。本文件及目标模式本身不授予新权限。
- 普通范围内的设计、代码、虚构本机测试、证据整理直接推进；云写入、推送、合并和部署必须符合当前有效授权。新费用、敏感凭证/权限动作和平台要求的当次确认仍遵守；尽可能一次性汇总可预见的具体请求。
- 月度总预算上限200元；付费模型/计算、部署前刷新当前费用及预算预留。没有新付费需求时不频繁查账唤醒资源；账单查询时点低于预算不是未来费用保证。无付费次数授权就先做本机与只读工作。
- CLI/API优先。GUI只用于必要登录、可见用户旅程和审美验收；需要用户时打开准确界面或给链接。能自行完成的已授权步骤不交给用户。
- 同一云资源写入串行；可并行不同资源只读检查和本机测试。等待CI或外部状态时推进独立工作，不高频轮询，不启动未经要求的子Agent。
- 每个有意义增量先定向测试；同一修复范围批量构建。公共源码/依赖/后端变化才构对应云包；纯静态修复不重构Worker或后台。不重跑未变更的真实模型/计算结果。
- 完整CI在最终代码版本上通过后交付；每次回归保留范围和环境。界面必须验证实际内容、状态、错误恢复和布局，不只看HTTP 200或按钮出现。
- 持续将检查点写入受保护最新执行状态，不能仅存临时VM；里程碑及重大阻塞时简明反馈。自动续接读取文件继续，不让聊天频繁回忆替代执行；活跃工具执行中仍保持必要的简短进度沟通。
- 到10小时截止、用户停止或系统额度终止时停止实质执行，先做安全清理并交付完成/未完成/阻塞/恢复点；不能为了时间到而把未达成目标标记完成，也不创建无限循环或额外定时任务。提前全部完成也直接交付。

### 任务板与交付格式

受保护执行状态每项至少记录：优先级、依赖、状态（TODO/DOING/实现完成/本机验收/私有云验收/待授权/阻塞）、开始时间、通过标准、证据路径、最后成功点、错误分类、重试次数、替代任务、下一步。每次只保留一个DOING主任务；等待时做独立验证不改变其依赖。

交付必须包含：本轮实际完成事项与意义；代码/CI/界面/真实结果/恢复证据；哪些仅本机、哪些私有云、哪些公网；仍未完成和具体阻塞；费用/资源/权限是否发生变化；临时资源与测试凭证是否已清理；唯一下一步及是否需要本人配合。禁止使用“整个中台已完成”代替分阶段验收。

目标模式写法参考官方[Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)：可核验结果、证据面、约束、范围、迭代策略和停止条件。时间盒为本项目执行安排，不是官方10小时运行保障。

## 总目标与剩余顺序

交付国内公网 HTTPS 实际可用、智能化、经典功能完整、易用且有审美的数据中台。Data Agent 是独立任务工作台；经典模块保留独立操作与人工接管。GUI/API/CLI/MCP 共用身份、权限、资源、版本和结果。仅使用虚构中国证券案例，覆盖经纪财富管理及资产管理/基金；不公开公司材料、内部地址、真实业务数据或凭证。

月运行费用尽量不超过 ¥50，上限 ¥200；资源、模型、存储、流量及试用到期费用都应核算。预算告警不等于账号硬封顶，未取得当前完整账单不能宣称全站预算已核验。

后续顺序：

1. 当前 Agent 开发交付闭环与真实私有云验收。
2. DAPI/XAPI 开发、测试、授权、限流、版本、调用日志及真实结果消费。
3. 数据源/元数据、离线与实时同步、资产血缘、质量、安全脱敏、报表及运维等经典模块真实实现，逐模块接入 Agent。
4. 至少 20 条完整“理解需求 → 代码 → 调试 → 调度 → 部署 → 上线 → 监控”独立评测，至少 17 条成功；不能以 SQL 跑通率代替。
5. 备案及技术门通过后完成域名、HTTPS、公网权限与 Safari/Chrome、多网络和性能验收。
6. 复刻手册与最终全流程 PPT；PPT 在约定范围完成或用户明确要求时生成。
