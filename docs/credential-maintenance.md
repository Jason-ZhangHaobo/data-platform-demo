# 凭证维护：只读业务下的最小执行顺序

更新：2026-11-02。本文是源码与验收约定，不表示任何真实凭证已轮换或云端已更新。实际资源、批准、预算、旧任务和执行回执只留在受保护的私有记录。当前产品主线仍是 Agent 开发、独立核验、交付与恢复；本专项只解除安全前置条件，不扩展通用运维平台。

## 1. 四类配置不能相互代替

| 类别 | 持久化权威来源 | 配置消费者 | 必须验证的结果 |
|---|---|---|---|
| 模型 API Key | 模型服务提供方 | 控制面 `DASHSCOPE_API_KEY`、同名 GitHub Environment Secret、本机受保护配置 | 新 Key 的地域与接口匹配；有界真实调用才算生成可用，保存成功或模型列表可读不等于生成成功；旧 Key 另行确认撤销 |
| 数据库密码 | RDS 账号 | 控制面 `V2_MYSQL_PASSWORD`、同名 Secret、本机受保护配置 | 新实例建立新连接并读取原有项目；不是旧连接池仍可用。只同步连接配置不会重置 RDS 密码 |
| 用户登录密码 | 持久化用户记录中的 scrypt 哈希 | 登录与会话服务；`V2_BOOTSTRAP_ADMIN_PASSWORD_HASH` 仅用于首次创建账号 | 本人用当前密码确认，更新后旧密码与旧会话失效，新会话保留原权限边界；重启后仍有效 |
| Worker 签名密钥 | 经批准成套切换的服务配置 | 控制面 `V2_SPARK_EXECUTOR_SECRET`、Worker `V2_SPARK_WORKER_SECRET`、GitHub `V2_SPARK_EXECUTOR_SECRET` | 新密钥签发的新固定自检结果通过独立断言；控制面密钥与 `V2_SPARK_QUEUE_READY_JOB_ID` 同次更新；不能拿旧签名就绪回执充当新密钥验证 |

数据库密码和用户密码由用户自行选择，不随机替换。只有服务间签名密钥可在具体授权后自动生成。不同用途的密码和密钥不共用，不进入聊天、命令参数、公开日志或 Git。

上述四项必须使用同名独立 Secret，不能再从 `JASONSECRETS` 回填。导出器忽略旧四项；如果消费工作流显式声明了某项但为空，且 bundle 仍有其旧值，导出直接失败且不写任何环境文件。远程 Spark 已配置时，部署/预配置校验还要求独立 Worker 密钥；纯初始预配置或只用调度密钥的流程不强制加载无关凭证。

这只是阻断旧值重新生效，**不表示云端 bundle 内旧副本已删除**。如日后具有受保护的原件及清理授权，只修改对应四项、保留其他项；不能盲删整个 bundle，也不为清理而公开导出其内容。GitHub Secret 名称和更新时间只能证明元数据，不能证明新值有效。

## 2. 本人改密不是业务开窗

复用现有“平台设置 → 修改登录密码”，不新增公网密钥录入页。只有精确 `POST /api/v2/auth/password` 可穿过只读或受限业务入口的第一层路由门，后端仍验证真实会话、CSRF、Origin 和当前密码；身份取自会话，不接受指定其他用户的字段。

- 接口只接受 `currentPassword`、`newPassword`。拒绝目标账号、项目、角色、权限等额外字段。
- 成功响应必须在持久化完成后发送，并撤销全部旧会话；存储失败不能返回成功或先发送新 Cookie。
- 新会话响应与登录接口使用相同的只读/开发/发布/服务范围投影，不能因为改密恢复完整业务权限。
- 业务窗口到期后依然只读；邀请、创建任务、发布和凭证管理不随改密开放。
- 原有本地开发身份不提供“改密”按钮；未登录用户先登录本人账号。既有管理员引导哈希不能代替真实用户改密。

真实云端验收必须包含：旧密码拒绝、旧会话拒绝、新密码可登录、原业务写仍拒绝、持久化恢复。测试环境使用虚构账号与合成存储，不能用其结果替代真实云端验收。

## 3. 一次集中准备，按依赖分步切换

1. **先准备源码。** 修复本人改密与专用 MySQL 同步的基线兼容性，执行定向回归、独立审查、完整 CI。构建必须绑定确切提交；过期产物不复活，新应用改动完成后再构建一次。
2. **集中确认维护范围。** 列明现有两个函数、确切代码对象、四项凭证、备用 bundle 项、账号、最多写入/回读次数、维护期限和费用。不借用旧业务验收批准，不增加 IAM/入口/规格/网络/资源。
3. **先部署本人改密修复。** 应用更新与凭证切换分开记录；全程保留只读，核对真实新实例。用户从正式设置页自行选择新密码；只返回成功/失败状态，不收集其明文。若要同步引导哈希，需另有受保护输入或内部传输路径，不能从浏览器公开响应导出哈希。
4. **收齐新配置再动现有服务。** 使用受保护的本机入口或提供方控制台；数据不经 URL、剪贴板日志或 shell 参数。前置校验不自动执行重置、部署或真实模型/Spark。缺一项先保留只读，不造成半轮换。
5. **确认旧任务已结清。** 读取原任务/结果/取消/wake 检查点，确认无在途、待回收或未知付费结果，旧后台授权已不能执行。不清零历史，不通过关一个开关就假定队列已空。
6. **按批准切换。** RDS 只重置密码，不选择同时重置账号权限；模型新 Key 保持原地域与最小模型权限。Worker 新签名密钥先配合一次固定虚构自检收取新签名回执，再将控制面新密钥和新就绪编号同次切换。其他配置须完整回读不变，允许的短暂维护不可用事先说明。
7. **验证后退出维护。** 验证新启动标识、数据库新连接、本人登录/会话、Worker 新结果和就绪；有界模型生成仅在另有额度时执行。确认旧 Key 已按批准失效，旧备用副本已处理，撤销临时权限/Secret，业务仍只读。随后回到原人工交付/恢复主线。

## 4. 可复用工具与不得直接套用的工具

- `scripts/credential-account-rotation.mjs`：无网络/文件副作用的第一阶段编排器，要求外部核实真实批准，逐步记录尝试与确认。每次改密、数据库重置、控制面同步均只发一次；非空未完成检查点必须先对账，不能自动重放。执行器不处理Worker、撤销旧模型Key或真实生成测试。
- `scripts/credential-auth-http-adapter.mjs`：固定正式HTTPS来源，Cookie和CSRF仅驻留内存；每个实际HTTP请求前记账，限制响应大小/耗时，拒绝重定向，不自动重试。使用实际认证组件生成Cookie做合成测试；恢复对照固定一个既有XAPI，不创建接口或运行查询。身份/只读状态与前后启动标识、配置回读共同构成实际恢复证据。

- `createSecureConfigServer({prepareOnly:true, plannedEmail})`：新增同进程准备能力。固定账号，严格收取用户自选数据库新密码、当前登录密码、新登录密码及确认、模型新Key；不收取/生成Worker密钥。所有输入仅短期驻留内存，无云端提交、`.env` 写入、工作流派发或模型调用。`waitUntilPrepared()` 只返回已完成提交的无值回执，`consumePrepared()` 仅能领取一次；过期或关闭释放引用。调用方仍需独立授权校验才能消费执行。独立CLI的`--prepare-only`会拒绝启动，避免用户填完却没有消费者、最终过期重填；真实填写页必须由已审阅的同进程驱动启动。本轮不因此启动实际收集或读取真实凭证。
- `scripts/sync-v2-control-mysql-secret.mjs`：两次前置快照比对，唯一目标变量写入，完整回读核对。私有单并发和公开只读八并发应是两条显式基线，不能简单取消并发检查或把线上并发改回旧值。成功仅表示连接配置同步，不表示数据库密码已重置或新连接已认证。
- `scripts/start-v2-secure-config.mjs --mysql-only`：现有入口会触发 `main` 的同步工作流；对应修复尚未进入该分支时不要让用户提交，也不要用默认模式要求重复填写三项账号。
- `scripts/refresh-v2-spark-readiness.mjs`：可复用固定载荷、时效、签名和独立断言，但现有实现只更新就绪指针，**不是密钥轮换器**。新旧密钥不同时不可直接运行；后续若实施，需最小适配“验证新密钥证据＋同次切换密钥/指针”，并增加失败/未知结果回归。
- `scripts/worker-key-readiness-cutover.mjs`：新增纯校验函数，验证原只读控制面、Worker仅密钥变化、新密钥签名的固定自检及6项独立断言后，返回控制面密钥与ready编号的成套期望补丁。只有`summary`可作安全输出，`patch`含密钥及原环境，禁止打印。没有CLI或网络执行入口；它不证明调用次数、预算授权、旧任务静止或新实例已生效，不会提交自检、改云配置、让旧签名继续启动任务或将旧回执重签为新证据。
- 全量部署工作流会更新代码、规格和环境；不能拿它代替只改已批准凭证的专用操作。

### Worker切换前的真实证据门

只读页面、`/health.active=0`、`dirty=false`或两次相同版本号均不足以证明系统静止：OSS消费路径不一定计入HTTP执行计数，持久化队列也可能仍在等待远端写入。必须先停止新生产者与有效后台委托，等待现有持久化链完成，再从权威后端读取完整、稳定且新鲜的元数据；结合队列job/result/cancel和FC在途证据排除待提交、执行、取消、回收以及孤儿任务。

已终结任务中保留的UNKNOWN费用不是新的运行任务，账本继续保留，不能为了“清空队列”而清零。仍有未知提交或未收回旧结果时，先用旧密钥对账原请求，不重提。已验签并持久化的终态结果继续通过原记录读取，合成回归验证该路径不再访问新密钥runner；实际云端历史兼容仍须验收。如果要求换密后首次读取未入库旧签名回执，现有单密钥实现不满足，必须先收证或另行设计严格历史访问方案。

## 5. 失败处理与停点

- 写请求超时/断网：按原请求和目标配置回读，不重复发送。付费结果未知计入原上限，不自动再跑模型或 Spark。
- RDS 密码已改而配置同步失败：保持维护关闭业务，安全修正唯一连接配置；不得自动把数据库改回可能已暴露的旧密码。
- Worker 已切换而新自检失败：停止新计算，保存原结果；不重签历史结果、复用旧就绪或静默回退到旧密钥。额外自检需新的执行额度。
- 用户改密持久化失败：返回未确认/失败，不签发成功 Cookie；先对账原用户与会话状态，再让用户判断是否需要重试。
- 密钥轮换失败不得伪称原代码回滚即可恢复全部状态；凭证是独立变更，应保持只读并明确哪一端仍未验证。
- 两次同类失败且无新证据即换诊断假设；没有安全可执行替代路径时停止外部写入，而非扩大权限或制造新工具。

预算必须包含数据库唤醒、一次固定 Spark 自检、OSS 与控制面请求；如批准模型调用还需单列价格/Token 上限。每次收费前核验当月完整账单与跨月未结算预留，不能凭旧月份小额账单认定本月尚有预算。维护准备本身不授权付费。
