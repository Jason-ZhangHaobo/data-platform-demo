# 持仓分布 Agent：本机代码阶段

用户在独立Data Agent选择已登记的资产类别或行业分布，用自然语言描述需求。Agent在同一次模型响应中返回六列理解和SQL；执行后按客户/交易日/分类复合键、市值、证券数量及不含现金的六位占比核验，失败可据当前版本的场景反馈修正。

元数据在`output-contract-metadata.json`，独立预期在`output-contracts.json`。两者由Node/Python组成可信注册表；浏览器只导入元数据，模型只获得表结构、参数、口径和受控反馈。禁止向模型传案例行、独立金额/比例答案或将参考SQL偷偷作为标准答案输入。用户自己选择的当前代码仍属于本次输入。

理解绑定原需求摘要、登记契约、粒度、全部字段及必需来源、约束、模型尝试和代码版本。分布强制要求此提案；缺失、错误粒度/约束或需要澄清时，在Spark之前停止。结构通过不代表含义正确，实际数据仍由独立断言检查。原客户五列协议、上下文与固定20例目录不迁移。

普通本机循环从同一任务、同一当前SQL摘要的前一失败运行构建反馈；显式修正须引用已核验的原失败来源。反馈包含失败场景、登记字段和错误分类；字段血缘仍只描述静态依赖。替身、未知结果、读取恢复和真实计算分开记录，刷新不重提模型或Spark。

界面展示六列输出、分类粒度和明确分母；核验按“分组”计数。旧客户级差异表不套到复合键结果。当前可完成需求、代码、调试和代码核验；本机八文件/演练/文件审阅已继续接入，见[分布交付](distribution-delivery-review.md)；发布批准与实际发布仍由服务端拒绝。Python、远程配置和公网目录不开放新分布，不因源码合并改变云端范围。

验证入口：

- `test/v2/distribution-agent.test.mjs`：两种提示、预期隐私、六列/粒度/约束反例、结果复核与需求冻结。
- `test/v2/distribution-agent-api.test.mjs`：缺失/澄清先停、原请求恢复、同任务合成修正反馈。
- `test/v2/agent-requirement-understanding.test.mjs`：六列、复合粒度、分母与精度展示。

实际本机验收保留原行业分布失败运行，并验证引用其来源的修正任务。随后以资产类别分布的新任务，真实Spark先失败、同任务取得反馈并修改SQL、再次真实Spark五场景通过；需求和代码均绑定第二次尝试，原两任务不变。上游是合成模型响应，首次替身传输断言失败保留在历史，不能将后续通过倒填到原任务。上述结果不能算真实模型自主完成，也不计当前20例或公网通过。完整CI、界面和源码状态见[唯一续接清单](goal-mode-next.md)。
