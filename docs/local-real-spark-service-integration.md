# 本机真实Spark到DAPI／XAPI集成验收

日期：2026-11-06。范围：隔离平台库、业务查询库和产物目录，虚构证券客户资产数据。代码是手工保存的参考SQL，审阅／批准由合成测试执行者完成；不是本人业务批准，不计新模型或Agent自主E2E，不能用于替代公网验收。

## 实际链路与结果

| 环节 | 实际操作及核验 |
|---|---|
| 手工开发 | 通过现有版本API保存MANUAL代码，真实Spark3.5.9运行全品类持仓＋现金口径，五套独立回归通过 |
| 文件交付 | 从实际成功运行生成八文件包，核对清单／文件摘要及源版本／运行；按文件重新执行主SQL和测试SQL |
| 测试审阅 | 四项确认、包摘要及演练绑定；审阅说明明确写入“合成测试审阅”，保持本机范围 |
| 本机调度 | 真实墙上时钟触发两个冻结样例批次，串行执行，主SQL、测试SQL及回归再次通过；这是同一业务日的两个测试批次 |
| 监控 | 两批分别有同包成功事件，事件时间不早于完成时间；发布健康、无开放告警，版本／包／批次关联一致 |
| 数据服务 | 两个DAPI读取实际发布结果快照，XAPI固定组合持仓和现金版本；独立HTTP查询核对客户、金额及证券数量 |
| 消费约束 | 全量及两页查询成功；未授权DAPI拒绝，应用撤销后再次访问拒绝，三条成功调用记录可回读 |
| 报表消费 | 续接同一实际发布结果，物化客户级快照并实际聚合五组件；独立金额、客户粒度及CSV对应关系通过，不生成缺失类别／行业分布，详见[报表字段范围](report-field-coverage.md) |
| 独立复核 | 重新打开落盘库及原文件，检查MANUAL来源、包／演练／审阅／批准／批次／事件关系、快照完整性和应用已撤销；没有Agent任务记录或完整令牌存储 |

共4个真实Spark进程：代码运行、文件演练及两个计时批次，最大并发1。没有模型调用或云资源变更。内部HTTP测试客户端不代表外部系统、公网或多网络验收。

## 界面验收

既有数据服务工作台实际展示2个DAPI、1个XAPI、固定子版本、Spark3.5.9来源、三条成功调用和已撤销应用。测试／新版本／新凭证写操作关闭。查看前后，版本、运行、发布批次、调用及应用数量均未变化，没有重新计算或调用接口。

初次CLI请求遗漏客户端校验头，被403拒绝且零写入／计算；核对后沿用原请求编号续接。只读预览初次遗漏目录使用的发布批次读取路径，被代理拒绝；补齐这一只读路径后通过，全部失败保留，未重新执行Spark。独立核验区分了令牌提示前缀与完整令牌，没有输出或保留明文令牌。

## 同一财富管理批次的直接 DAPI 验收

从保存库复制原本机 Spark 发布、报表和查询快照。在隔离副本中，为原持仓与现金 DAPI 各签发一个仅授权本接口的测试应用。使用 `GET /api/v2/open/dapis/{slug}?page=1&pageSize=1` 和第 2 页读取原固定版本。四页均与独立证券样例及原报表两位客户的金额和证券数量对应。无凭证请求、访问另一 DAPI 或 XAPI、撤销后再次使用凭证，均按相应权限拒绝。重复应用请求只回原应用编号，完整令牌没有持久保存。

关闭 HTTP 服务后用只读 SQLite 重新核对四条新 DAPI 调用和三条原 XAPI 调用。原记录及发布、报表和查询快照字节保持一致。较早的客户资产快照即使没有分布快照表也可直接只读核验，缺行或摘要不符仍会拒绝。补充调用只来自隔离副本，保留原 XAPI 历史、手工开发与测试审阅归因。本轮没有新增模型、Spark、发布或公网调用。

### 从原报表回看授权消费

在本机「数据报表」打开客户资产报表，展开「回看报表授权消费」。有多个成功运行时，可以选择原运行。读取只沿该运行的报表版本、快照和原发布批次。系统重新核对手工代码归因、报表组件、DAPI 快照、XAPI 固定子版本、应用授权时序及分页结果摘要。完整通过需要同一 XAPI 的全部固定子版本均有各自完整的直接 DAPI 分页。页面同时展示回执和撤销状态。

| 入口 | 读取方式 |
| --- | --- |
| API | `GET /api/v2/reports/{reportId}/wealth-consumption?run_id={runId}` |
| CLI | `shuduo reports wealth-consumption --id REPORT_ID --run-id RUN_ID` |
| MCP | `report_wealth_consumption`，输入 `reportId` 和 `runId` |

未保存完整分页时显示待核对，损坏回执单独计入未确认。每次最多核对最近 100 条同批成功调用。其他批次及最新版的回执不会补齐所选运行。该功能只读本机已保存证据，使用原开发工程师的归属和报表快照，返回回执摘要及授权状态。

在本机隔离副本中，原报表运行显示四条直接 DAPI 和三条 XAPI 回执，切换到另一成功发布批次的报表运行显示待核对。浏览器、API、CLI 和 MCP 的结果一致，关闭服务后重新读取仍指向原批次。回看未创建新应用或调用日志。

### 离线复核已保存的财富管理链路

用已保存的三份 SQLite 文件和原编号运行。为每个分页调用重复传入相应选项，提供两个 DAPI 固定子版本及 XAPI 的完整分页。报表、批次及包摘要均须明确指定。

```sh
node scripts/verify-saved-wealth-lifecycle.mjs \
  --metadata /private/metadata.sqlite --business-snapshots /private/business.sqlite \
  --report-snapshots /private/reports.sqlite --release-id RELEASE_ID --package-digest SHA256 \
  --batch-id ORIGINAL_BATCH_ID --report-id REPORT_ID --run-id ORIGINAL_REPORT_RUN_ID \
  --dapi-call-id HOLDINGS_PAGE_ONE --dapi-call-id HOLDINGS_PAGE_TWO \
  --dapi-call-id CASH_PAGE_ONE --dapi-call-id CASH_PAGE_TWO \
  --xapi-call-id ORIGINAL_XAPI_PAGE_ONE --xapi-call-id ORIGINAL_XAPI_PAGE_TWO
```

通过时返回 `LOCAL_SAVED_EVIDENCE`、同版证据摘要及手工开发归因。核对范围包括原开发结果、八文件、T+1 业务日、演练、测试审阅、审批、原定时批次和监控。报表版本及快照、两条 DAPI 和 XAPI 的授权与撤销记录均绑定所选批次。命令只读文件，使用独立证券样例核对保存结果，输出不含客户明细或凭证。

隔离样例实测复核两个实际 Spark 批次、原报表两行、四条 DAPI 和三条 XAPI 回执。重排调用编号得到相同结果。错批次、错包、缺页、重复或错类调用、改动时序、报表结果、业务快照或撤销状态均被拒绝。该复核证明本机保存链路的证据一致，人工审阅身份与公网业务仍由各自验收确认。

## 可复用方法

复用既有API顺序：`/revisions` → `/runs` → `/delivery/packages` → 包的`verify` → 明确测试审阅和批准 → `/releases` → `/release/runs`及`/monitoring/overview` → DAPI／XAPI测试发布 → 临时应用查询与撤销。每次写入先保存请求键和正文摘要，结果未知先回查原记录，不重建案例。

真实业务必须由工程师审阅确切版本，不能照搬自动化测试的批准动作。真实模型、当前v3 20例、新口径／云恢复、外部客户端、正式公网和经典模块缺口仍按[完整目标清单](goal-acceptance-audit.md)分别验收。
