# 独立手工发布来源的服务 Agent 上下文与持久规划

更新：2026-11-10。代码与本机协议、模型适配层替身、签名事件及完整页面验收通过；尚未调用真实模型或部署云端，不计当前v3自主E2E。

## 1 背景

独立手工成果已有真实交付资源和接口消费，但专用服务Agent仍要求上游Agent任务。工程师应能把已核验的手工发布交给服务Agent规划DAPI／XAPI，保持真实来源，而不创建假的开发Agent。

## 2 价值

继续复用同一持久规划器、模型适配层、预算、租约、事件和提案校验。从确切手工批次读取安全上下文，保存需求后明确开始规划，再审阅指定摘要创建草稿。原记录、固定版本、未知结果和用量都可恢复。

## 3 问题

- 同一UUID也不能混用taskId与manualDeliveryTaskId；旧窗口不能隐含扩展到新来源。
- 模型不能取得业务行、金额答案、原SQL、令牌或内部租约，也不能虚构发布批次或DAPI版本。
- 创建回执丢失、模型结果未知、服务重开或来源变化时，不能换任务重试或抹掉已发生用量。
- 模型成功不是服务发布：确认须绑定完整提案摘要，后续测试、发布及调用凭证仍有独立权限门。

## 4 需求与验收

### 来源与上下文

规划sourceBinding仍恰好四项：二选一的taskId或manualDeliveryTaskId，加packageDigest、releaseId、sourceReleaseRunId。两类ID互斥；部分绑定、混用、未知字段及相同UUID替代均拒绝。

私有来源解析复用服务管理器的原交付、演练、审阅／批准、两个正确批次及快照校验，核对本人和同项目。上下文返回MANUAL／ENGINEER_AUTHORED，批次使用manualDeliveryTaskId，不含sourceAgentTaskId；旧Agent和人工接管语义保留。

上下文只读给出登记口径、字段含义、一个确切批次和至多100个同源已发布DAPI固定版本。模型适配层再投影需求、口径和可用资源引用；不发送行、金额预期、原SQL、凭证、内部租约或用户身份。读取上下文不构成执行授权。

### 规划、确认与恢复

保存需求 → 原编号读取／恢复 → 明确开始或登记原事件 → 受限模型步骤 → 校验DAPI／XAPI提案 → 人工审阅proposalHash → 确认原草稿。

新建service_agent_plan是真实的服务规划任务，不是伪造上游开发Agent。sourceBinding、ENGINEER_AUTHORED、冻结口径与版本保持人工来源，agentIndependentE2E=false；原手工代码／运行／发布不变。

DAPI只能选择原批次及允许字段；XAPI只能固定当前同源已发布DAPI版本。提案、固定版本或来源不符，不能创建草稿。确认只接受当前完整proposalHash，幂等恢复同一个草稿，不自动测试、发布或发凭证。

创建未知先查询原requestId；重开后保留同一任务。模型未知不自动重试，尝试和保守Token预留保留；到期阻断新模型步骤，原记录可读和取消。模型返回后来源变化时拒绝方案，已经确认的用量仍保留。

### 权限与事件

复用既有PRIVATE_SERVICE_AGENT_PROFILE的指定账号、来源、最多两小时、最多三个任务／模型步骤、Token与费用门，以及完整月账单／未结算预留检查。sourceBinding的新身份进入边界指纹，同一窗口不能替换来源或清零预算。

公网业务入口继续只读；模型推进只走受保护私有转发／已授权事件。旧执行窗口不会因新语法被恢复。源码不自动配置密钥、触发器、IAM或资源；实际模型和云端验收需有效授权及账单。

原有OSS事件驱动识别新来源边界，重复事件不重复模型调用。显式推进界面不冒充已安装事件后台；事件与真实云恢复分别计证据。

### GUI／API／CLI／MCP

既有 `/data-services/agent/context`、`plans`、`requests/:requestId`及计划的advance／apply／cancel接口不变，统一接受严格绑定。查询使用manual_delivery_task_id替代agent_task_id，另三项必须齐全。

CLI的services plan／plans／plan-context支持 `--manual-delivery-task-id ID --package-digest SHA256 --release-id ID --source-run-id ID`；旧--task-id保留且互斥。MCP的service_agent_context、plan_create和plan_list采用同一二选一schema，不提供执行者覆盖。

完整页面沿用“保存任务→模型规划→确认草稿”，显示已登记股票／现金口径、固定候选、当前阶段、尝试／保守预留和草稿状态。回执未知保留输入和原编号；刷新只读恢复原任务。未审阅前确认按钮关闭，不把生成方案当服务发布。

### 验收

完整本机CI1739项：1738通过、0失败、1既有跳过；类型、构建和入口体积门通过。覆盖无上游Agent、同UUID混用／另一账号、严格回执、DAPI／XAPI固定版本、提案摘要、模型前后来源变化、已发生用量、未知结果／重开／到期、取消、CLI／MCP、生产适配层隐私及事件幂等，旧来源回归通过。

完整主页面用生产模型适配层配本机fetch替身：一个保存请求丢失回执后恢复原任务，明确推进一次、人工确认摘要，创建一个真实SQLite草稿。刷新保持同一任务／草稿和700个合成用量Token，原代码和运行逐项不变，零上游Agent／应用记录，没有测试或发布。提示词白名单核验通过；所有临时进程已停止。

模型和上游签名回执都是替身；这些证据不能证明真实模型完成率、云恢复、外部消费或当前v3自主完成。

## 5 Demo

中国证券财富场景：根据手工发布的“股票持仓＋可用现金（非客户全资产）”结果规划客户查询。Agent引用原批次，提出client_id和组合口径字段的DAPI；工程师审阅摘要后得到未发布草稿。真实环境后续测试、发布与授权仍沿同一来源逐项验收。
