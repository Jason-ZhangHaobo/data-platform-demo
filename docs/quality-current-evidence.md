# 质量健康与当前数据证据

## 行为

原检测的通过／失败属于当时的输入，不能直接作为新批次健康。质量规则详情、总览、API、CLI、MCP和Agent聚合上下文共用本次读取的证据判定：

| 当前情况 | 本次读取状态 | 原记录 |
| --- | --- | --- |
| 规则版本、数据版本、资产摘要、实际行摘要均匹配 | 沿用原有效检测结论 | 保留 |
| 新批次，即使内容完全相同 | STALE，当前数据待检测 | 保留原通过／失败 |
| 同批内容或实际行摘要变化 | STALE，当前数据待检测 | 保留 |
| 来源不可读、原执行／计数不足、旧回执缺行摘要 | UNCONFIRMED，未计健康 | 保留 |
| 当前规则版本变化 | PENDING，待检测当前版本 | 保留旧版本结果 |
| 时效通过证据到期 | STALE，需显式重新检测 | 原通过仍是历史通过 |
| 实际检测为空 | NO_DATA，无通过率，不作为恢复依据 | 保留 |

新实际运行保存`inputRowsHash`和`evaluatedAt`。`FRESHNESS_SECONDS`非空通过额外保存`validUntil`，按原数据最早时间＋允许时效计算，不按“检测时间＋时效”延长。边界时点仍有效，超过边界才到期。旧时效回执缺有效期时不能确认当前健康。

核对来源可能读取当前实际行重算摘要，但不调用规则求值、不新建检测运行、不重新计算通过率。来源恢复可核对且仍是同一有效输入时，可再次显示原有结论；这不是新检测，也不会修改告警。当前输入改变后，必须显式运行才取得该输入的质量结论。

## 界面与恢复

“数据质量”显示“本次读取状态”，原检测结论与原／当前批次分开。来源区可展开对照完整摘要；“重读当前数据状态”只读，“实际检测当前表”才检测。页面不是实时订阅，停留期间的数据变化以重读为准；时效证据有效期同时显示北京时间。

旧告警的“原批次已恢复”不能表示新数据已通过。读取不会新建告警、解除告警或改写原检测；真实当前失败／修复继续走原检测和恢复流程。历史复检继续`HISTORY_ONLY`，不能替代当前依据。

## 接口与Agent

既有质量详情／列表／总览接口增加`sourceFreshness`，包括状态、原因、`lastDetected`和可读取时的`current`（数据版本、摘要、实际行摘要和行数），不返回业务行。`health`是本次读取的投影；存储中的规则和运行历史不因读取修改。总览增加`counts.stale`、`counts.unconfirmed`，旧通过不计当前健康。

Agent上下文的`latestRun`按规则保存的`lastRunId`取得，不能取最近一条历史复检。`currentInputStatus`随聚合摘要传入模型；提示明确失配／未确认时不能宣称当前数据通过。模型仍只生成规则草稿，真实模型理解效果另行验收。本项没有调用真实模型。

## 验收与边界

`test/v2/quality-current-evidence.test.mjs`覆盖真实CSV／SQLite换批、相同内容的新批次、缓存元数据与实际行失配、来源中断与恢复、旧证据不足、时效边界、当前告警恢复、历史复检及Agent摘要，以及API／CLI／MCP一致性。原质量空表、缺字段、版本与归档检测继续回归。

实际浏览器已验证旧通过→待检测→实际失败→新数据待检测→实际通过与恢复；读失败显示未确认，读取及刷新没有调用规则求值。最终界面只读复用已保存结果，桌面和窄屏检查分别留证。模型／Spark／云端及正式20例不由本项替代；当前是小数据本机验证，大规模来源核对性能须另行测量。
