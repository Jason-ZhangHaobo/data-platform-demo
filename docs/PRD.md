# 数栈 · 离线同步中心 MVP 产品需求文档

## 1. 产品目标

为数据中台产品经理提供一套可公开演示、可反复迭代的全栈项目，用于验证以下端到端能力：

1. 将需求和验收标准转化为前后端代码。
2. 通过 GitHub 分支和 Pull Request 管理变更。
3. 自动执行代码检查、测试和构建。
4. 自动部署测试环境。
5. 经过人工审批后部署模拟生产环境。

本项目只使用虚构数据，不连接公司系统。

## 1.1 默认业务上下文

本项目后续新增的业务用例默认围绕中国证券行业展开，优先覆盖券商经纪、财富管理、资产管理、基金、托管清算、行情参考、风险合规和审计等数据场景。当前已完成的通用 Demo 数据保留用于兼容既有验收；新需求、代码和测试数据应遵循[中国证券行业业务上下文](business-context.md)。

所有机构、客户、账户、证券代码、订单、成交、持仓、估值和监管报送内容均为虚构。项目只做学习演示和流程复刻，不执行真实交易、资金操作或正式监管报送。

## 2. 第一版范围

### 2.1 包含

- 查看离线同步任务列表与运行概览。
- 新建、编辑、启用和停用同步任务。
- 配置虚构的源端、目标端、同步模式、调度周期和负责人。
- 手动触发模拟运行或停止运行中的任务。
- 查看模拟读取量、写入量、状态和运行日志。
- 后端真实保存任务配置和运行记录。

### 2.2 不包含

- 连接真实数据库或实际搬运数据。
- 用户登录、组织权限和审批流。
- 数据开发、数据脱敏、数据资产目录的具体功能。
- Data Agent 对话、任务规划、技能路由和自动执行。
- 自定义域名、ICP备案和真实生产流量。

### 2.3 数据脱敏 MVP（当前迭代）

- 面向投资者手机号、投资者标识、证券账户、银行卡号和姓名等敏感字段配置脱敏规则。
- 支持规则启用/停用和虚构样例预览，预览结果写入脱敏预览记录。
- 只做规则与预览，不连接真实客户数据，不执行生产批量脱敏。
- 规则策略必须说明保留范围；默认不允许将真实证件号、资金账号或银行卡号写入 Demo。

### 2.4 数据资产目录 MVP（当前迭代）

- 登记证券主数据、投资者账户、订单成交、持仓快照和基金净值等虚构资产。
- 展示资产类型、数据分层、业务域、负责人、标签、敏感等级和更新时间。
- 支持按资产名称、物理表名、字段、业务域和标签搜索，并查看字段级元数据与上游血缘摘要。
- 当前为只读目录和检索上下文，不包含生产资产变更、权限授予或真实血缘扫描。

### 2.5 账号、权限与审计 MVP（当前迭代）

- 提供虚构证券行业用户、角色和权限集合，角色包含最高可访问敏感等级。
- 支持检查用户是否能执行资产读取、脱敏预览或审计查询等动作。
- 每次允许或拒绝的访问检查都写入审计记录，包含操作者、动作、资源、敏感等级、结果和原因。
- 当前为演示身份和内存/OSS 状态，不接入公司账号、阿里云 RAM 或真实生产权限。

### 2.6 Data Agent Lite（当前迭代）

- 使用规则编排识别数据同步、数据开发、数据脱敏和数据资产检索意图。
- 先生成执行步骤、待澄清问题、风险与草稿，不直接写入资源。
- 用户确认后才创建 Demo 任务、脱敏规则、开发草稿或返回资产检索结果。
- 每次计划生成和确认执行都写入审计记录；当前不调用外部大模型，不使用 API Key。

### 2.7 数据质量与运维 MVP（当前迭代）

- 围绕财富顾问持仓分析提供空值、唯一性、行数和 T+1 时效规则。
- 支持质量规则启停、模拟运行、得分、提醒和检查历史。
- 当前使用虚构数据模拟，不接真实生产质量引擎和告警通道。

### 2.8 语义上下文 MVP（当前迭代）

- 提供客户总资产、持仓市值、证券数量、资产类别分布和行业分布的指标口径。
- 记录来源资产、字段、粒度、计算公式、业务说明和使用限制。
- Data Agent 生成财富顾问持仓分析计划时必须返回语义证据，不允许只凭自然语言猜测口径。

### 2.9 Data Agent 评测 MVP（当前迭代）

- 固化同步、资产检索、脱敏、财富顾问持仓分析和模糊请求五类评测用例。
- 输出意图准确率、计划字段完整性和确认安全门结果。
- 评测结果写入历史，作为接入真实模型前的回归基线。

## 3. 核心业务规则

1. 未启用的任务不能运行。
2. 运行中的任务不能重复运行，也不能直接停用。
3. 每次运行必须产生独立记录。
4. 模拟运行完成后，任务与运行记录都更新为成功。
5. 停止运行后，任务和对应记录都更新为已停止。

## 4. 验收标准

- 用户可以创建一条合法任务并立即在列表中看到它。
- 缺少任务名称、源端或目标端时，后端拒绝保存并返回清晰错误。
- 用户可以运行已启用任务，并在数秒内看到成功结果与模拟行数。
- 用户不能运行已停用任务。
- 页面在电脑和手机宽度下均可使用。
- `npm run ci` 全部通过。
- GitHub PR 必须通过 CI 后才允许合并。
- 测试环境自动发布；模拟生产环境必须人工批准。

## 5. 产品长期定位

项目长期形态不是单一“离线同步工具”，而是由数据中台业务模块和跨模块 Data Agent 组成的平台：

- 业务模块负责提供稳定、可审核的确定性能力。
- Data Agent 负责理解自然语言、补充上下文、规划步骤，并调用各模块能力。
- Agent 的写入、发布、脱敏、权限调整等高风险动作必须经过人工确认并留下审计记录。

Data Agent 对标阿里云 DataWorks Data Agent 的产品能力，但不复制其代码和界面。重点对标自然语言交互、多步计划、模块技能路由、上下文引用、执行反馈、ChatBI 问数和知识库语义能力。

## 6. 后续迭代路线

1. 接入 CSV 到 MySQL 的真实小规模同步。
2. 新增数据开发任务与 SQL 模拟执行。
3. 新增数据脱敏规则和审批记录。
4. 新增数据资产目录、字段信息和负责人。
5. 增加账号、角色、审计日志和真正的环境权限隔离。
6. 增加 Data Agent Lite：用自然语言路由同步、开发、脱敏和资产检索，展示计划后确认执行。
7. 将数据开发、脱敏、资产目录和运维能力注册为 Agent Skills。
8. 增加自然语言问数、可视化分析与结论摘要能力。
9. 增加统一知识库和语义模型，沉淀表结构、指标口径、业务资料与团队规则。
10. 增加 IM 频道和周期巡检，让 Data Agent 主动服务各功能模块。
