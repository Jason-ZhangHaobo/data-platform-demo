# 数栈 · 离线同步中心 MVP 产品需求文档

## 1. 产品目标

为数据中台产品经理提供一套可公开演示、可反复迭代的全栈项目，用于验证以下端到端能力：

1. 将需求和验收标准转化为前后端代码。
2. 通过 GitHub 分支和 Pull Request 管理变更。
3. 自动执行代码检查、测试和构建。
4. 自动部署测试环境。
5. 经过人工审批后部署模拟生产环境。

本项目只使用虚构数据，不连接公司系统。

## 2. 第一版范围

### 2.1 包含

- 查看离线同步任务列表与运行概览。
- 新建、编辑、启用和停用同步任务。
- 配置虚构的源端、目标端、同步模式、调度周期和负责人。
- 手动触发模拟运行或停止运行中的任务。
- 查看模拟读取量、写入量、状态和运行日志。
- 后端真实保存任务配置和运行记录。

### 2.2 不包含

- 连接真实数据库或实际搬运数据。
- 用户登录、组织权限和审批流。
- 数据开发、数据脱敏、数据资产目录的具体功能。
- 自定义域名、ICP备案和真实生产流量。

## 3. 核心业务规则

1. 未启用的任务不能运行。
2. 运行中的任务不能重复运行，也不能直接停用。
3. 每次运行必须产生独立记录。
4. 模拟运行完成后，任务与运行记录都更新为成功。
5. 停止运行后，任务和对应记录都更新为已停止。

## 4. 验收标准

- 用户可以创建一条合法任务并立即在列表中看到它。
- 缺少任务名称、源端或目标端时，后端拒绝保存并返回清晰错误。
- 用户可以运行已启用任务，并在数秒内看到成功结果与模拟行数。
- 用户不能运行已停用任务。
- 页面在电脑和手机宽度下均可使用。
- `npm run ci` 全部通过。
- GitHub PR 必须通过 CI 后才允许合并。
- 测试环境自动发布；模拟生产环境必须人工批准。

## 5. 后续迭代路线

1. 接入 CSV 到 MySQL 的真实小规模同步。
2. 新增数据开发任务与 SQL 模拟执行。
3. 新增数据脱敏规则和审批记录。
4. 新增数据资产目录、字段信息和负责人。
5. 增加账号、角色、审计日志和真正的环境权限隔离。
