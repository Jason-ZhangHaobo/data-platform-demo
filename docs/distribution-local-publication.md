# 分布本机测试发布、监控与回滚

文件审阅只是检查文件。分布测试发布另需明确确认此包、成功演练、元数据摘要、计时计划及两个冻结虚构证券批次。批准内容存入`distributionConsent`，发布参数必须完全一致；同一批准的并发客户端只能生成一个发布和两批，响应未知时查询同一版本。

每批领取、持久化及目录恢复后，在实际计算前重核来源。需求/代码/契约变化会阻断新计算并保留失败证据。停止绑定发布ID及包摘要，取消后不再提交新计算；正在执行的晚到结果不能覆写取消，主动停止不计失败告警。

同一分布契约的发布替换同族版本，资产类别与行业互不覆盖，旧客户资产保留原默认范围。回滚只选择同族健康历史版本，另确认目标包与冻结数据范围；状态、回滚记录和两条恢复批次在同一事务保存。响应丢失按原请求ID恢复，重复请求不能增加恢复批次。历史批次保留，当前窗口单独统计；两条新恢复批次成功后才解除原版本失败告警。

独立Agent页面提供确切确认、批次编号、计划/触发状态、告警、停止和历史目标回滚。恢复到其他任务版本时提供原目标任务入口，不把旧代码结果移到当前任务。CLI批准/发布可用`--distribution-consent`读取已审阅JSON，回滚同样读取确认文件并用`--request-id`保留原编号；MCP提供闭合确认结构和`release_cancel`。工具调用仍须取得明确确认，不自动填入发布批准。

范围仅本机墙钟调度器和虚构数据：不创建云资源、不改变公网入口、不调用新模型。远程分布/Python仍关闭；DAPI/XAPI多行投影未适配，页面明确保留证据并关闭接管，不回退旧客户五列接口。

验证入口：

- `test/v2/distribution-publication-api.test.mjs`：确认与参数绑定、并发单发布、漂移/停止阻断、回滚事务回退/幂等、当前恢复窗口与告警、停止竞态。
- `test/v2/distribution-publication-ui.test.mjs`：冻结两批确认、只读和原目标入口，渲染无执行。
- `test/v2/distribution-publication-clients.test.mjs`：CLI/MCP同一确认/停止/回滚/请求编号，无真实运输。

实际本机验收复用已演练确切包，重新完成测试发布确认：一个本机批准、一个发布、两条真实墙钟Spark批次，主SQL/测试SQL/五场景均通过，健康达到通过，新模型请求0。人为损坏发布响应后界面找回同一发布，未重复建批。原上游模型为替身，批准为本机虚构验收操作，不是用户生产批准，不计真实模型或当前20例完整自主率。

首次补验时，两批先于浏览器关闭完成。原观察断言保留为失败，业务结果单独记录。停止和回滚的证据来自合成执行器测试。

## 关闭页面后的本机调度实测

复用同一个已演练分布包，在隔离库用测试审批创建一次本机发布。两批计划相隔 75 秒。第一批完成独立核验后，刷新原 Agent 的发布监控，确认第二批仍在等待调度。关闭测试标签并确认已移除，随后从 SQLite 只读记录第二批仍为 `SCHEDULED`、调度器尚未触发的状态。

关页确认约 28 秒后，第二批由同一发布的墙上时钟调度器触发。关页至完成期间服务收到 0 个 HTTP 请求。两批均由 Spark 3.5.9 实际执行，原主 SQL、测试 SQL、三条分布结果及五个独立回归场景通过。两条监控事件对应同一发布和交付包，发布健康且无开放告警。关闭服务后，重新只读打开 SQLite 核对原编号、关页及触发时序和独立结果。

本次复验使用虚构数据、原模型替身归因及本机测试审批。证据覆盖浏览器关闭后本机调度继续执行。服务实例重启和正式云后台分别验收。最新证据和缺口见[唯一续接清单](goal-mode-next.md)。
