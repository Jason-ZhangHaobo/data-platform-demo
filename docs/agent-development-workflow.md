# Agent开发、核验与交付

## 有界事件后台：代码开发阶段

用户可显式委托一个持久Spark SQL任务的云后台（`background=true`）；读取状态、停止后续推进与人工接管共用API、CLI、MCP。GUI只观察状态，不承担后台触发责任。当前许可默认15分钟/最多20事件，SQL开发结束后停止，不自动审批或上线。许可状态包括ACTIVE、PAUSED、NEEDS_CONFIRMATION、EXPIRED、CANCELLED、COMPLETED；状态必须与任务实际成功/失败分别展示。

协议、权限、出站对象恢复与默认关闭门见[任务持久化：事件后台](durable-agent-recovery.md)。运行配置显示可用也不能代替真实云验收；首轮先在获准范围关闭浏览器/本机驱动，验证实际模型、Spark回执、后端重建、重复通知及停止行为。

## 独立任务证据导航

核验读取有明确的读取中、成功、失败状态。读取失败不清空已有报告或提交新计算；提供“重新读取核验记录”恢复入口。读取未确认时，旧报告只作参考，不能作为生成交付和审阅发布的依据。代码或批次变化后，检查项显示“历史记录”而非当前绿色通过。发布卡片与导航共用证据门槛：仅有 HEALTHY 标签、缺少计划批次或对应监控事件，均不得宣称监控验收通过；回滚和停止保留明确状态。

开发工作台以原任务编号串起需求与口径、代码调试、独立核验、调度部署文件、审阅发布、监控及DAPI/XAPI消费。阶段卡片可定位原代码、核验报告、文件和发布记录；“下一步”来自第一个未完成阶段，而非任务总状态。

- 核验必须绑定同一任务、当前代码版本和正在查看的运行。编辑未保存、切换到历史批次或缺少独立断言时，不继承旧报告结论。
- 文件通过必须绑定源版本、源运行、包摘要、演练编号，并具备实际执行、测试SQL与全部五个证券场景断言。仅文件生成不显示演练通过。
- 发布记录只有包与源版本对应当前交付，且实际调度批次成功才显示发布证据通过；历史记录仍保留，但不能替新版本证明上线。
- 健康必须核对全部计划批次、独立批次编号、调度触发、对应包的成功监控事件与未解除告警。健康标签单独不足以通过。
- 同任务接口接管带入原任务来源；不自动新建服务、凭证或调用。未保存代码和未发送需求阻止切换，保护输入。消费仍须独立核对授权返回值与调用日志，本视图不把打开服务页面计作消费通过。
- 工作流只选当前源版本与源运行对应的交付任务。不完整历史来源链接不能令健康服务目录整体报错，也不能被当作可选来源。

此导航是用户体验与证据投影，不是自主E2E评分。公开代码、合成界面测试、本机进程、私有云及公网验收各自记录，不能互相替代。

### 交付文件与指定版本审阅

八份交付文件按加工代码、结果断言、调度依赖、部署清单、交易日历、验证数据、源运行报告、说明展示；每份有用途说明、纯文本预览和单文件下载。缺文件或空内容明确提示，不计为完整交付；附加文件不能替代必需文件。切换包后重新选择有效文件，避免显示空白。显示包编号与完整摘要供对照，不把显示摘要视为完整性验证。

发布前集中展示范围、代码版本、源运行、演练编号和包摘要。四项人工确认必须是该范围的精确字段；不能用数量相同的其他字段替代，也不会因打开文件自动代勾。支持暂不发布；权限撤销、证据未确认、当前修改或版本变化会禁止提交或清空审阅状态。服务端仍独立核验权限、来源与批准，UI不代替授权。

交付复用同时匹配原任务、源版本和源批次；持久执行模式额外匹配代码摘要。即使SQL文本不变，新批次或新版本也不沿用旧包。同源重复请求复用原记录；前端在来源变化时更换幂等键，未知结果下保持同一来源原请求。测试覆盖HTTP入口和持久交付引擎，不把测试替身记录计为真实演练。

### 返回任务后的发布与监控恢复

`GET /api/v2/agent/tasks/:id/publication` 在本机环境按任务→交付包→发布的持久来源恢复记录；优先当前源版本与批次，没有当前版本时保留该任务历史发布供对照。返回范围仅包含该发布的批次、告警、监控事件与展示字段，不返回结果行、远程执行凭证或工作目录。私有云模式继续沿用原执行器读取和所有者校验，不因新增本机路径开放公网能力。

页面初次进入会主动读取发布记录，不依赖内存中的发布编号；刷新只读原任务，不提交新任务。读取未确认时保留历史记录、取消当前健康判断并禁止再次发布，提供独立的“刷新发布与监控”。自动读取只在有未完成批次时进行、单请求在途；错误后停止自动读取等待用户重试，终态停止轮询。发布/取消回执使旧读取失效，离开任务后迟到响应不能污染新任务。本机新监控事件保存实际包摘要；旧事件缺摘要不补造验收证据。

### 人工接管后的恢复与交付

工程师保存并运行修改后，工作台保留原 Agent 引用、人工代码版本和批次，不改写原 Agent 的状态。提交前将原运行幂等编号写入本机恢复链接（仅不透明UUID，不含SQL、凭证或批准）；响应丢失时保留编号和输入，刷新不自动计算、不用另一个同版本批次替代原请求。用户明确按原编号重试后，服务端复用同一批次；确认成功后清除待确认标记。待确认期间阻止发起另一委托或切换任务，恢复不覆盖未保存代码。

本机成功人工运行可在同页打开既有经典人工交付流程，固定源批次且只展示该批次的包。生成、演练、审阅和发布仍由用户操作并经服务端验证，不计作 Agent 自主E2E。私有云人工版本交付暂未接入，明确提示边界，不借用原 Agent 的批准。

`POST /api/v2/revisions` 支持 `Idempotency-Key`，按项目与已认证操作者隔离；相同编号/内容返回原版本，不同内容或来源返回409，不覆盖。未带编号的旧客户端仍能保存，但不提供该请求的幂等恢复保证。可选 `originAgentTaskId` 必须属于当前可操作来源且业务口径匹配；后端记录人工修改者、来源任务与时间，并明确 `agentIndependentE2E=false`，不修改原 Agent 的结果。它是来源元数据，不冒充不可篡改审计账本。

`GET /api/v2/revisions/requests/:key` 查询当前用户自己的原保存请求。返回SAVED前须确认此前待提交的元数据已持久化；持久化失败仍返回错误，不凭内存记录宣称保存成功。此查询不创建新版本/任务或执行计算。未找到返回NOT_FOUND，不暴露另一用户的版本。浏览器仅在恢复链接保留UUID，代码不写入URL；服务端未收到请求且页面已关闭时，无法从编号还原未保存代码，需重新填写后沿用原编号提交，若内容与已提交请求冲突则拒绝。恢复成功不自动继续运行；保留当前未保存修改，由工程师审阅后决定。

当前仍待私有云人工交付、浏览器交互与真实模型/Spark验收，不能据本机恢复测试声明完整人工闭环已验收。

### CLI与MCP的邀请身份

本机POSIX客户端可用`node bin/shuduo-session.mjs login --base-url API_BASE --email EMAIL --file SESSION_FILE`正常登录已有邀请账号，密码只从标准输入读取，不放参数、环境变量、聊天或MCP工具参数。文件仅存会话Cookie、CSRF及服务端有效期，不存密码；新文件0600、不得覆盖已有文件。用户须在自己的终端安全输入密码。MCP不提供收集密码的工具。

`SHUDUO_V2_SESSION_FILE`由CLI和MCP共用。每次调用检查当前用户所有的普通文件、非符号链接、权限、精确API地址/项目及有效期；非本机HTTP不能传凭证。管理写入携带CSRF，拒绝额外actor覆盖；应用Bearer查询不读取或携带管理Cookie。角色、权限和撤销仍由服务端判断，本机文件的有效期不能证明服务器登录仍有效。

`node bin/shuduo-session.mjs status --file SESSION_FILE --base-url API_BASE`只检查本机范围，不宣称服务器认证。私有FC仍须原IAM受控通道；此会话文件不能绕过云端IAM、开放公网或授予新权限。本机真实邀请API及CLI/MCP进程验证与真实私有云管理身份验收分别记录。此增量仅修改本机客户端，不为当前控制面包重新构建/上传。

### 任务消费证据（私有只读）

`GET /api/v2/data-services/task-evidence?agent_task_id=UUID&package_digest=SHA256`继承正常项目身份和任务所有者/管理员限制；应用Bearer不能代替管理身份。GUI、`shuduo services task-evidence --task-id … --package-digest …`和MCP `data_service_task_evidence`共享此合同，私有CLI/MCP的真实管理身份连接仍须独立验收。

报告只选同任务、同包的发布服务及XAPI固定子版本，最多20个服务；每个有成功调用的服务只读重查最新的一条当前版本非空结果，单次查询对照限时1秒。比较实际行数和摘要，不调用应用、写调用/限流记录、重新物化快照、发凭证或运行计算。缺失来源、配置正文漂移、实际快照损坏、历史调用摘要不符都不能通过；超出报告上限也不能标记完整阶段。

组合XAPI覆盖客户、市值、现金、总资产和证券数量且具有成功的历史授权调用，才形成此证券场景的消费证据。服务测试不算消费，别的任务/包/服务版本的调用不能借用。应用撤销后历史证据仍保留，界面显示对照时的授权状态，不保证当前可调用。报告不返回令牌、业务行或查询参数；导出须保留任务/包/版本/调用编号、对照时间与范围。

这是持久查询收据与现有快照的对照，不是外部客户端独立断言、真实云恢复或Agent自主E2E成功率。只有当前开发、交付与发布证据也绑定同一版本时，任务导航才显示消费阶段通过。

私有数据服务的进程重建、实际行完整性和报告对照见[恢复合同](private-service-recovery.md)。当前实例检查不能替代新实例验收。

Agent开发工作台围绕同一任务呈现代码、结果、逐项核验、交付文件、审阅发布和运行监控。当前核验契约为已知的虚构证券客户资产口径；新增指标需要建立新的独立预期。

## 核验与交付

`GET /api/v2/agent/tasks/:id/workflow`返回代码版本对应的结果报告、最新交付准备、文件及演练摘要和发布条件。检查代码哈希、实际Spark执行、客户唯一性与金额/数量，以及五个独立回归场景。读取不会提交模型或Spark工作。任务权限沿用代码任务所有者与项目管理员。

`POST /api/v2/agent/tasks/:id/prepare-delivery`从已通过核验的源任务生成同摘要绑定的SQL、测试SQL、DAG、部署清单、日历、输入快照与验证文件。已启用持久SQL Agent的环境使用可恢复交付模式。

`POST /api/v2/agent/deliveries/:id/advance`接受`expectedVersion`，一次推进一个持久边界。先保存文件和唯一Worker提交编号，再提交真实文件演练。未知提交结果沿用原编号恢复；GET只读取结果。演练要求主SQL、测试SQL摘要、引擎版本和五场景断言全部匹配。

`POST /api/v2/agent/deliveries/:id/cancel`先持久保存取消，再发送Worker取消标记；迟到结果不能复活任务。恢复不生成新模型任务，不复用旧审批。

GUI、`shuduo agent workflow`、`shuduo agent advance-delivery --version …`和MCP的`agent_development_workflow`、`agent_delivery_advance`共用这些API。

## 发布与监控

本机测试环境沿用现有摘要绑定审阅、批准和发布API，在同页观察调度器实际触发的批次。每次代码修改需要新的核验和交付。发布是否健康取决于运行记录，不由按钮文案决定。

本机发布使用已启用LOCAL_TIMER的测试环境；私有云使用下述默认关闭的增量。尚未验证的定时执行、上线发布和运维监控不会显示为完成。正式云发布适配和后台触发需复用现有预算、身份与恢复机制，并补真实上线后批次验收。临时预览的目标函数通过受保护环境变量`SHUDUO_PRIVATE_PREVIEW_FUNCTION`提供，源代码不硬编码实际资源标识。

## 私有云发布增量（默认关闭）

`GET/POST /api/v2/agent/tasks/:id/publication`与`POST …/publication/cancel`复用任务所有者、项目角色和CSRF。审阅绑定包摘要、真实演练与当前代码版本，确认代码、断言、交付文件和云端测试范围后创建两个冻结样例批次。创建状态为等待调度，不能当作运行或上线完成。

驱动由IAM保护的FC定时事件唤醒，不使用浏览器计时器；定时消息绑定发布编号、精确触发器名、时间、Nonce及HMAC，最多十分钟签名有效期。触发前保存唯一Worker编号和预算预留，重启后沿用原编号。重复事件、停止和迟到回执不得生成第二份计算或复活停止状态。

每次事件最多提交一个新批次。两个独立验证批次均完成且没有未解除告警后才判健康；失败留下告警，后续真实成功才能关联恢复，历史失败保留。已完成的两个批次明确标记测试完成，不暗示持续生产调度。首次云端激活需核对具体触发器、日期/频率、清理、费用和原权限边界；通用代码及本机合成测试不代表云端验收。

临时驱动关闭后，已有发布编号、完成批次和健康记录仍能只读恢复；界面不得把已完成发布重新标成“待发布”，也不能自动重启下一批次。完整发布编号用于GUI/API/CLI/MCP关联，不是认证凭证。

## 发布结果的数据服务消费（默认关闭）

私有数据服务由`V2_PRIVATE_DATA_SERVICES_ENABLED`显式开启，必须处于原IAM保护的私有边界，不创建公网触发器。`GET /api/v2/data-services/sources`仅返回本人或项目管理员可使用的已完成健康云发布批次摘要，支持`agent_task_id`过滤；不返回输入、结果行或原始日志。

首版沿用DAPI/XAPI生命周期API，保存版本、源发布批次、包摘要和真实结果快照摘要。服务管理使用正常邀请身份、项目权限、资源所有者与CSRF；请求幂等键包含操作者。发布提交审阅过的`configHash`且须有同版本成功测试。编辑新草稿不切断旧发布端点。私有XAPI固定同一源批次的子DAPI版本，拒绝混合来源；通用多数据集编排后续另扩。

`GET /api/v2/open/dapis/:slug`和`…/xapis/:slug`使用只授予指定服务的独立应用Bearer令牌，不借用工程师Cookie或模型密钥。查询只接受客户编号与分页参数，运行不可变结果快照的参数化查询，不重新调用模型或Spark。数据面快照缺失或摘要不一致时失败，不能返回预设值或伪装为空结果。应用令牌只回显一次、持久化只存哈希，可撤销；调用与限流记录持久保存，私有单并发边界下串行判断限流。

独立客户端为`scripts/query-v2-data-service.py`：从权限0600的令牌文件读取，禁用重定向，仅GET查询；stdout不含令牌。通过私有通道的调用不等于公网外部系统已接入。OpenAPI标记`PRIVATE_CLOUD_TEST`，正式域名、HTTPS与网络验收仍单独完成。

GUI在独立Agent工作台提供“发布结果→接口交付”，经典数据服务模块也可使用同一组件与API。`shuduo services sources`、MCP `data_service_sources`共用元数据读取；私有发布通过CLI `--config-hash`或MCP `configHash`绑定版本。首版界面使用明确的字段契约模板创建草稿，不冒充新的模型语义规划。

规范依据：[FC定时事件与Cron](https://help.aliyun.com/zh/functioncompute/time-triggers)。日期限定Cron在测试后仍需清理；应用的过期签名阻止窗口外派发，但不能代替移除触发器。

导出的`shuduo-delivery-package.json`可用现有`shuduo-package unpack`解包，摘要从包记录取得。它是版本产物，不能把下载行为视为上线。

“下载演练证据”导出同一代码任务的核验报告、交付任务、完整包摘要与文件清单、实际演练批次及发布条件。包编号进入文件名，便于把证据与交付文件配对。导出保留实际状态，不把尚未完成的演练或关闭的发布通道标为成功；不包含凭证、Worker提交载荷、业务结果行或原始日志。
