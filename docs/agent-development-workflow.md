# Agent开发、核验与交付

## 独立任务证据导航

开发工作台以原任务编号串起需求与口径、代码调试、独立核验、调度部署文件、审阅发布、监控及DAPI/XAPI消费。阶段卡片可定位原代码、核验报告、文件和发布记录；“下一步”来自第一个未完成阶段，而非任务总状态。

- 核验必须绑定同一任务、当前代码版本和正在查看的运行。编辑未保存、切换到历史批次或缺少独立断言时，不继承旧报告结论。
- 文件通过必须绑定源版本、源运行、包摘要、演练编号，并具备实际执行、测试SQL与全部五个证券场景断言。仅文件生成不显示演练通过。
- 发布记录只有包与源版本对应当前交付，且实际调度批次成功才显示发布证据通过；历史记录仍保留，但不能替新版本证明上线。
- 健康必须核对全部计划批次、独立批次编号、调度触发、对应包的成功监控事件与未解除告警。健康标签单独不足以通过。
- 同任务接口接管带入原任务来源；不自动新建服务、凭证或调用。未保存代码和未发送需求阻止切换，保护输入。消费仍须独立核对授权返回值与调用日志，本视图不把打开服务页面计作消费通过。
- 工作流只选当前源版本与源运行对应的交付任务。不完整历史来源链接不能令健康服务目录整体报错，也不能被当作可选来源。

此导航是用户体验与证据投影，不是自主E2E评分。公开代码、合成界面测试、本机进程、私有云及公网验收各自记录，不能互相替代。

私有数据服务的进程重建、实际行完整性和报告对照见[恢复合同](private-service-recovery.md)。当前实例检查不能替代新实例验收。

Agent开发工作台围绕同一任务呈现代码、结果、逐项核验、交付文件、审阅发布和运行监控。当前核验契约为已知的虚构证券客户资产口径；新增指标需要建立新的独立预期。

## 核验与交付

`GET /api/v2/agent/tasks/:id/workflow`返回代码版本对应的结果报告、最新交付准备、文件及演练摘要和发布条件。检查代码哈希、实际Spark执行、客户唯一性与金额/数量，以及五个独立回归场景。读取不会提交模型或Spark工作。任务权限沿用代码任务所有者与项目管理员。

`POST /api/v2/agent/tasks/:id/prepare-delivery`从已通过核验的源任务生成同摘要绑定的SQL、测试SQL、DAG、部署清单、日历、输入快照与验证文件。已启用持久SQL Agent的环境使用可恢复交付模式。

`POST /api/v2/agent/deliveries/:id/advance`接受`expectedVersion`，一次推进一个持久边界。先保存文件和唯一Worker提交编号，再提交真实文件演练。未知提交结果沿用原编号恢复；GET只读取结果。演练要求主SQL、测试SQL摘要、引擎版本和五场景断言全部匹配。

`POST /api/v2/agent/deliveries/:id/cancel`先持久保存取消，再发送Worker取消标记；迟到结果不能复活任务。恢复不生成新模型任务，不复用旧审批。

GUI、`shuduo agent workflow`、`shuduo agent advance-delivery --version …`和MCP的`agent_development_workflow`、`agent_delivery_advance`共用这些API。

## 发布与监控

本机测试环境沿用现有摘要绑定审阅、批准和发布API，在同页观察调度器实际触发的批次。每次代码修改需要新的核验和交付。发布是否健康取决于运行记录，不由按钮文案决定。

本机发布使用已启用LOCAL_TIMER的测试环境；私有云使用下述默认关闭的增量。尚未验证的定时执行、上线发布和运维监控不会显示为完成。正式云发布适配和后台触发需复用现有预算、身份与恢复机制，并补真实上线后批次验收。临时预览的目标函数通过受保护环境变量`SHUDUO_PRIVATE_PREVIEW_FUNCTION`提供，源代码不硬编码实际资源标识。

## 私有云发布增量（默认关闭）

`GET/POST /api/v2/agent/tasks/:id/publication`与`POST …/publication/cancel`复用任务所有者、项目角色和CSRF。审阅绑定包摘要、真实演练与当前代码版本，确认代码、断言、交付文件和云端测试范围后创建两个冻结样例批次。创建状态为等待调度，不能当作运行或上线完成。

驱动由IAM保护的FC定时事件唤醒，不使用浏览器计时器；定时消息绑定发布编号、精确触发器名、时间、Nonce及HMAC，最多十分钟签名有效期。触发前保存唯一Worker编号和预算预留，重启后沿用原编号。重复事件、停止和迟到回执不得生成第二份计算或复活停止状态。

每次事件最多提交一个新批次。两个独立验证批次均完成且没有未解除告警后才判健康；失败留下告警，后续真实成功才能关联恢复，历史失败保留。已完成的两个批次明确标记测试完成，不暗示持续生产调度。首次云端激活需核对具体触发器、日期/频率、清理、费用和原权限边界；通用代码及本机合成测试不代表云端验收。

临时驱动关闭后，已有发布编号、完成批次和健康记录仍能只读恢复；界面不得把已完成发布重新标成“待发布”，也不能自动重启下一批次。完整发布编号用于GUI/API/CLI/MCP关联，不是认证凭证。

## 发布结果的数据服务消费（默认关闭）

私有数据服务由`V2_PRIVATE_DATA_SERVICES_ENABLED`显式开启，必须处于原IAM保护的私有边界，不创建公网触发器。`GET /api/v2/data-services/sources`仅返回本人或项目管理员可使用的已完成健康云发布批次摘要，支持`agent_task_id`过滤；不返回输入、结果行或原始日志。

首版沿用DAPI/XAPI生命周期API，保存版本、源发布批次、包摘要和真实结果快照摘要。服务管理使用正常邀请身份、项目权限、资源所有者与CSRF；请求幂等键包含操作者。发布提交审阅过的`configHash`且须有同版本成功测试。编辑新草稿不切断旧发布端点。私有XAPI固定同一源批次的子DAPI版本，拒绝混合来源；通用多数据集编排后续另扩。

`GET /api/v2/open/dapis/:slug`和`…/xapis/:slug`使用只授予指定服务的独立应用Bearer令牌，不借用工程师Cookie或模型密钥。查询只接受客户编号与分页参数，运行不可变结果快照的参数化查询，不重新调用模型或Spark。数据面快照缺失或摘要不一致时失败，不能返回预设值或伪装为空结果。应用令牌只回显一次、持久化只存哈希，可撤销；调用与限流记录持久保存，私有单并发边界下串行判断限流。

独立客户端为`scripts/query-v2-data-service.py`：从权限0600的令牌文件读取，禁用重定向，仅GET查询；stdout不含令牌。通过私有通道的调用不等于公网外部系统已接入。OpenAPI标记`PRIVATE_CLOUD_TEST`，正式域名、HTTPS与网络验收仍单独完成。

GUI在独立Agent工作台提供“发布结果→接口交付”，经典数据服务模块也可使用同一组件与API。`shuduo services sources`、MCP `data_service_sources`共用元数据读取；私有发布通过CLI `--config-hash`或MCP `configHash`绑定版本。首版界面使用明确的字段契约模板创建草稿，不冒充新的模型语义规划。

规范依据：[FC定时事件与Cron](https://help.aliyun.com/zh/functioncompute/time-triggers)。日期限定Cron在测试后仍需清理；应用的过期签名阻止窗口外派发，但不能代替移除触发器。

导出的`shuduo-delivery-package.json`可用现有`shuduo-package unpack`解包，摘要从包记录取得。它是版本产物，不能把下载行为视为上线。

“下载演练证据”导出同一代码任务的核验报告、交付任务、完整包摘要与文件清单、实际演练批次及发布条件。包编号进入文件名，便于把证据与交付文件配对。导出保留实际状态，不把尚未完成的演练或关闭的发布通道标为成功；不包含凭证、Worker提交载荷、业务结果行或原始日志。
