# 第二个总体目标：世界级证券数据中台差距与演进路线

## 1. 目标与边界

在现有 MVP 基础上，以个人 + Codex 的方式，在 **12 个月以内**建设一个可明显对标 DataWorks 的综合数据平台。12 个月是上限；每阶段达到验收标准即可提前进入下一阶段。

优先服务两个虚构证券场景：经纪与财富管理、资产管理与基金。全部机构、账户、证券代码、数据源和指标均为虚构；不接入公司系统、真实交易、资金或监管报送。

产品目标不是复制任何厂商界面，而是把成熟平台的设计原则落实为可验收能力：数据源接入、元数据与资产治理、离线/实时同步、数据开发、质量、报表、运维、权限以及 Data Agent 的统一工作流。

## 2. 当前能力事实基线

| 能力域 | 当前已上线的 MVP | 明确边界 |
|---|---|---|
| 数据源 | 安全登记向导、连接测试、元数据采集摘要 | 不收集凭证；不连接真实生产数据源 |
| 数据同步 | 离线任务、运行记录、受控 CSV → MySQL 演示 | 非通用企业连接器与 CDC |
| 实时数据 | Kafka/Flink SQL 任务模型、状态、延迟与检查点模拟 | 不连接真实 Kafka/Flink |
| 数据开发 | SQL 草稿、静态校验、模拟发布、模拟运行和运行记录 | 尚无真实 DataWorks/EMR 适配器与 DAG |
| 数据资产与治理 | 资产目录、字段、血缘摘要、敏感等级、数据契约 | 元数据/血缘尚非真实自动采集 |
| 数据质量与运维 | 规则、评分、T+1 告警、影响分析、处置手册 | 尚无真实日志、告警渠道与根因引擎 |
| 数据报表 | 财富顾问持仓看板、受范围约束的问数 | 数据为虚构 T+1 快照，不构成投资建议 |
| 安全 | 虚构角色、最小权限检查、审计、脱敏预览 | 尚未接入 SSO、组织与行列级策略引擎 |
| Data Agent | 计划、确认、SQL/调度/部署产物、运维诊断、评测集 | 规则编排，不调用外部大模型 |
| 多端入口 | 浏览器 GUI、HTTP API、CLI、stdio MCP | CLI/MCP 仍是学习型客户端，未发布为企业 SDK |

## 3. 对标结论

当前产品属于“**可演示的端到端产品原型**”：它已经跨越了单页 Demo，具备从需求、代码、发布、报表到运维的闭环。但距离世界级数据中台仍有三个层级的差距：

1. **真实执行层**：连接器、数仓执行、调度、血缘和实时引擎仍以受控模拟为主。
2. **企业治理层**：组织、SSO、凭证托管、行列级策略、审批、合规留存与多租户尚未形成体系。
3. **可信智能体层**：需要真实工具授权、长任务状态、Trace、反馈闭环与更大规模证券场景评测。

与 DataWorks、Databricks、Snowflake、Microsoft Fabric、Collibra/Informatica 的比较重点不是功能清单数量，而是以下共同原则：

- 同一原子能力由 GUI、API、CLI、MCP 复用，使用同一权限、审计和错误模型。
- Agent 先展示计划、证据、风险与可修改产物；写入、发布、敏感访问和恢复必须经过确认。
- 数据目录必须连接数据源、字段、质量、契约、血缘、责任人和消费者。
- 自然语言问数必须受语义口径、时间语义、访问范围和引用证据约束。

## 4. 标杆用户旅程

### 财富顾问客户持仓分析

目标用户：财富顾问。第一版仅允许查看本人负责的虚构客户，数据时效为 T+1。

1. 顾问描述持仓分析需求，或在报表页提出受范围约束的问题。
2. Agent 检索资产、字段、敏感等级、语义口径和数据契约。
3. Agent 生成 Hive/Spark SQL、测试 SQL、质量检查、调度配置和部署配置。
4. 用户在代码编辑器审阅或修改 SQL，并确认创建任务。
5. 数据开发模块校验 SQL、人工确认发布并记录模拟运行。
6. 持仓看板展示客户总资产、持仓市值、证券数量、资产类别和行业分布。
7. 质量或 T+1 时效异常进入运维中心；Agent 可展示影响与处置手册，但不得自动结案。

首条旅程的价值在于：把“业务问题 → 受治理数据 → 可审阅代码 → 可发布任务 → 可解释报表 → 可处置异常”串成一个可复刻闭环。

## 5. Data Agent 产品原则

工作台采用“对话 + 计划 + 代码 + 结果”四区结构：

- 对话：收集需求与修改意图。
- 计划：步骤、证据、风险、确认点和影响范围。
- 代码：SQL/Python、测试、差异、版本和静态校验。
- 结果：样例、质量、运行、报表、审计和下一步。

Agent 可自动生成 SQL、调度、部署文件、质量规则和报表配置。以下动作必须等待人工确认：创建/修改任务、运行或发布任务、访问敏感资产、修改权限/脱敏/数据源、确认告警；“标记已恢复”必须有人类核验结果。

## 6. GUI、API、CLI、MCP 的产品分工

| 入口 | 主要用户 | 定位 |
|---|---|---|
| GUI | 财富顾问、产品经理、业务人员 | 可视化配置、计划审阅、代码确认、报表和运维处置 |
| API | 前端、系统集成、自动化 | 统一资源、权限、审计与状态接口 |
| CLI | 数据开发工程师、运维 | 列表、校验、发布、运行、告警排查和流水线调用 |
| MCP | 受治理 Agent | 将 API 原子能力封装为带确认要求的工具 |

MCP 不应绕过 API，也不应拥有比 GUI/CLI 更高的权限。第一阶段已提供开发任务校验/发布与告警确认工具；自动结案工具被刻意排除。

## 7. 演进路线图（12 个月上限）

| 阶段 | 时间上限 | 核心交付 | 阶段验收 |
|---|---:|---|---|
| P0：标杆旅程可用 | 0—2 个月 | 持仓分析、代码/调度/发布、问数、运维闭环 | 从一句需求到受范围约束的报表，无需手工填写多个表单 |
| P1：真实执行适配 | 2—4 个月 | DataWorks/EMR 适配层、DAG、版本、重试、CSV/API/DB 连接器 | 开发工程师可用 GUI 或 CLI 产出同一任务与审计 |
| P2：治理生产化 | 4—7 个月 | 自动元数据、真实质量/血缘、契约评审、SSO、凭证托管、策略引擎 | 资产变更能评估消费者影响，并按策略阻断风险发布 |
| P3：实时与智能体可信化 | 7—10 个月 | CDC/Kafka/Flink、Trace、审批、幂等、50—100 条评测集 | Agent 的正确率、SQL 成功率、引用完整性和拒答正确率可量化 |
| P4：复刻与团队化 | 10—12 个月 | 成本控制、备份、监控、培训 PPT、部署手册和复刻项目 | 团队成员能按文档复刻首条财富顾问数据旅程 |

## 8. 量化评价指标

- 易用性：从需求到首个可用结果的时间、表单数量、人工切换次数。
- Agent：计划采纳率、首次 SQL 通过率、人工修改行数、引用完整率、拒答正确率。
- 完整度：数据源、同步、开发、质量、资产、契约、报表、权限、运维、Agent 的端到端覆盖率。
- 可靠性：任务成功率、数据质量通过率、T+1 SLA、平均恢复时间。
- 安全性：越权拒绝率、敏感字段暴露率、审计完整率。
- 成本：每次 Agent 任务成本、每个成功任务成本、云资源月度上限。

## 9. 成本与优先级约束

默认目标为每月不超过 50 元；必要时允许 50—200 元。优先使用 GitHub Actions、阿里云 Serverless、自动暂停、最小实例数和模拟数据。任何需要长期运行的数仓、流计算或大模型服务，都必须先给出成本上限、停用方式和替代方案。
