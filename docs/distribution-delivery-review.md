# 分布八文件与本机文件审阅

已核验的分布Agent任务可继续生成同一版本的SQL、测试SQL、调度、部署、日历、验证数据、源报告和说明八文件，并按这些实际文件执行Spark演练。准备过程不再调用模型。客户、交易日与分类共同组成键；同一客户多行是合法结果。

`tests.sql`逐组匹配全部六列并核对总行数，比例按六位小数比较。实际值不先转换到两位或六位再作比较，避免错误精度被舍入掩盖。Worker仍独立核验字段、复合键、金额、数量、比例范围和五组字面预期。旧客户级测试SQL保持原字节。

manifest的`source.outputContract`绑定登记ID与元数据摘要，`fixtures.json`冻结元数据和同族样例，`validation.json`冻结原需求理解。验证会拒绝缺失绑定、改动粒度/精度、混用契约、恒真或降精度测试SQL，即使重新计算全部文件和包哈希也不能通过。需求、代码或源批次变化不能借用旧包或旧审阅。

上下文API、静态前端代码与模型提示只使用安全元数据；供工程师执行和审阅的交付包包含虚构样例及独立预期。它们用于复现断言，不作为模型生成或修正提示的标准答案。

文件演练通过后，可逐项确认代码、断言、文件和本机范围，登记`LOCAL_FILE_REVIEW`。记录绑定包ID/摘要/演练与当前审阅人；它不创建发布批准、定时器或批次。准备或审阅回执未知时，先按原任务/包读取现有记录；读取失败保留历史，但禁用当前写入。文件审阅和实际发布是两个独立动作，分布批准发布/实际发布端点在本阶段保持关闭。

GUI/API沿用原任务、交付与审阅接口；现有CLI/MCP文件和审阅能力复用同一API，不新增独立执行链。CLI `unpack`、`plan`仅解包/解析，本轮实际核对其三节点顺序且`executed:false`。MCP审阅工具仍要求工程师明确确认，不能把生成文件视为已经审阅。

验证入口：

- `test/v2/distribution-delivery.test.mjs`：八文件、冻结理解/契约、六位断言、重签篡改、假成功与远程目标拒绝。
- `test/v2/distribution-delivery-api.test.mjs`：准备幂等、确切演练/摘要、旧理解拒绝、只登记文件审阅及发布关闭。
- `test/v2/distribution-review-ui.test.mjs`：四项明确确认、只读禁用、历史与当前区分、渲染无写入。

实际本机验收复用已有虚构资产类别任务：一次真实文件演练通过，准备响应丢失后找回同一包与演练，原开发任务保持不变。精度反例先确认实际产生第七位误差，再确认测试SQL和独立断言均拒绝；首个被宽精度运算提前舍入、未产生误差的样例保留为未覆盖反例，不倒填为通过。上游模型为替身，本轮无新模型请求，不计真实模型、公网或当前20例完整自主率。完整CI与页面证据以[唯一续接清单](goal-mode-next.md)为准。

下一阶段适配分布的本机测试发布、实际调度/监控和停止回滚；云端激活、真实模型与正式业务发布另验，不继承旧授权窗口或旧批准。
