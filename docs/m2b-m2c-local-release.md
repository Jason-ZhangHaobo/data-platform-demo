# M2b/M2c：本机真实调度、发布与监控闭环

日期：2026-09-14。范围仅为本机、虚构证券数据和`local-spark-v1`。本报告证明本机标杆链路，不证明公网、生产、云端隔离或完整Agent E2E。

## 实现语义

1. 只有包摘要匹配且存在成功文件演练的交付包才能审批。
2. 审批记录绑定包摘要、源SQL哈希、演练批次和审阅人；同一审批不能改参数后重复使用。
3. 本机发布将不可变包解到独立发布目录，创建`ACTIVE_LOCAL`版本及持久化计划批次。
4. 批次由墙上时钟计时器触发，不由“立即运行”按钮伪装；队列串行执行真实Spark与tests.sql。
5. 每批保存计划时间、实际触发时间、完成时间、引擎、五场景断言、工作流节点和日志摘要。
6. 失败批次创建开放告警；后续成功可自动恢复。回滚只允许指向已有成功批次的历史版本，并安排两个计时恢复批次。

发布状态中的`published=true`仅表示本机版本已激活；`publicDeployed=false`和`fullLifecycleE2E=false`始终保留。样例业务时刻仍为2026-09-11 09:00，对应冻结业务日2026-09-10；短周期墙上时钟只验证本机调度器。

## 未完成边界

- 这不是守护进程或多实例高可用调度器；本机进程和SQLite不能直接公开部署。
- 尚未使用官方交易所日历、云端OSS/镜像、邀请认证、项目ACL和隔离执行。
- 本轮故障是发布文件完整性故障，不等于已经覆盖Spark资源耗尽、数据迟到或业务质量异常。
- 尚未把20个M1案例逐一跑完整发布链路，因此完整Agent E2E≥85%仍未评测。
