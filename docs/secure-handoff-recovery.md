# 本机安全交接：未知结果恢复

本机凭证入口先确认服务和当前入口身份。断线、超时、返回内容无法解析或入口不匹配时，保留当前页面的输入，禁用重复保存，自动尝试一次只读核对；之后可明确点击“核对原保存状态”。界面不再直接显示原始网络异常或响应正文。

| 原状态 | 页面反馈与下一动作 |
|---|---|
| 尚未接收 | 服务在线时可明确重试原内容；原请求正文被冻结，不能悄悄换一份输入 |
| 验证拒绝 | 没有开始保存，输入保留并开放纠正，不自动提交 |
| 仍在保存 | 保留输入并等待，只读核对不增加写入 |
| 写入结果未知／部分步骤未确认 | 保留输入、阻止重写，需独立核对原执行回执 |
| 本机准备或领取已确认 | 才清空输入；这不是密码轮换、云配置或业务验收完成 |
| 加密值已保存，工作流启动未确认 | 不要求再次填写或重写已确认值，不自动重跑工作流 |
| 暂存过期或服务停止 | 不延长期限、不重开权限，不把保存未知说成未保存 |

刷新页面只保留一个非秘密操作标记，不保存密码、Key或原请求正文到浏览器存储；不能据此重建丢失的凭证正文并重复提交。输入只在当前页面及既定进程内存中按原期限保留，关闭或过期后的材料处理不改变。

`GET /status` 只返回当前入口的状态、期限和计数，要求原Token、对应HttpOnly Cookie、正确Host及同源边界；不返回邮箱、凭证、密码哈希、Token值或准备材料。不同入口使用各自的Cookie名，避免多页覆盖。它不写GitHub、不领取材料、不调用模型，也不延长暂存或执行窗口。

准备回执及 `waitUntilPrepared`／`consumePrepared` 协议保持不变，只有原成功响应发送后才能一次领取。`executionAuthorized` 仍只决定文案，不授予执行权。已有批准须按原提案、起算点、历史用量和当前前置条件核验，不能仅按文件日期认定失效，也不能由本机状态自行激活云操作。

本机合成验收覆盖了已接收但回执丢失后的原结果恢复、完全离线后的五项输入保留、只读核对、明确原内容重试、过期、不匹配入口、未知写入阻断与工作流未确认。GitHub、账户和维护执行均使用替身，不代表真实凭证已交接或云端轮换通过。真实入口应在本人方便填写时生成，避免提前开启后再次过期。
