# 数舵完整目标验收清单

更新：2026-11-10。需求基线为[PRD](PRD.md)，执行入口为[当前续接](goal-mode-next.md)。本页保留完整产品目标；源码、本机、私有云、公网和真实用户验收分别记录，实际运行标识及回执保存在本机受保护证据中。

## 验收口径

当前新任务目录是 `securities-live-agent-reviewed-lifecycle-v3`：固定20例，10条新任务及10条成功来源口径变更，覆盖两组共10套已登记证券上下文。每例包含需求、代码、调试、调度文件、部署文件、工程师审阅、实际发布、监控和授权消费；完整成功门槛至少17/20，未执行项留在分母。

当前目录需要新的模型任务。旧v1记录不含消费，旧冻结SQL回放不含新模型委托；合成模型、参考SQL、人工救援和内部消费回查均需单独披露。执行器的本机 `targetMet` 也不代表公网、外部客户端或最终Agent自主目标已经通过。没有完整实测时，完成率应标为尚未测得，不能把未执行理解为模型成功率为零。

2026-11-10来源核查已复现并封堵五类合成误计，覆盖嵌套回执、人工续改及仅服务规划任务；运行／刷新／报告共用检查。报告以`autonomousCompletionRate=null`及`fullGoalTargetMet=false`表达本机审阅链没有测量完整自主目标；测试通过不改变实际20例状态，见[完整计分范围](live-lifecycle-evaluation.md#来源反例与报告口径2026-11-10)。

计划上界为60次模型调用、120个Spark运行及640000 Token预留，`willExecute=false`。这些是最坏情况规模，不是执行或费用批准。实际推进按小批次、预算、真实凭证和确切版本审阅控制；人审等待不由执行器代批。

后续[隔离实际集成](local-real-spark-service-integration.md)已补真实Spark文件演练、两个本机计时批次和DAPI／XAPI实际查询。它使用MANUAL参考SQL与合成测试审阅；临时测试应用已撤销。该记录只证明既有开发／交付／调度／消费API的本机串接，不升级为当前v3新模型、公网、外部系统或自主E2E成功。

## 当前执行顺序

1. 保留现有真实／合成／人工及历史失败记录；核对有效契约和原运行，恢复已有可信运行时，不重建资源或重复计算。
2. 在不调用模型的隔离环境推进一条真实Spark开发→文件→调度→消费集成回归，明确测试执行者与合成审阅，不计Agent自主20例，也不冒充本人业务批准。先复用已有执行器和API，按实际缺口修复。
3. 合法模型凭证及具体范围就绪后，先一条当前v3新任务，审阅确切包后续接监控与消费，再推进口径变更和其余固定案例。云端、外部客户端、浏览器／网络与完整经典模块证据继续分别补齐。
