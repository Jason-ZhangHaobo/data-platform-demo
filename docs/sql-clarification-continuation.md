# SQL Agent：回答原问题后续接

## 背景

Agent遇到未登记口径可以提出问题，但原任务停止后，用户不应重述需求或重建代码输入。普通SQL任务此前没有统一保留初始代码，直接再发一条回答也会失去原问题和上下文。

## 价值

用户直接回答上方问题，以原需求、问答历史和代码输入创建独立后续任务。原任务、原用量和失败记录保留，新代码仍独立执行、生成文件并审阅。GUI、API、CLI和MCP使用同一协议。

## 问题

回答必须绑定本人、同项目的原问题版本，不能替换代码、口径或费用历史；结果未知时不能创建第二个任务。人工补充业务意图仍由Agent编写代码，但不等于最初需求的直接自主完成，也不应错误归因为工程师手写SQL。

## 需求

- 新普通SQL任务保存实际送入模型的`initialSql`；持久任务继续保留原输入。读取恢复优先展示保存代码或初始输入，不猜造旧任务缺失的代码。
- `GET /agent/tasks/:id/clarification-source`只读核对原创建者、项目、已确认的澄清状态、问题报告、代码和用量，返回原输入及问题摘要绑定，不调用模型／Spark。其他管理员也不能代原创建者回答；原角色、CSRF和执行窗口检查不变。
- `POST /agent/tasks`新增`clarification:{taskId,evidenceDigest}`；`message`为1—1000字的回答，SQL和口径必须与原问题一致。拒绝混用修正／人工／派生或未定义字段。客户端不能提供完整可信历史，也不能覆盖归因。
- `shuduo-sql-clarification/v1`保存原需求、原任务、问答、来源摘要、原用量及估算标记，最多三轮。新任务独立保存，不复制原运行、结果、交付包或批准。原用量不转移、不清零；平台总预算和调用门继续覆盖每次新请求。
- 模型仍使用一次原生成接口；提示只投影原需求、问题与回答及依据摘要，不发送任务ID、来源摘要、历史Token或其他控制元数据。历史问答纳入原请求预算，超限按既有预检停止，不扩大预算或自动截断。
- 创建、模型调用前／后、计算提交和后续交付／发布前重核来源。来源变化时停止新增调用；已经准备的运行保留原编号和未知状态，先查询回执，不假设未执行或自动重提。后台遇到该状态暂停。
- `humanClarified=true`、`directAutonomousEligible=false`及原澄清任务随新任务／代码／报告保留，显式成功来源派生继续保留标记。原生开发与经典功能仍可用；不将人工澄清误写为手工SQL，也不计入直接自主E2E。
- 理解报告、依据摘要与八文件冻结问答及归因；只读界面区分原任务历史占用与本次用量。新任务仍须重新核验、演练和明确审阅，不继承批准。
- GUI只需回答原问题，权限／只读／未就绪／未保存编辑／缺失原输入／超出轮数时说明原因并关闭提交。后台委托仍显式显示原限制。请求丢失沿用原恢复编号；读取恢复不重发需求。问答是文本，不可执行指令。

首期支持原生、已登记SQL任务及其澄清链；人工来源、显式修正／成功口径派生的问题暂不接入此入口，界面明确说明。Python及更广业务契约继续按总目标扩展，不由本增量宣称完成。

## Demo、接口与验收

- CLI：`shuduo agent clarification --id TASK_ID`只读问题及摘要；`shuduo agent clarify --id TASK_ID --evidence-digest SHA256 --answer "当前五项即可" --request-id UUID --confirm`明确续接。未知结果用原`agent request`查询。
- MCP：`agent_clarification_source`只读，`agent_clarification_reply`要求确切摘要、回答、稳定requestId和confirm；不自动发布。注册源码与外部实际客户端连接分别验收。
- 回归涵盖归属／CSRF、代码与口径替换、旧问题／混合来源、三轮上限、模型前后和持久化间变化、原预留／用量、SQLite恢复、派生归因、提示隐私、真实HTTP及CLI／MCP同源。
- 实际主页面保留同一原问题，提交一次答复并注入一次连接中断；只保留一个后续任务、两次模型响应替身。初次浏览器过程记录全部POST，不据此宣称没有传输重放；补验原编号纯读取恢复没有新增POST、模型或Spark。
- 使用现有真实本机Spark3.5.9分别完成一次开发、一次八文件演练，独立客户金额／数量、测试SQL和五场景均通过；原任务不变，问答进入冻结包。模型响应合成，未审阅发布、不调用云资源、不计真实模型或当前v3自主完成率。

回归入口：`durable-agent.test.mjs`新增场景、`sql-clarification-api.test.mjs`与`sql-clarification-ui.test.mjs`。当前状态见[执行清单](goal-mode-next.md)，实际标识及运行证据只留受保护位置。
