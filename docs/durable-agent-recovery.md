# Agent 任务持久化与恢复：第一阶段

本文记录通用实现、虚构测试及验收方法，不报告私有环境的运行事实。实际部署状态须查阅本机受保护的`docs/private-execution-state.md`（如存在）。最初13项合成故障测试见[本机记录](evidence/v2-durable-agent-recovery-local.json)。只覆盖Spark SQL，Python和后续调度发布不在本阶段。

## 目标与边界

### P0②：事件后台增量（默认关闭）

`V2_AGENT_DRIVER_MODE=OSS_EVENTS`复用现有私有控制函数与签名Spark队列。用户创建任务时显式选择`background=true`，或者对原任务POST`/api/v2/agent/tasks/:id/background`，提供`expectedVersion`。后台许可只绑定当前任务、提交者和上下文契约；默认15分钟、最多20个事件，硬上限30分钟，不自动发布。没有配置完整的私有执行边界、持久执行器、事件账户和签名密钥，服务启动失败；没有选择后台的旧任务不自动纳入。

推进顺序是：持久许可与不可变唤醒对象 → OSS创建事件 → 当前任务单个检查点 → 必要时创建下一个唤醒对象。`WAITING_FOR_RUN`等待已有Spark结果对象的事件，不创建空闲轮询或进程计时器。结果必须属于已登记运行，并通过原Worker签名验证，才能唤醒同一个任务。达到SQL开发完成后停止，不跨过交付审阅、发布或权限变更边界。

每次执行重新检查提交者仍启用且有当前项目工程师/管理员权限。许可到期、撤销、上下文漂移、事件次数耗尽和模型结果未知都会暂停；不会自动付费重试未知模型。写入响应未知时保留同一出站对象的编号和正文，禁止创建新需求或重复模型步骤。模型检查点已持久化但原Tick回执丢失时，恢复原回执，不在旧事件下偷偷启动下一个Spark步骤。

`POST .../background/cancel`只停止后续后台推进，不删除任务或撤销已提交计算；停止整个任务仍使用原`POST .../cancel`。后台启用期间人工`advance`被拒绝，先停止后台再接管。GUI只通过GET展示进度，不以页面轮询来驱动模型。API、CLI和MCP使用同一权限与检查点；CLI启用/停止需`--confirm`，MCP需`confirm:true`。

触发对象前缀与Spark任务、结果、取消、产物分别隔离；每次通知只识别一个严格的UUID对象。控制角色仅需新增唤醒前缀Get/Put，并复用已有结果读取范围。官方FC3.0的`fc:InvokeFunction`不支持单函数Resource授权，因此方案只允许核验并复用已有OSS事件调用角色，不把`Resource:"*"`新增到控制角色。若现有调用权限不足，停在权限门，不能假称“单函数最小权限”。参考[官方RAM授权表](https://help.aliyun.com/en/functioncompute/api-fc-2023-03-30-ram)和[OSS触发规则](https://help.aliyun.com/zh/functioncompute/overview-of-oss-trigger)。

`scripts/render-v2-agent-event-plan.mjs`仅生成待审阅计划，不应用云变更。云端需另核验当前账单、私有性、原角色策略、两条互不重叠的通知规则、异步重试边界与源包后才启用。首个真实云用例要求关闭页面/本机驱动后继续推进；签名队列与模型替身测试、localhost UI、配置成功均不计作真实云或完整E2E验收。事件丢失、投递未确认或失败时保持可见恢复状态，不保证无条件最终完成。

唤醒签名使用既有调度密钥（如已配置），否则使用既有Worker密钥，经`shuduo-agent-wake-key/v1 + project`独立用途域派生，不新增或回显密钥。原始Worker签名不能作为唤醒签名。Worker没有唤醒前缀写权限或平台元数据库权限；消费时还必须匹配控制面持久化的原对象正文摘要、许可、身份与任务版本，不能只凭共享签名发起工作。

以下章节保留显式推进/临时CLI驱动的历史合同，不能据此推定当前云部署状态。

不再把“数据库中有一条任务记录”等同于任务可恢复。请求输入、阶段、模型尝试与预算、生成版本、唯一运行批次均写入现有元数据存储。复用已有签名 Spark 队列和结果验证机制，不创建新云角色、触发器或执行器。

默认关闭。`V2_DURABLE_SQL_AGENT_ENABLED=true` 仅在已装配 durable Spark runner 时启用；没有持久执行器则启动失败，不能退回进程内执行来冒充恢复。旧模式保持原状。当前私有预览的 Agent 路由仍未开放。

首版采用**显式推进 API**，一次推进一个检查点，不使用 GET 启动模型或付费计算。下述后台驱动是有界进程，示例配置默认关闭；其实现不等同永久托管云调度或自主完成所有阶段的验收。

## 阶段与恢复行为

| 阶段 | 已保存的证据 | 再次推进时的行为 |
|---|---|---|
| READY_FOR_MODEL | 需求、代码、上下文与验证契约摘要、任务预算 | 在调用模型前保存尝试、预算预留和有期限的租约 |
| MODEL_IN_FLIGHT | 尝试号、租约、保守预算预留 | 有效租约期间拒绝重复请求；过期或超时转为结果未知 |
| MODEL_OUTCOME_UNKNOWN | 可能已经发生的用量预留、未知结果标记 | 不自动再次调用；明确确认后才在剩余预算与次数内重试 |
| READY_FOR_RUN | 原子关联的生成 SQL 和版本 | 恢复原版本，不重新调用模型 |
| WAITING_FOR_RUN | 唯一运行编号、已准备的固定签名提交内容 | 丢失提交响应时复用同一正文和幂等运行，不能创建新批次 |
| READY_FOR_MODEL（修正） | 前次运行、独立断言错误和尝试记录 | 在后续显式推进中修正，不把前次失败擦掉 |
| CANCELLING | 取消意图 | 取消标记未确认时保持此阶段，重试取消而不是继续计算 |
| SUCCEEDED／FAILED／CANCELLED | 最终状态和关联结果 | 不重复发起工作；迟到模型结果或 Worker 成功不能复活已取消任务 |

模型步骤设独立超时；结果未知时保留保守用量，不能当作“免费重试”。默认最多三次模型尝试、任务 Token 上限沿用配置，单次预留最多 12000 Token。模型返回用量超过本次限额时停止，不继续提交 Spark。月度模型和计算预算门继续有效。

当前恢复合同要求输入上下文及验证契约摘要不变；发生变化时返回冲突，要求审阅并新建任务，不静默套用新的业务口径。

## API

- `POST /api/v2/agent/tasks`：使用现有请求字段创建任务；启用新模式后只保存，不在此调用模型。创建幂等键按项目和提交人隔离。
- `GET /api/v2/agent/tasks`、`GET /api/v2/agent/tasks/:id`：读取状态，不推进。内部租约令牌和恢复字段不对外返回；公开 `stage`、`version`、`attempts` 与 `recovery` 摘要。
- `POST /api/v2/agent/tasks/:id/advance`：请求体必须提供刚读取的 `expectedVersion`；可选 `confirmModelRetry` 布尔值。旧版本返回409，避免相同请求意外推进下一个阶段。
- `POST /api/v2/agent/tasks/:id/cancel`：保存取消意图，复用现有签名取消标记；统一工作台的子任务取消也接入同一路径。

新模式继承后端会话、CSRF、项目和开发权限校验，并限制任务由提交人或项目管理员读取/推进/取消。项目内代码和运行的共享策略仍沿用原模块；不能将本次任务级测试扩充宣称为全部云端跨用户隔离验收。

## 测试与后续门槛

测试入口：`test/v2/durable-agent.test.mjs`。使用可重开的 SQLite、复制快照 CAS、合成模型和签名队列测试替身，覆盖：

- 输入、版本、运行检查点分别重启后恢复；旧任务模式仍按原规则中断。
- 独立 OS 子进程在生成版本后、队列已接收但尚未确认提交后强制退出；第三个进程恢复，同一测试最终只有一次模型调用、一个版本和一个计算事件。模型与队列仍为合成测试替身。
- 提交响应丢失后仅保留一个计算事件，同一签名正文、同一运行编号。
- 持久化失败前不调用模型；生成版本保存后不重复生成。
- 模型有效租约、防止重复推进、超时未知、明确重试与迟到结果隔离。
- 修正上下文、预算耗尽、输入变化阻断、取消失败恢复。
- 复制存储冲突在外部调用前阻止竞争者；请求版本 CAS 不被复制存储忽略。
- 真实本机 HTTP 的创建幂等、只读无执行、CSRF、提交人权限、跨项目拒绝及开关默认关闭。

这些是恢复机制与安全测试，不是真实模型或真实 Spark 成功率。下一步按已确认顺序完成真实模型→真实 Spark 的恢复验证、交互入口与必要的后台驱动；云端私有灰度通过后再推进调度文件、部署文件、审阅发布、监控以及 DAPI/XAPI。不能仅打开 Agent 按钮就升级完成状态。

生成器异常目前保守归为“模型结果未知”，需要明确确认才会重试；下一阶段再结合真实服务商响应细分错误，不能把未知异常当作无成本重试。

## 第二次增量：有界私有后台驱动

`V2_AGENT_DRIVER_MODE=PRIVATE_TICK` 必须与持久 SQL Agent、私有 provisioning 调用边界同时启用，否则启动失败。默认 `DISABLED`。不增加公网 tick 路由，不配置新的云触发器或 IAM 权限。

- 在现有 IAM 私有 `/invoke` 中新增 `PRIVATE_AGENT_TICK_V1`，只接收 `operation` 和 UUID `requestId`。不接受代码、目标项目、任务执行列表或模型重试确认。
- 每次最多推进一个任务的一个阶段。先持久化项目级120秒租约和请求收据，再执行；同一请求重放返回原收据，不重复推进。
- 从持久状态选任务，不依赖浏览器会话或页面轮询。每步重新确认提交人账号有效且仍有当前项目开发权限；撤权后仅允许继续已请求的取消清理。
- 有效模型租约期间不启动下一任务；过期模型调用转为未知结果，需要人工明确确认，后台驱动绝不代替确认。
- 每任务至少5秒冷却，失败指数退避至60秒；同一任务版本连续3次失败后暂停后台尝试，其他任务可继续。人工处理改变任务版本后可再次尝试。任务取消、模型预算等仍由原引擎控制。
- `agent_tick` 保存每次实际领取的结果，`agent_dispatch_state` 保存任务冷却/错误码，`agent_dispatch_guard` 保存项目租约。迟到调用不能覆盖新租约或新调度记录。

操作脚本 `scripts/run-v2-agent-driver.mjs` 复用执行环境的 `aliyun` CLI 登录，不读取或导出凭证，不修改资源。目标从本机/受保护环境的 `V2_FUNCTION_NAME` 与 `V2_REGION` 获取，不在公开文档写入真实标识。仅在云端开关及新代码核验后执行：

```sh
node scripts/run-v2-agent-driver.mjs
```

默认每5秒发一个 tick、最多60次、5分钟后不再发新请求；已发出的单次 CLI 请求最多再等待150秒。两次空闲或连续三次调用/步骤失败会停止。响应丢失时复用原 `requestId`。脚本不依赖浏览器，但**脚本进程停止、主机休眠或 Cloud Shell 到期后不会自行继续**；重启驱动后从数据库恢复。它不是已部署的常驻云调度器。

新增10项后台专项测试使用合成模型/回执，覆盖实际 SQL Agent 状态机跨 SQLite 重开、多个驱动竞争、复制存储冲突、持久化失败、租约到期、撤权、连续失败暂停、迟到结果及 CLI 有界重试。另有1项旧版发布路径回归，遍历 V1 实际相对导入，保留被 V1 共用的 OSS 客户端触发。云端登录创建 Agent 任务、后台真实模型与 Spark 验收、前端恢复提示仍待完成。

此增量本机完整 `npm run ci`：447通过、0失败、1既有跳过（含2项本机私有运维测试，不等同公共CI计数）；构建与前端入口体积门均通过。本轮没有付费模型调用、云资源改动或新增密钥。

## 私有云验收入口（验收结果另行记录）

新增 `PRIVATE_AGENT_RECOVERY_V1` 固定虚构证券 fixture，载荷仅接受 `action`（prepare/generate/read/finish）和 `requestId`。prepare幂等保存专用验收主体及任务；generate仅允许首次模型生成，不能确认未知模型结果或自动重试；read返回实例启动标识、任务/版本/批次摘要和独立结果匹配；finish仅在任务结束后停用该专用主体。没有登录密码、不接收任意SQL、不暴露进程终止接口。

实际验收必须记录生成检查点，在受控配置切换后独立读取：启动标识必须改变，原任务、代码摘要、尝试次数和Token账本必须一致。再由私有后台tick继续同一任务，要求真实模型身份、Spark3.5.9、五套断言及独立金额结果均通过。仅实现入口不代表验收成功；该fixture不等同最终用户GUI或七阶段E2E验收。

临时操作环境丢失本机验收编号时，`read`/`finish` 也可用互斥的 `taskId` 找回已经登记的专用验收记录；不能用它创建任务、调用模型或访问非验收任务。操作端必须将编号、检查点和日志留在可恢复的受保护位置并及时导出，不能只放 Cloud Shell `/tmp`。

## 第2项已开始：正常用户需求入口

私有应用转发接入持久SQL Agent的创建、读取、推进、取消。开关关闭时保持拒绝；不允许退回旧进程内Agent，不允许Python。转发保留登录Cookie、CSRF和项目头，由原业务API判断权限；不会为用户代造会话或确认模型重试。创建必须返回同一幂等任务和READY_FOR_MODEL，尚不执行模型。发布状态和用户旅程必须另行验收，不能从通用代码和虚构测试推断。

## Agent 开发工作台交付范围

独立工作台在同一页面提供任务历史、证券数据口径与字段、需求输入、SQL编辑/差异、执行结果、独立校验和日志。原全平台规划入口保留；私有试用先限定SQL开发，不开放未接入的模块。

- 点击“按此口径生成并验证”后，本页按版本推进检查点，在预算和次数内自动处理执行失败与修正；刷新只恢复任务，不自动再次调用模型。未知模型结果必须显式勾选费用提示才能重试。
- 会话自动推进有次数和时间边界，关闭页面后不继续发起新步骤；已提交计算可在执行器中继续。返回后从原任务继续。该实现不是永久托管云后台，不替代后续驱动迁移。
- 人工编辑可以撤销、查看差异或另存版本执行；刷新服务端状态不能覆盖未保存修改。切换任务和离开页面需保护未保存草稿。不同登录身份不共享工作台缓存。
- “让Agent修正并验证”绑定具体失败批次和对应SQL版本。后端验证项目、上下文、代码一致性，错误从服务端运行记录读取，不接受客户端伪造错误；成功批次、跨项目、代码不一致或执行超时不能当作SQL修正来源。
- 历史失败尝试仍可回看日志，不因后续成功而被删除；结果显式绑定运行批次和代码版本。缺失的原始草稿或实际引擎耗时不补造，预算预留不显示为实际执行耗时。

私有预览默认仍不开放Agent路由，需显式使用 `--agent-development`；后端持久引擎也须已启用。两侧均不放宽身份、CSRF、Host/Origin、固定路径、请求额度或数据范围。通用启动形式：

```sh
node scripts/run-v2-cloudshell-preview.mjs --origin <已核验的官方私有预览源> --port 60000 --agent-development
```

工作台的真实验收应覆盖正常生成、手工失败批次修正、任务刷新、失败历史回看、停止、未知结果确认、草稿保护及窄屏布局；合成界面测试与真实模型/执行器测试必须分开记录。
## 模型诊断与审阅恢复补充

模型尝试的 `diagnostic` 记录固定分类 `code`、阶段 `phase`、`elapsedMs`、`requestMayHaveBeenSent`，以及存在时的 `httpStatus`/允许列出的 `networkCode`。不包含响应正文、URL、异常消息、输入或密钥。没有历史诊断的旧尝试不能补猜根因；请求发送与实际计费也不能由错误状态推定。

原任务后台暂停后，提交 `POST /api/v2/agent/tasks/:id/background/resume`，正文为 `{expectedVersion, confirmModelRetry}`。后端核验所有者、有效项目权限、上下文摘要、尝试/Token/事件上限；未知模型结果必须明确确认。恢复仅持久化审阅与重新排队，模型由后续云事件推进。恢复窗口15分钟，原次数和预留不清零，不能恢复已完成任务，旧窗口事件不执行。

CLI：`shuduo agent resume-background --id <task-id> --version <version> --confirm`；未知结果另加 `--confirm-model-retry`。MCP：`agent_background_resume` 使用相同版本与确认字段。界面须展示诊断、剩余边界和显式恢复动作；新诊断不改变未知结果不自动付费重试的规则。
