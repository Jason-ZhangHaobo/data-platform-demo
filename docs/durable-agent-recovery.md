# Agent 任务持久化与恢复：第一阶段

更新：2026-10-10。状态：实现与本机合成故障测试阶段；13项专项测试通过，本机全量436通过、0失败、1既有跳过（含本机私有运维测试）。[脱敏测试记录](evidence/v2-durable-agent-recovery-local.json)。未部署到云端，未计入真实模型完成率或完整 Agent E2E。只覆盖 Spark SQL 开发任务，Python 和后续调度发布不在本阶段。

## 目标与边界

不再把“数据库中有一条任务记录”等同于任务可恢复。请求输入、阶段、模型尝试与预算、生成版本、唯一运行批次均写入现有元数据存储。复用已有签名 Spark 队列和结果验证机制，不创建新云角色、触发器或执行器。

默认关闭。`V2_DURABLE_SQL_AGENT_ENABLED=true` 仅在已装配 durable Spark runner 时启用；没有持久执行器则启动失败，不能退回进程内执行来冒充恢复。旧模式保持原状。当前私有预览的 Agent 路由仍未开放。

首版采用**显式推进 API**，一次推进一个检查点，不使用 GET 启动模型或付费计算。服务重启后可以读取原任务并继续；没有常驻/外部调度驱动时，任务不会凭空自行推进。因此，这不是“关闭浏览器后仍能自主完成所有阶段”的云端验收。

## 阶段与恢复行为

| 阶段 | 已保存的证据 | 再次推进时的行为 |
|---|---|---|
| READY_FOR_MODEL | 需求、代码、上下文与验证契约摘要、任务预算 | 在调用模型前保存尝试、预算预留和有期限的租约 |
| MODEL_IN_FLIGHT | 尝试号、租约、保守预算预留 | 有效租约期间拒绝重复请求；过期或超时转为结果未知 |
| MODEL_OUTCOME_UNKNOWN | 可能已经发生的用量预留、未知结果标记 | 不自动再次调用；明确确认后才在剩余预算与次数内重试 |
| READY_FOR_RUN | 原子关联的生成 SQL 和版本 | 恢复原版本，不重新调用模型 |
| WAITING_FOR_RUN | 唯一运行编号、已准备的固定签名提交内容 | 丢失提交响应时复用同一正文和幂等运行，不能创建新批次 |
| READY_FOR_MODEL（修正） | 前次运行、独立断言错误和尝试记录 | 在后续显式推进中修正，不把前次失败擦掉 |
| CANCELLING | 取消意图 | 取消标记未确认时保持此阶段，重试取消而不是继续计算 |
| SUCCEEDED／FAILED／CANCELLED | 最终状态和关联结果 | 不重复发起工作；迟到模型结果或 Worker 成功不能复活已取消任务 |

模型步骤设独立超时；结果未知时保留保守用量，不能当作“免费重试”。默认最多三次模型尝试、任务 Token 上限沿用配置，单次预留最多 12000 Token。模型返回用量超过本次限额时停止，不继续提交 Spark。月度模型和计算预算门继续有效。

当前恢复合同要求输入上下文及验证契约摘要不变；发生变化时返回冲突，要求审阅并新建任务，不静默套用新的业务口径。

## API

- `POST /api/v2/agent/tasks`：使用现有请求字段创建任务；启用新模式后只保存，不在此调用模型。创建幂等键按项目和提交人隔离。
- `GET /api/v2/agent/tasks`、`GET /api/v2/agent/tasks/:id`：读取状态，不推进。内部租约令牌和恢复字段不对外返回；公开 `stage`、`version`、`attempts` 与 `recovery` 摘要。
- `POST /api/v2/agent/tasks/:id/advance`：请求体必须提供刚读取的 `expectedVersion`；可选 `confirmModelRetry` 布尔值。旧版本返回409，避免相同请求意外推进下一个阶段。
- `POST /api/v2/agent/tasks/:id/cancel`：保存取消意图，复用现有签名取消标记；统一工作台的子任务取消也接入同一路径。

新模式继承后端会话、CSRF、项目和开发权限校验，并限制任务由提交人或项目管理员读取/推进/取消。项目内代码和运行的共享策略仍沿用原模块；不能将本次任务级测试扩充宣称为全部云端跨用户隔离验收。

## 测试与后续门槛

测试入口：`test/v2/durable-agent.test.mjs`。使用可重开的 SQLite、复制快照 CAS、合成模型和签名队列测试替身，覆盖：

- 输入、版本、运行检查点分别重启后恢复；旧任务模式仍按原规则中断。
- 独立 OS 子进程在生成版本后、队列已接收但尚未确认提交后强制退出；第三个进程恢复，同一测试最终只有一次模型调用、一个版本和一个计算事件。模型与队列仍为合成测试替身。
- 提交响应丢失后仅保留一个计算事件，同一签名正文、同一运行编号。
- 持久化失败前不调用模型；生成版本保存后不重复生成。
- 模型有效租约、防止重复推进、超时未知、明确重试与迟到结果隔离。
- 修正上下文、预算耗尽、输入变化阻断、取消失败恢复。
- 复制存储冲突在外部调用前阻止竞争者；请求版本 CAS 不被复制存储忽略。
- 真实本机 HTTP 的创建幂等、只读无执行、CSRF、提交人权限、跨项目拒绝及开关默认关闭。

这些是恢复机制与安全测试，不是真实模型或真实 Spark 成功率。下一步按已确认顺序完成真实模型→真实 Spark 的恢复验证、交互入口与必要的后台驱动；云端私有灰度通过后再推进调度文件、部署文件、审阅发布、监控以及 DAPI/XAPI。不能仅打开 Agent 按钮就升级完成状态。

生成器异常目前保守归为“模型结果未知”，需要明确确认才会重试；下一阶段再结合真实服务商响应细分错误，不能把未知异常当作无成本重试。
