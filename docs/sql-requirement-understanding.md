# SQL Agent：可审阅的需求理解

## 背景

独立开发工作台原先展示登记口径、需求原文和模型解释；这不能证明模型理解了本次指标、记录粒度或字段。完整E2E的需求阶段不能仅以请求摘要与LIVE_MODEL布尔值表达完成。

## 价值

同一次代码生成响应同时返回结构化理解与SQL，不另加一次模型调用。工程师在独立Agent内查看指标解释、真实字段、客户日粒度和去重／现金约束，再结合原代码及独立执行结果判断。需要未登记字段或不同粒度时，模型可以先提出一个必要问题，避免用现有五字段冒充其他需求。

## 问题

模型的结构化提案仍可能语义错误，不能因字段齐全就说理解正确。模型请求已经发生但理解不完整时必须保留用量；刷新、控制面重开或重新读取不能再次调用模型。旧任务没有结构化理解时不能补造历史证据，工程师编辑代码后也不能将原提案当作新草稿已验证。

## 需求

- `shuduo-sql-requirements/v1`绑定原需求摘要、登记上下文、验证族／版本、参数、表字段、五项指标和约束，保存摘要。只投影元数据，不发送业务行、独立答案或参考SQL；当前代码仍按既有代码生成协议提供给模型。
- 同一模型响应返回`requirement`、`sql`、`explanation`。开发理解含摘要、`CLIENT_TRADE_DATE`粒度、五项指标的解释与真实字段引用、完整约束及basisDigest。股票族额外确认仅股票持仓；不能解释成客户全部资产。
- 可返回`CLARIFICATION_REQUIRED`、摘要和一个问题，此时SQL可为null。当前任务保留`FAILED + REQUIREMENT_CLARIFICATION_REQUIRED`明确终态，界面显示等待澄清／未执行。后续须补充完整需求重新委托，不由原任务自动重试或重用批准。
- 字段引用、粒度、约束、摘要绑定或结构缺失，记`REQUIREMENT_EVIDENCE_INVALID`，不创建新代码或Spark任务。持久执行器及本机普通HTTP路径均保留已返回模型用量；缺少用量沿用既有保守预留机制。
- 成功提案保存到原task的`requirements`，绑定模型尝试、revisionId及SQL摘要，状态`MODEL_PROPOSED`、语义核验`REQUIRES_INDEPENDENT_EXECUTION`。SQLite重开只读恢复原记录；不能把结构核对替代独立客户结果和五场景断言。
- 新提案存在时，开发核验报告增加需求绑定检查；已成功执行但理解记录矛盾也不能准备交付。手工代码仍按其独立来源核验，不使用原Agent解释代替手工结果。
- GUI显示可展开提案、指标、字段、粒度、参数、约束与代码版本；澄清／无效记录展开说明。代码已编辑时提示仅对应原保存版本；旧任务明确没有结构化理解。任务API、CLI和MCP沿用原任务读取，不另建接口或授予权限。
- 当前v3运行和保存报告在新理解存在时核对其原需求、代码、模型尝试及摘要；旧契约、目录和历史缺失记录不迁移。旧本机契约率不能因此升级为完整自主率或公网完成。

当前范围为已登记的两组证券资产SQL任务；Python、自动登记新指标／新数据结构和澄清多轮续接仍按总体目标分阶段推进。交付包内冻结依据已由[冻结与审阅增量](frozen-requirement-delivery.md)继续补齐，不补造旧记录。该协议没有新执行、费用、部署或业务审批授权。

## Demo与验收

1. 同一次合成模型响应返回开发理解与SQL。真实本机HTTP／SQLite保存一条提案和一次尝试；刷新与元数据库重开不增加模型调用，原任务及代码版本一致。
2. 输入未登记行业分布场景，合成模型返回一个澄清问题。保存模型用量，SQL为null、无执行记录；重复读取／推进终态不重算。
3. 分别返回错误basisDigest、未知字段、少约束、错误粒度或缺少理解，均在Spark前停止，保留一次用量。
4. 篡改原任务／需求／版本／代码／口径依据，不能通过保存证据和交付核验。实际React组件和完整主页面验证提案、澄清、刷新及旧记录披露。
