# 数栈 V2 架构基线
来源：2026-09-13 已批准计划。需求见 PRD.md，决策见 decisions.md。

## 分层
- React/TypeScript 工作台：项目导航、Monaco 编辑器、Agent、版本差异、结果/日志。
- Node.js 模块化 /api/v2：上下文、版本、后台任务、运行和产物；GUI 已接入，V2 CLI/MCP 同源迁移待完成。
- 元数据仓库：开发使用独立 SQLite；云端独立 MySQL 数据库，业务表不存平台会话。
- 执行单元：真实 Spark SQL；仅访问该运行绑定的虚构输入，超时和结果规模有限。
- 模型适配：按量 Qwen API，可替换，未配置明确不可用，禁止关键词/模板冒充真实 Agent。
- 产物：M1 导出 SQL、验证报告和结果；M2a 新增实际可执行的测试 SQL、调度/部署/日历/输入文件和内容摘要。本机文件运行器已实现，真实云发布、云端 OSS 和运行时镜像绑定仍待后续阶段。

## 生命周期
草稿生成/人工编辑 → 保存不可变版本 → 后台执行 → 独立验证 → 人工审阅指定版本 → 发布。
模型修正有次数与 Token 预算，结果未通过不能宣告完成。
后台状态持久化；服务重启把不可恢复的进行中运行标为中断，不假造成功或静默重复执行。

## 边界
本地回环开发模式不是公网认证。公网写入须经过邀请/登录、项目授权、幂等与资源隔离验收。
SQL 由 Spark 执行；SQLite/MySQL 只用于平台元数据或明确的业务接口查询，不作为 Spark 替身。
旧 /api 和部署流程保留；新增代码不自动改造已发布函数。M0 预算/模型/隔离条件通过后安排灰度。

## UI 设计规范
暖白侧栏与工作区、深墨绿主色、琥珀色提示、清晰状态文字；统一间距和层次。
顶部紧凑项目上下文，左侧按工作域分组，中央代码/资产信息，右侧可收起的 Agent，下方结果与日志。
正文字号 13–14px；控制密度、对齐和截断提示；键盘、空/错/忙状态及窄屏均验收。
结果显式绑定版本哈希/运行编号；修改代码或更换上下文后，旧“通过”降为历史结果，不可当作当前代码已验证。
