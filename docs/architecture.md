# 数栈 V2 架构基线
来源：2026-09-13 已批准计划。需求见 PRD.md，决策见 decisions.md。

## 分层
- React/TypeScript 工作台：项目导航、Monaco 编辑器、Agent、版本差异、结果/日志。
- Node.js 模块化 /api/v2：上下文、版本、后台任务、运行和产物；M3、M4a、M4b已由GUI、V2 CLI和V2 MCP同源调用，后续模块随实现继续扩展同一契约。
- 元数据仓库：开发使用独立 SQLite；云端实现MySQL项目快照CAS，保存任务、版本、认证、权限与审计，业务行不进入该平台元数据快照。
- 云端业务状态：函数内存SQLite仅作单实例查询索引；私有OSS对象以ETag CAS持久化离线落地行、实时事件/状态/Checkpoint、DAPI服务快照和报表快照，冷启动时校验格式、主键、外键与JSON后恢复。
- 云端写入边界：成功的变更响应等待OSS业务状态先落盘、再提交MySQL元数据；后台实时处理也触发同一协调器。当前是月预算约束下的单实例试点架构，FC并发实例数必须保持1；它不是跨MySQL/OSS的分布式事务。
- 执行单元：真实 Spark SQL；仅访问该运行绑定的虚构输入，超时和结果规模有限。
- 模型适配：按量 Qwen API，可替换，未配置明确不可用，禁止关键词/模板冒充真实 Agent。
- 产物：M1 导出 SQL、验证报告和结果；M2a 新增实际可执行的测试 SQL、调度/部署/日历/输入文件和内容摘要。
- 本机发布控制面：审批绑定包摘要与源代码哈希；发布记录引用只读交付目录，不修改原包。
- 本机调度与监控：持久化计划批次由墙上时钟触发并串行进入 Spark；事件、告警、健康度和回滚记录写入平台库。云端MySQL/OSS适配与冷启动恢复已在内存后端和伪OSS上验收，真实账号连接、运行时镜像和公网函数仍待验证。
- 数据服务控制面：DAPI/XAPI逻辑资源、不可变版本、测试、应用授权和调用日志保存在平台库；一次性令牌只存哈希。
- 数据服务业务面：已验证发布批次结果物化到独立`v2-business-services.sqlite`，使用参数化SQLite查询；不把平台文档表当业务查询表。云端首个低成本版本将该索引快照保存到私有OSS，真实业务RDS查询适配仍待后续验收。
- 多端客户端：React、`shuzhan` CLI和`shuzhan-mcp`共用`/api/v2`；共享客户端统一项目头、客户端身份、幂等键、超时和错误结构。
- 接入控制面：数据源、源版本、连接测试、元数据版本、同步任务与运行证据保存在平台库；文件内容不写入平台文档。
- 接入数据面：FULL/INCREMENTAL_UPSERT使用独立`v2-landing.sqlite`事务落地通用行；主键冲突整批回滚，内容摘要不包含运行时间等易变元数据。
- 实时数据面：`v2-stream-state.sqlite`分别保存已处理事件、按证券最新状态和Checkpoint；Checkpoint绑定offset、源前缀、Watermark和状态摘要，恢复不能跳过被改写的历史。
- 实时控制面：平台库保存源/版本、Agent方案、任务、运行、指标与告警；Agent只获得源摘要和固定事件契约，人工应用只生成READY任务。当前适配器仅`local-event-log-v1`，Kafka/Flink连接状态固定为未连接。
- 资产目录面：运行时从Spark样例表、已采集源、离线落地表、实时状态表、已验证发布数据集和DAPI/XAPI版本自动投影目录；业务说明单独版本化，不覆盖底层证据。
- 资产关系面：同步映射、实时任务、发布批次和数据服务版本形成有向血缘；上下游分别遍历，避免把共享来源的兄弟资产误判为同一链路。Spark SQL字段级表达式解析固定标记为未完成。
- 指标与标准执行：首版只读取独立落地库或实时状态库的实际合成行；金额使用整数分精确汇总，标准失败样例只返回值哈希，定义、运行和证据摘要写入平台库。
- 数据质量控制面：逻辑规则引用不可变配置版本；运行绑定规则配置摘要和资产证据摘要，失败行只保存哈希。失败创建告警，新版本复检通过后以recoveryRunId解除，历史运行和版本不删除。
- 质量Agent面：只发送可执行资产的字段元数据、规则摘要和聚合失败计数；方案经后端重新验证资产、字段、类型和配置，人工应用只创建规则V1，不自动读取数据。
- 本机安全策略面：四个虚构身份用于验证角色、顾问客户范围、字段ALLOW/MASK/HASH/DENY和默认拒绝；安全查询读取实际合成行后先裁剪行、再处理列，并记录不含业务行的审计。
- 权限工作流：无策略身份失败关闭；READ_MASKED/READ_FULL申请只有DATA_OWNER合成身份可审批，授权带1—168小时到期时间。`X-Actor-Id`仅为本机测试身份头，公网必须替换为真实会话认证。
- 安全Agent面：只发送合成身份、资产字段元数据与策略摘要；方案经后端逐项校验，人工应用只创建策略V1，不自动查询、审批或扩大已有授权。
- 报表数据面：`v2-reports.sqlite`独立保存数据集快照行，平台库只保存快照摘要、报表/组件版本、聚合运行和导出证据；不把报表明细写入通用平台文档。
- 报表执行面：报表版本固定一个不可变数据集快照，只支持KPI、BAR、PIE和SUM/COUNT聚合；金额按整数分计算，client_id/position_id维度在结果生成前默认脱敏。
- 报表Agent面：只发送就绪数据集的字段、行数和快照摘要，以及已有报表摘要；后端复核全部组件引用，人工应用只创建报表草稿，不运行、导出或发布。
- 运维归一面：扫描离线/实时/质量/发布/数据服务失败运行，以源运行ID幂等生成事故；Checkpoint、质量规则和回滚的成功运行自动关联恢复，事故详情不返回业务行。
- 运维处置面：ACKNOWLEDGED只记录人工确认；RESOLVED必须验证同一资源、晚于失败且状态成功的运行证据。Agent诊断只能引用事故源/恢复证据且固定不可执行。
- 运维隐私门：外部模型只可接收别名化事故和错误码，但默认`V2_ALLOW_EXTERNAL_OPS_CONTEXT=false`；没有用户对该类运维摘要的单独明确授权时，接口在创建任务前返回412。
- 完整链路评测：冻结清单从原M1正式评测数据库导出真实Agent SQL、Spark结果与五场景断言，去除日志和本机路径；每例继续生成文件、实际演练、摘要审批、本机激活、两个墙上时钟Spark批次与健康监控。
- 评测报告：运行中逐例写入`.v2-artifacts/full-lifecycle/<runId>/report.json`并更新`latest.json`；API/CLI/MCP和运维页只读展示，固定`deploymentScope=LOCAL_ACTUAL`、`publicDeployed=false`。
- 邀请认证面：管理员生成一次性7天邀请码，只保存SHA-256；兑换后用户密码以scrypt保存。8小时会话令牌和CSRF令牌分别以哈希落库，浏览器使用HttpOnly会话Cookie和可读CSRF双提交Cookie。
- 项目授权面：公开GET保持匿名只读；公网写请求同时校验来源、会话、CSRF、项目成员和API资源权限。ADMIN/ENGINEER/PRODUCT_MANAGER/VIEWER由后端映射能力，前端只根据相同权限改善禁用状态。
- 公网秘密边界：模型Key页面入口在公网完全移除，服务端接口再次拒绝；启动管理员和模型凭证只允许云端秘密管理注入。回环认证预览可显式使用非Secure Cookie，非回环环境禁止该开关。
- 云端运行时：V2依赖Node 24内置`node:sqlite`；FC当前内置Node 20不能作为V2运行时。Linux x64构建脚本将Node 24解释器、最小mysql2依赖、`web-dist`、源码和合成fixtures打入自定义Debian 12代码包，并限制ZIP不超过70MiB以保留API Base64上传余量。

## 生命周期
草稿生成/人工编辑 → 保存不可变版本 → 后台执行 → 独立验证 → 生成交付包 → 按文件演练 → 人工审批摘要 → 本机版本激活 → 计时批次 → 监控/告警/回滚 → DAPI物化与测试 → XAPI组合 → 应用授权调用。实时支线为源版本 → 人工或Agent任务草稿 → 显式启动 → 事件幂等/状态/Checkpoint → 故障告警 → 前缀校验后的断点恢复。
模型修正有次数与 Token 预算，结果未通过不能宣告完成。
后台状态持久化；本机重启和模拟云冷启动均可恢复已完成业务状态，进行中运行标为中断，不假造成功或静默重复执行。
尚未触发的本机发布批次保留计划时间，服务恢复后重新装载；正在执行的批次中断后不静默重放。

## 边界
本地回环开发模式不是公网认证。公网写入须经过邀请/登录、项目授权、幂等与资源隔离验收。
SQL 由 Spark 执行；SQLite/MySQL 只用于平台元数据或明确的业务接口查询，不作为 Spark 替身。
旧 /api 和部署流程保留；新增代码不自动改造已发布函数。M0 预算/模型/隔离条件通过后安排灰度。
V2使用独立`dataplatform-v2-staging-api`函数和手动工作流；预创建、部署变量/秘密、真实云验收齐备前，不能替换现有V1函数或自动随main发布。

## UI 设计规范
暖白侧栏与工作区、深墨绿主色、琥珀色提示、清晰状态文字；统一间距和层次。
顶部紧凑项目上下文，左侧按工作域分组，中央代码/资产信息，右侧可收起的 Agent，下方结果与日志。
正文字号 13–14px；控制密度、对齐和截断提示；键盘、空/错/忙状态及窄屏均验收。
结果显式绑定版本哈希/运行编号；修改代码或更换上下文后，旧“通过”降为历史结果，不可当作当前代码已验证。
