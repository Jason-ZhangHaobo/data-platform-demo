# 已保存 SQL 运行对照

更新：2026-11-09。状态：已实现并完成本机验收，尚未云部署。

## 1 背景

证券工程师修正客户资产SQL后，需要同时检查两版代码、字段值来源、条件引用和各自独立核验结果。仅看当前样例正确，可能遗漏重复持仓等回归失败；仅比较代码或引用摘要，也不能证明输入数据或验证依据相同。

本次在独立Agent开发工作台的执行反馈中增加“运行对照”。对照只读取确切已保存运行，复用原执行器、来源分析与权限，不创建新的模型、解析或计算通道。

## 2 价值

工程师可在同一工作台选择基线，观察当前运行的核验变化，并审阅来源摘要和只读代码差异。例如本机参考SQL移除持仓去重后，重复持仓场景由通过变为未通过，条件摘要同时出现DISTINCT引用移除。该观察不自动证明某条条件是唯一原因，也没有据此测得Agent真实修正成功率或节约工时。

## 3 问题

旧记录缺少实际输入或断言内容指纹时，不能用当前样例重新计算并冒充历史证据。缺少条件引用记录，也不能解释为条件新增／删除。不同口径、结构、解析器或缺失引擎版本的结果，应保留各自记录并明确比较范围。

## 4 需求与验收

| 编号 | 行为与预期 |
|---|---|
| FR-RC01 / AC-RC01 | Worker保存实际顾问范围输入的规范化指纹，包含口径、参数、结构和送入Spark的行；排除标准答案。每个实际回归场景分别记录。旧运行未记录时保持未记录，不回填 |
| FR-RC02 / AC-RC02 | 验证器另存断言内容及验证器版本指纹，比较时核对两次记录；默认对照报告不返回断言内容指纹、行、预期金额或诊断原文。主运行与当前场景输入指纹冲突时明确未确认 |
| FR-RC03 / AC-RC03 | 两个运行及其原代码分别按现有后端权限读取；候选仅列当前用户可见同口径记录，最多50条元数据，不含SQL／行／日志。不能通过只拥有一个运行读取另一个运行 |
| FR-RC04 / AC-RC04 | 对照固定运行ID、代码ID、SQL摘要、口径及原分析。值来源与条件独立比较；不同口径、结构或解析器不推断引用变化；旧记录缺条件不能当全部新增／删除。条件按种类及源字段多重集匹配，忽略不稳定条件编号，不宣称语义等价 |
| FR-RC05 / AC-RC05 | 只有所有登记场景的输入、断言及已记录引擎版本核对一致时，展示通过状态变化；缺失不能以“两边都缺失”当相同。始终保留`causalConclusion=NOT_ESTABLISHED`，不把观察提升为唯一因果 |
| FR-RC06 / AC-RC06 | 界面初始无对照结论，明确选择基线后只读。未保存草稿不属于对照。错误回执保留同一对运行的上次快照并标未确认；切换基线后迟到响应不能覆盖。候选／对照分别重读，不触发执行 |
| FR-RC07 / AC-RC07 | 两版SQL原文默认不加载；本人显式读取时使用既有代码读取API，逐一核对代码ID、口径和完整字节SHA-256。原文不一致拒绝展示，不取草稿或最新版本。差异编辑器只读并折叠未改动区域，不将原文加入默认对照报告或模型请求 |

API前缀`/api/v2`：

| API | 协议与作用 |
|---|---|
| `GET /runs/:id/comparison-candidates` | `shuduo-run-comparison-candidates/v1`，最多50条同口径可见候选 |
| `GET /runs/:id/comparison?baseline_run_id=UUID` | `shuduo-sql-run-comparison/v1`，两个固定运行的只读记录、证据一致性和引用／核验变化；只接受一个基线参数 |

CLI为`sql compare-candidates --run-id`、`sql compare-runs --run-id --baseline-run-id`；MCP为`sql_run_comparison_candidates`和`sql_run_compare`。GUI／CLI／MCP共用回执校验。显式SQL差异由GUI组合已有`GET /revisions/:id`读取，不扩大默认MCP报告内容。

输入协议为`shuduo-spark-execution-input/v1`，范围固定`ADVISOR_SCOPED_REGISTERED_TABLES`；断言协议为`shuduo-securities-assertion-evidence/v1`。指纹相同只证明记录所覆盖的输入和断言内容一致，不能替代引擎、环境、授权或生产审计。已隐藏字面量的摘要相同，也不表示SQL语义相同。

## 5 Demo 与证据

本机打开独立Agent中已保存的Spark运行，选择“运行对照”及基线，再读取。两侧卡片展示原核验状态、场景数量及文件测试；下方分开展示证据一致性、场景变化、值来源和条件摘要。需要审阅代码时展开“查看两版SQL（只读）”。修正入口保留在“结果／校验”等原工作流，不在对照页重复占据结果区。

本机真实Spark会话中顺序执行参考SQL及去掉持仓去重的变体，共1个进程／2次主执行，各含5场景及测试SQL。输入与断言指纹已对10个场景作独立跨语言复核；参考为5/5，变体为4/5，观察到重复持仓失败及一组DISTINCT引用摘要移除。运行导入隔离库为手工来源，另有一条合成旧证据副本用于缺失回归；没有Agent生成、调度发布或真人审批。

完整本机CI1640项：1639通过、0失败、1既有跳过，类型、构建及入口体积门通过。实际界面验证了基线切换、旧证据未齐、错误回执保留／恢复、在途切换与迟到隔离、较大对照区以及只读SQL差异。API／CLI／MCP处理器回读一致，不代表外部MCP连接。全库摘要不变，零真实模型／云变更；不计当前v3自主20例、公网、实例恢复或两种网络性能验收。
