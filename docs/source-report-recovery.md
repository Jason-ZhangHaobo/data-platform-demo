# 同源报表 Agent：调用边界、恢复与审阅

本增量只覆盖现有本机同源报表规划。GUI、API、CLI与MCP共用原规划和报表创建记录，不新增云资源、权限或后台触发器，不代表真实提供方或云端E2E验收。

## 执行与用量

新同源规划使用 `SOURCE_BOUND_REPORT_AGENT_V1`。排队先保存 `NOT_STARTED`；调用前再次核对来源、当前执行所有者、预算和记录版本，然后保存调用编号、时限和保守Token预留。只有当前执行实例的确切调用可在预算门中替换自己的预留，其他未确认调用继续占用预算。

解码得到提供方回执后，先保存模型、用量和来源标记，再校验来源与方案。JSON错误、来源变化或业务校验失败不丢掉已知用量；Token总数不会低于已报告的输入与输出之和。无可靠回执、超时或取消时保留预留，不自动计作零费用。取消规划不撤销已发生的模型调用。

## 中断与恢复

读取会区分当前活跃执行和旧进程记录，不因刷新重新调用模型。

- 原排队任务证明尚未调用模型时，显示可显式续接，保留原编号、需求、来源和上下文摘要。续接前核对来源，使用记录版本控制取得执行所有权。
- 已有调用编号、预留或未确认提供方结果时，显示结果未知，禁止续接或自动重试。缺少旧边界记录时采用保守处理，不推断“未发送”。
- 旧队列、旧调用结果及迟到失败不能覆盖新执行所有者。提供方结果未记录时不能应用方案；已成功方案仍须提交其确切 `proposalHash`。

API复用原查询端点，新增 `POST /reports/agent/plans/:id/resume`，只接受空请求体和原所属人。CLI：`shuduo reports resume-plan --id PLAN_ID`；MCP：`report_plan_resume`。这项操作可能继续一次模型调用，只有符合未调用边界时才执行；查询原方案仍是只读。

## 界面

同批次规划历史支持读取原方案、未知任务及已生成结果。切换历史保留输入框未发送文字；草稿与原请求冻结文字分别保存，刷新后可恢复。当前显示的原规划结果未知时，界面禁用重新调用与应用；方案生成后的报表回执未知时先查询原方案，不再提交一次应用。缺字段只提出一个澄清问题，不用持仓分布替代现金或全资产。

本轮已有澄清仍通过新的规划请求处理；原问题与答案的显式续接链路列为下一项，不宣称已具备完整多轮报表对话。

## 证据边界

`test/v2/source-report-recovery.test.mjs`覆盖旧执行者、并发续接、未知预留、超时、来源变化、畸形内容、解码用量及生产适配层的合成响应兼容。原规划、预算、SQL和报表回归保持。真实模型准确率、云端连续推进、当前20例完整E2E和公网验收仍另行执行。

本机用户旅程在独立验收副本进行：复用原真实Spark来源，以明确合成提供方响应验证恢复／审阅／生成／澄清；没有真实模型调用或新Spark，主库不变。操作标识、原始证据和界面记录只保存在受保护状态，不进入公开仓库。
