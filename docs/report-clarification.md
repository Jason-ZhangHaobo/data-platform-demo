# 同源报表Agent澄清答复

已登记发布结果缺少所需指标时，Agent先提出一个澄清问题。原创建者可回答后沿用同一发布来源生成独立后续方案；不把回答当成脱离原需求的新请求，不补造现金、全资产或其他缺失字段。本增量保持本机边界，真实模型和云端另验。

## 绑定与历史

读取原问题时核对原创建请求、所属人、需求、问题、方案摘要、来源上下文和用量，返回 `shuduo-report-clarification/v1` 及问题摘要。回答为1—1000字，最多三轮。

后续规划保留原需求、每轮问题／回答、原方案编号与用量、原来源和摘要；原记录不修改，新的模型调用单独记账。创建前、模型前后、恢复和应用前都重核父链；原问题、用量或来源变化时不采用旧依据。未记录的历史用量标记未知，不作零用量处理。

新审阅摘要绑定后续方案自身身份、创建请求、回答及澄清摘要。相同组件不能借用其他方案摘要，删除澄清字段后重算普通摘要也不能绕过原创建记录。旧未澄清方案的摘要格式保持兼容。

## 交互与恢复

- `GET /reports/agent/plans/:id/clarification`：只读核对原问题与历史用量。
- `POST /reports/agent/plans/:id/clarify`：提交 `{evidenceDigest, answer}` 和原请求幂等编号；来源由服务器固定，客户端不能另指定。
- 原编号查询复用 `/reports/agent/requests/:requestId`。已受理回答的查找和同编号回读不要求再配置或调用模型。

界面保留原问题与回答。提交结果未知后先查询原编号；确认为未找到时，可显式按同一编号和冻结回答重试。每次发送后关闭重试入口，直到再次查询；不自动重提。不确认后续结果时不会丢弃原回答或另造请求。历史选择原问题可找回已创建的后续方案。

CLI：`shuduo reports clarification --id PLAN_ID`、`shuduo reports clarify --id PLAN_ID --evidence-digest SHA256 --answer "回答" --request-id UUID`。MCP：`report_plan_clarification`、`report_plan_clarify`。GUI／API／CLI／MCP共用同一记录与权限。

## 提示隐私与验收

模型只获得原需求及每轮问题／回答，加上原来允许的字段、口径、组件和摘要；不接收业务行、独立答案、历史模型名称、用量或私有操作标识。澄清链在服务器持久保存，界面可查看；不会用模型自行返回的来源替代。

`test/v2/report-clarification.test.mjs`核验单次派生、幂等、不同回答冲突、三轮上限、原问题／用量变化、剥离来源后重算摘要的拒绝、提供方前后核对、无模型配置的已受理回读及提示隐私。实际隔离本机验收使用原真实Spark结果和合成模型响应，完成未受理／丢失回执恢复及报表生成；真实模型0、新Spark0，不计当前真实完整E2E。

当前报表结果仍通过原任务／创建请求关联澄清记录；离线交付中独立冻结需求与审阅溯源列为下一项，不能仅凭CSV推断完整对话或审批依据。
