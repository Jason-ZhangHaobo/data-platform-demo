# 工作台 UI 与交互设计基线

来源：用户明确要求“先进、有审美、功能组织合理、好用好理解好看”。不是仅换主题色。
视觉与交互是产品验收项，不是功能完成后的装饰工作。

## 信息组织

- 全局侧栏按数据接入、开发交付、治理服务、运行管理组织 11 个经典模块；Data Agent 是跨模块协作入口。
- 项目与环境固定可见。一级导航不能因当前只做一个 MVP 就删除其他必需领域。
- 当前未实现模块展示阶段、范围与进入工作台的路径，不显示假的运行数、成功率或发布按钮。
- 代码工作台把编辑、运行、版本、结果与 Agent 放在同一任务上下文中；不把大标题、营销卡片当主工作区。

## 视觉语言

暖白背景、低饱和墨绿主色、深色代码编辑区。绿色代表有证据的成功，琥珀代表等待/历史结果/需注意，红色代表实际失败。
正文目标 13–14px，信息层级通过字重、间距和对齐表达；技术元信息单独弱化，不能压低关键正文可读性。
图标统一采用 Lucide；字体使用系统中文字体；Monaco 与其 Worker 本地打包，不依赖外部 CDN。
尊重 reduced-motion，交互显示键盘焦点；窄屏图标导航仍必须有可访问名称和悬停说明。

## 核心交互

1. 输入上下文先展示表结构和口径；切换输入保留代码，提醒重新执行。
2. 保存形成不可变版本；差异支持审阅，撤销恢复载入版本。
3. 运行立即进入后台队列，明确排队/运行/取消/失败；结果绑定版本哈希和批次。
4. 编辑后的代码与旧结果不一致时标注历史结果，要求重跑；不能继续暗示当前代码已通过。
5. Agent 展示配置状态、上下文、委托、修正记录和停止入口；用户审阅产物差异。
6. 模块搜索支持 DAPI 等任务词；对话框支持焦点约束和 Escape 退出。
7. 调度发布页用四步证据带串起交付包、文件演练、审批发布和运行监控；选中版本状态与当前生效版本分开显示，避免把已回滚版本误认为在线版本。
8. 监控卡同时显示健康度、成功批次、开放告警、已恢复告警及实际计时批次；所有本机发布位置明确提示不是公网或完整 E2E。

## 响应式

1440 与 1280 宽度显示导航、编辑器和 Agent 三列；1024 与 768 下使用图标侧栏，Agent 作为可收起面板。
结果表格可以在其区域内横向滚动，但页面主体不得溢出。
首屏主要操作应可见，编辑器不得被宣传区挤压。
2026-09-14再次检查1280×900和768×900：页面级scrollWidth等于视口；768下审批/监控由双栏改为单栏，避免健康度与按钮截断；浏览器控制台无错误。
完整屏幕阅读器审计、所有状态的对比度扫描和 Safari/Chrome 公网验收仍待完成。
