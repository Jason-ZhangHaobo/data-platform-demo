# 一次性签名HTTP入口验收

这是有界的真实边界测试，不是部署器，也不代替应用登录或完整E2E。工作流仅支持main、既有v2-staging环境分支限制及精确的已通过CI源码SHA；环境限制不等于仓库分支保护，必须分别核验，不自动修改仓库权限。默认NOT_AUTHORIZED，不定时运行、不因push自动执行。

## 前置与范围

- 必须有当前明确授权：一个签名HTTP临时触发器、最多20次读取/对照调用，无模型或Spark，单轮预算预留1元、账户月上限200元。
- 执行器不创建/修改RAM策略；操作方在流程就绪后才按单独授权临时附加所需权限，并在结束后精确撤销。建议附加策略设置短时有效期；到期不替代清理与复核。
- 调度输入须携带该临时策略的UTC到期时间；启动时不足10分钟不创建入口，探测在到期前至少3分钟停止以留出清理时间。输入时间必须与实际策略核对，不能仅修改输入延长权限。
- 已知部署checksum必须匹配，CPU0.25/512MB/并发1/timeout≤120；公网应用开关保持关闭，私有验收开关须存在。原触发器只能是两个OSS，存在其他入口或无法完整列举就停止。
- 完整分页账单必须为当前北京时间账期、CNY，预留1元后仍在月预算内。账单有延迟，流程记录查询时点，不将预算预留冒充最终已结算费用。

## 执行与清理

1. 验证OIDC身份、函数版本/开关/容量和原触发器；核验账单。
2. 仅调用一次PRIVATE_STATUS_V1确认私有控制路径；不提交业务任务。
3. 创建前保存目标/原配置摘要检查点，再创建一个authType=function、仅GET/POST的临时触发器。
4. 执行14个固定探测。POST载荷始终是PRIVATE_STATUS_V1，路径、伪造头及重复头用于验证入口隔离。未签名应被网关拒绝；签名基线及边界用例必须到达应用的404/INGRESS_DENIED，不能把签名失败冒充隔离成功。总对照/HTTP请求15次，不自动重试。
5. 无论通过或失败，删除精确匹配本轮名称/描述/配置的临时触发器；读回证明入口不存在、原两个触发器及函数配置未改。创建/删除结果不明先查证，不盲目重建。配置漂移拒绝删除非本轮目标。
6. 工作流另有always清理步骤及密文证据导出。报告和检查点用RSA3072+AES-GCM密封，只上传密文；不记录响应正文、凭证、函数环境值。操作方下载核验后撤销新增IAM并与原基线对照。

如果runner整体丢失或清理仍未确认，必须保留失败状态，依据密文检查点恢复同一目标；不得直接重跑创建新入口。密文报告缺失、执行超时或权限到期均不能推断资源已删除。尚未附加临时权限时，不执行此工作流。

## 本机验证

`node --test test/v2/http-boundary-acceptance.test.mjs test/v2/http-boundary-probe.test.mjs` 覆盖配置/预算门、创建结果未知、鉴权未通过、私有协议暴露、删除未知与失败、目标漂移、次数/时间界限、路径/重复头保留和秘密不输出。

本机替身与CLI dry-run只验证程序行为；真实边缘行为、账单、触发器清理和临时IAM撤销须有单独运行证据。签名方式依据[阿里云HTTP触发器签名认证](https://help.aliyun.com/zh/functioncompute/configure-signature-authentication-for-http-triggers)，使用官方SDK，不采用自行放宽签名或绕过网关的方式。
