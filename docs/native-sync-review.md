# Agent 冻结持仓文件审阅与发布预检

适用本机原生 Spark SQL Agent 的冻结虚构证券持仓交付。手工辅助、Python、基金专用和云端发布各沿用自己的流程；此功能不改变公网发布窗口。

## 工程师如何使用

1. 在独立 Agent 中打开已经生成并成功演练的原交付，进入文件区。
2. 点击“核对原包审阅与发布范围”。服务端重新核对原作者、任务、代码、运行、交付编号、包摘要、冻结输入和完整演练，不重跑模型或 SQL。
3. 核对结果行数、五场景、八文件摘要及原业务日期。合成模型来源明确标注，不能算真实模型端到端成功。
4. 文件审阅需要本人逐项确认代码、独立断言、交付文件和本机范围，再点击“仅记录文件审阅”。默认全部未选；此操作不批准发布。
5. 下载“审阅预检 JSON”保留材料。下载未确认时可展开文本；材料摘要仅验证完整性，不代表不可篡改生产审计。

预检展示后续独立批准的两批**本机**测试计划：激活后约 5 秒和 35 秒分别触发，使用同一个冻结业务日，绝不是两个交易日。实际发布仍要原审阅、原演练、确切版本、明确测试同意以及独立批准共同通过。未启用计时器时仅解释，不代为开启。预检不创建批准、批次、调度器或云资源。

“技术证据已核对”“当前文件审阅已核对”“已批准发布”是不同状态。即便原包有旧批准，也不能由本次读取推导为当前已批准。预检故意只返回 `publicationApproved:false`。

## 变化与中断

- 包、输入、代码或演练不一致：拒绝，不挑选其他可用旧包，页面撤下旧正向结果和下载。
- 旧文件审阅缺少当前演练摘要或不匹配：`STALE_REVIEW`，重新逐项检查。
- 审阅前再只读核对一次。演练摘要变化时撤销本页勾选，不沿用原确认。
- 审阅响应丢失：显示结果待确认，先查询同包同演练的原审阅；不自动重提。若确实没有回执，用户明确重新勾选后才用原页面请求号提交；刷新页面后服务端仍会复用同一有效审阅。
- 页面换任务、版本或失去编辑权限：旧异步结果不能填入新卡片。历史原包可只读核对，不代记审阅。

## API／CLI／MCP

只读 API：

```text
GET /api/v2/agent/tasks/:taskId/sync-review-preflight
  ?deliveryId=:uuid&packageId=:uuid&packageDigest=:sha256&verificationId=:uuid
```

四个唯一查询参数全部必填。禁止未知参数、重复参数、当前版本替代或自动回退。原项目、原作者、本机回环、原生来源与成功文件演练同时校验。只读返回 `shuduo-native-sync-review-preflight/v1`，含八文件摘要、演练摘要、当前审阅状态、未勾选的测试范围依据和零计算/未发布声明。**不返回** `confirmFrozenFictionalData:true`。

```sh
node bin/shuduo.mjs agent sync-review-preflight \
  --id TASK_UUID --delivery-id DELIVERY_UUID --package-id PACKAGE_UUID \
  --package-digest SHA256 --verification-id VERIFICATION_UUID
```

MCP：`agent_sync_review_preflight`，相同五个绑定字段，只读工具。多端使用同一响应校验器：绑定错位、数据结构变化、提前同意、额外字段、宣称完整 E2E 或摘要变化均拒绝。

实际文件审阅复用 `POST /delivery/packages/:id/review`（CLI `delivery review`、MCP `delivery_review_create`）：必须传原 `syncRehearsalDigest` 和四项明确确认。发布与激活接口未由本次预检代调。

## 验收范围

定向测试用显式协议替身覆盖身份、精确版本、坏证据、零写入、重复参数、当前与过期审阅、CLI/MCP和响应变造；不将其称为实际 Spark。浏览器另复用已经通过的本机真实 Spark 文件演练，在数据副本上读取、实际下载并核对 JSON、检查默认未勾选和窄屏布局，注入文件摘要变化后撤下旧材料。浏览器不代为给真实交付记审阅、不批准或启动批次。

本轮不新增真实模型、Spark 或云资源调用，不计正式云端 E2E。后续发布仍须工程师在确切版本上独立确认，并实际验收两批结果及监控。

后续可在独立确认后使用[原生持仓两批发布与监控](native-sync-publication.md)。文件预检和文件审阅本身仍不批准或启动批次。
